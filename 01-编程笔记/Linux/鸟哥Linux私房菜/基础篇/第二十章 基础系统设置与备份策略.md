# 第二十章 基础系统设置与备份策略

> [!info] 关于本章
> 本章以鸟哥《Linux 私房菜 — 基础学习篇》第二十章为骨架，已将原基于 CentOS 7 的内容更新到当前 **Rocky/AlmaLinux 9 / RHEL 9** 状态：网络配置以 **NetworkManager**（`nmcli`/`nmtui`）为准、时间同步改用 **chronyd**（取代 `ntpd`/`ntpdate`）、防火墙以 **firewalld**（`firewall-cmd`，底层 `nftables`）为主，主机名 / 时区 / 语系统一通过 `hostnamectl` / `timedatectl` / `localectl` 设置；包管理用 `dnf`（取代 `yum`）。术语统一为大陆通行写法。CentOS 7 已于 2024-06-30 EOL。

系统设置与备份是运维的两面：一面让机器按预期提供网络、时间、语系等服务，一面在硬件故障或安全事件后能快速恢复。

## 20.1 系统基本设置

RHEL 9 系发行版已不再提供图形化的 `setup` 综合配置工具，转而以命令行工具配合 bash-completion 完成各类系统设置。本节汇总网络、时间、语系、防火墙四类基本设置。

### 20.1.1 网络设置

**网络参数的获取方式**

| 方式 | 说明 | 典型场景 |
|---|---|---|
| 手动设置固定 IP | 需向 ISP/网管索取 IP、netmask、gateway、DNS | 服务器、企业内网固定工位 |
| DHCP 自动获取 | 由 DHCP 服务器分配参数 | 家庭/办公路由器下游、虚拟机默认 |
| PPPoE 宽带拨号 | 经 `ppp0` 接口拨号上网 | 部分光纤/ADSL 直连场景 |

**网卡命名规则**：RHEL 系从 CentOS 7 起采用基于固件/总线位置的"可预测网络接口名"（predictable network interface names）。

| 名称前缀 | 含义 |
|---|---|
| `eno1` | 主板 BIOS 内置网卡 |
| `ens1` | 主板 BIOS 内置 PCIe 网卡 |
| `enp2s0` | PCIe 独立网卡（总线 + 插槽编号） |
| `eth0` | 上述规则都不适用时的回退命名 |

> [!tip] 查看与设置网络
> 查看所有网卡：`ip link show`（现代发行版默认的 iproute2 工具，取代旧 `ifconfig -a`）。RHEL 9 默认由 **NetworkManager** 托管网络配置，统一用 `nmcli`（命令行）或 `nmtui`（文本菜单）设置，不建议手改配置文件。

**nmcli 连接模型**：每个"连接（connection）"绑定一张"网卡（device）"，二者通常同名。

```bash
nmcli connection show                 # 列出所有连接
NAME  UUID                                  TYPE            DEVICE
eth0  505a7445-2aac-45c8-92df-dc10317cec22  ethernet        eth0

nmcli connection show eth0            # 查看某个连接的全部属性
```

常用的 IPv4 属性：

| 属性 | 说明 |
|---|---|
| `connection.autoconnect` | `yes` 时开机自动启用此连接 |
| `ipv4.method` | `manual`（手动）或 `auto`（DHCP） |
| `ipv4.addresses` | `IP/前缀长度`，如 `172.16.1.1/16` |
| `ipv4.gateway` | 网关 IP |
| `ipv4.dns` | DNS 服务器 IP |

**手动设置固定 IP**（IP `172.16.1.1/16`，网关/DNS `172.16.200.254`）：

```bash
nmcli connection modify eth0 \
  connection.autoconnect yes \
  ipv4.method manual \
  ipv4.addresses 172.16.1.1/16 \
  ipv4.gateway 172.16.200.254 \
  ipv4.dns 172.16.200.254

nmcli connection up eth0
```

`modify` 只改写配置文件，必须 `up` 才生效。

**DHCP 自动获取**：只需把 `ipv4.method` 改为 `auto`：

```bash
nmcli connection modify eth0 \
  connection.autoconnect yes \
  ipv4.method auto

nmcli connection up eth0
```

> [!tip] bash-completion
> `nmcli` 的 `connection.`、`ipv4.` 等参数支持 `[Tab]` 补全，命令无需死记。

**修改主机名**：用 `hostnamectl`，立即生效并写入 `/etc/hostname`。

```bash
hostnamectl                            # 查看主机名、系统、内核版本、架构
hostnamectl set-hostname www.example.com
```

`hostnamectl` 输出含 `Static hostname`、`Operating System`（如 Rocky Linux 9）、`Kernel`（6.x）、`Architecture`（x86_64）等。

### 20.1.2 日期与时间设置

**时区查看与设置**（`timedatectl`）：

```bash
timedatectl                            # 查看本地时间、UTC、时区、NTP 状态
timedatectl list-timezones | grep Asia # 列出支持的时区
timedatectl set-timezone "Asia/Shanghai"   # 设置为上海时区（东八区）
```

**手动设置时间**（格式 `yyyy-mm-dd HH:MM`）：

```bash
timedatectl set-time "2026-08-05 14:30"
```

> [!note] timedatectl 一站式管理
> 过去修改时间后还要用 `hwclock` 同步硬件时钟（RTC），`timedatectl` 一次完成系统时间与 RTC 的同步。

**网络校时：chronyd**

RHEL 9 默认时间同步服务为 **chronyd**（取代旧版的 `ntpd`/`ntpdate`）。chronyd 启用后系统自动与配置的 NTP 服务器对时。

```bash
systemctl enable --now chronyd   # 启用并启动
chronyc tracking                 # 查看同步状态
chronyc sources                  # 查看时间源
```

> [!tip] 手动立即同步
> 想立刻强制对一次时，用 `chronyc makestep`；`ntpdate` 在 RHEL 9 中已移除，统一走 chronyc。国内可用国家授时中心 `ntp.ntsc.ac.cn` 或公共池 `cn.pool.ntp.org`。

### 20.1.3 语系设置

**系统语系** 与 **当前 shell 语系** 是两个概念：

```bash
localectl     # 系统语系（影响图形登录界面等服务）
locale        # 当前 shell 的语系环境变量
```

常见 locale 值：`zh_CN.UTF-8`（简体中文）、`en_US.UTF-8`（英文）。简体中文服务器推荐把系统语系设为 `en_US.UTF-8`，避免日志/终端乱码干扰排障；个人 shell 需要中文时再 `export LANG=zh_CN.UTF-8` 临时切换。

**修改系统语系**：

```bash
localectl set-locale LANG=en_US.UTF-8
```

要让图形界面也跟随变更，注销或重启图形会话即可。

### 20.1.4 防火墙简易设置

RHEL 9 默认防火墙为 **firewalld**，底层在 RHEL 8 起改用 **nftables**（CentOS 7 时代为 iptables 后端）。日常管理用 `firewall-cmd`。

**两个关键概念**

| 概念 | 说明 |
|---|---|
| **区域（zone）** | firewalld 按网络信任度预定义的规则集，默认区域一般为 `public`；其它常用区域有 `trusted`、`drop`、`block`、`dmz` |
| **运行时 vs 永久** | 直接添加的规则只对当前运行时生效；加 `--permanent` 才写入持久配置，还需 `--reload` 重载 |

> [!warning] 永久规则必须 reload
> 仅在"运行时"添加的规则，重载或重启后会丢失。要持久生效：先 `--permanent` 添加，再 `firewall-cmd --reload`。

**常用命令**：

```bash
firewall-cmd --get-default-zone           # 查看默认区域
firewall-cmd --list-all                   # 查看当前区域所有规则

# 永久放行标准服务
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --permanent --add-service=ftp

# 永久放行非标准端口（如 222/tcp、555/tcp）
firewall-cmd --permanent --add-port=222/tcp
firewall-cmd --permanent --add-port=555/tcp

# 永久放行整个网段（rich rule）
firewall-cmd --permanent \
  --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" accept'

# 重载使永久规则生效
firewall-cmd --reload
```

`--add-service` 对应 `/usr/lib/firewalld/services/` 下预定义的服务（含端口）；自定义端口用 `--add-port`；按来源网段放行用 rich rule。

## 20.2 服务器硬件信息收集

升级内存前要先确认主板插槽与内存类型；判断磁盘故障要先看 SMART 数据。Linux 提供了一组命令在不拆机的前提下查清硬件。

### 20.2.1 用 dmidecode 解析硬件配备

`dmidecode` 读取 SMBIOS 表，能列出主板型号、CPU 规格、内存插槽等。需 root。

```bash
dmidecode -t 1     # 系统信息（厂商、产品名）
dmidecode -t 4     # CPU 信息（频率、核心数、线程数）
dmidecode -t 9     # 系统插槽（PCI/PCIe 规格）
dmidecode -t 17    # 每根内存插槽的容量与型号
```

物理机上输出会显示真实主板型号与每根内存的容量/型号，是升级硬件前的必查项。

### 20.2.2 硬件资源收集与分析

内核在开机时探测硬件并加载驱动，探测结果记录在 `/proc` 与 `/sys`（如 `/proc/cpuinfo`、`/proc/partitions`、`/proc/interrupts`）。常用查询命令：

| 命令 | 作用 |
|---|---|
| `lscpu` | CPU 架构概要（替代 `cat /proc/cpuinfo`） |
| `lspci` | 列出所有 PCI 设备（主板与各板卡） |
| `lsusb` | 列出 USB 总线及连接的设备 |
| `iostat` | CPU 与磁盘 I/O 实时统计（来自 `sysstat` 包） |
| `vmstat` | CPU/内存/I/O 综合状态 |
| `dmesg` | 查看内核启动以来的日志 |

> [!note] 内核探测偶尔会误判
> 内核用"最合适的模块"驱动硬件，少数情况下会误判。需要更新驱动时可加载更新版内核模块；现代发行版一般不建议自行重编内核。

**lspci**

```bash
lspci                  # 列出所有 PCI 设备
lspci -v               # 详细信息
lspci -s 00:03.0 -vv   # 指定总线插槽的最详细输出
```

`lspci` 的数据取自 `/proc/bus/pci/`，厂商 ID 与名称对应表在 `/usr/share/hwdata/pci.ids`，可用 `update-pciids` 在线更新。

**lsusb**

```bash
lsusb                  # 列出 USB 总线及设备
lsusb -t               # 树状显示 USB 端口层级
```

**iostat**

```bash
iostat                 # CPU 与所有磁盘的整体统计
iostat -d 2 3 vda      # 仅磁盘，每 2 秒一次，共 3 次
```

输出字段含义：

| 字段 | 含义 |
|---|---|
| `tps` | 平均每秒 I/O 传输次数（次数，非容量） |
| `kB_read/s` | 平均每秒读取量 |
| `kB_wrtn/s` | 平均每秒写入量 |
| `kB_read` | 自开机累计读取量 |
| `kB_wrtn` | 自开机累计写入量 |

> [!tip] sysstat 包
> RHEL 9 默认未装 `iostat`，需 `dnf install sysstat`（CentOS 7 时代的 `yum` 在 RHEL 8 起统一为 `dnf`）。

### 20.2.3 了解磁盘健康状态（SMART）

数据安全的核心是磁盘健康。**SMART**（Self-Monitoring, Analysis and Reporting Technology）让磁盘自我监测并报告健康状态，由 `smartmontools` 包提供 `smartctl` 读取。

```bash
dnf install smartmontools

smartctl -a /dev/sda          # 显示磁盘整体信息与健康状态
smartctl -t short /dev/sda    # 触发一次短测
smartctl -a /dev/sda          # 再看测试结果
```

关键输出：

```
SMART overall-health self-assessment test result: PASSED
```

`PASSED` 表示健康；`FAILED` 应立即备份数据并更换磁盘。`SMART Error Log` 与 `SMART Self-test log` 记录历史错误与自检结果。

> [!warning] 不要在系统繁忙时跑 SMART 自检
> 自检会加重磁盘 I/O 负载，建议在低峰时段进行。

> [!info] 虚拟盘与 NVMe
> 虚拟机的虚拟磁盘一般不支持 SMART；NVMe SSD 用 `smartctl -a /dev/nvme0n1`（走 NVMe 协议，字段与 SATA 略有差异）。

## 20.3 备份要点

系统会因硬件损坏、软件缺陷、人为误操作或安全事件而损毁。备份是损毁后快速恢复的最后一道保险。

### 20.3.1 备份的考量因素

**导致系统损毁的常见原因**

| 类别 | 例子 |
|---|---|
| 硬件 | 硬盘坏道、电源烧毁、RAID 控制器故障 |
| 软件 / 人为 | 误删（如 `rm -rf`）、配置错误、升级失败 |
| 安全 | 服务被攻击、勒索软件、权限被提升 |

> [!warning] RAID 不是备份
> RAID（哪怕是 RAID1/5/6）只防单盘物理故障，防不了误删、误操作、被攻击、整台机器被偷。重要数据仍需独立备份。

**主机角色不同，备份策略不同**：个人桌面与 7×24 在线的服务数据库，对备份频率和还原速度的要求天差地别。规划时要考虑：

- 备份**什么**（哪些目录/数据）；
- 用什么**媒介**（外置盘、NAS、磁带、异地）；
- 备份**方式**（完整 / 增量 / 差异）；
- 备份**频率**（每日 / 每周 / 每月）；
- 选用什么**工具**（`tar` / `rsync` / `dd` / `xfsdump` 等）。

### 20.3.2 哪些数据需要备份

**操作系统层面（关键配置）**

| 目录 | 内容 |
|---|---|
| `/etc/` | 几乎所有系统与服务配置文件 |
| `/home/` | 用户家目录 |
| `/root/` | root 家目录 |
| `/var/spool/mail/` | 用户邮件 |
| `/var/spool/cron/`、`/var/spool/at/` | 定时任务 |
| `/boot/` | 内核与引导配置（改过内核时尤其重要） |
| `/usr/local/`、`/opt/` | 自行安装的软件 |

**网络服务层面（应用数据）**

| 服务 | 典型数据目录 |
|---|---|
| WWW（httpd/nginx） | `/var/www/` 或 `/srv/www/`，以及用户家目录 |
| 数据库（MariaDB/PostgreSQL） | `/var/lib/mysql/`、`/var/lib/pgsql/` |
| 容器（Docker/Podman） | `/var/lib/docker/`、`/var/lib/containers/` |

> [!warning] 数据库不要直接 tar 运行中的数据文件
> 运行中的数据库文件可能在备份瞬间被改写，导致备份不一致。应先停服务，或用 `mysqldump --single-transaction`、`pg_dump` 等逻辑导出。

**不需要备份的目录**

| 目录 | 原因 |
|---|---|
| `/dev` | 设备文件，开机自动生成 |
| `/proc`、`/sys`、`/run` | 内核虚拟文件系统，运行时才有内容 |
| `/mnt`、`/media` | 临时挂载点 |
| `/tmp` | 临时文件 |

### 20.3.3 备份媒介的选择

| 媒介 | 优点 | 缺点 |
|---|---|---|
| 外置 USB 硬盘 | 便宜、容量大、通用 | 单盘易损，需多盘轮换 |
| NAS | 自带 RAID、可网络访问 | 整机被盗则同损 |
| 磁带（LTO） | 单位容量便宜、寿命长、可离线保管 | 怕消磁/发霉，需专用驱动器 |
| 异地灾备 | 防整机被盗/机房灾害 | 受带宽限制 |

> [!tip] 异地备份
> 把最重要的数据定期通过加密通道（`rsync` over SSH）传到另一台机器或异地 NAS，可在本地整机失联时仍保留副本。带宽有限时只传关键数据。

## 20.4 备份的种类、频率与工具

按备份范围，策略分两大类：**完整备份**（含累积/差异两种细化）与**关键数据备份**。

### 20.4.1 完整备份之累积备份（Incremental backup）

完整备份把整个系统（或某个文件系统）原样复制下来。还原时直接倒回去即可，甚至不需要重装系统，因此对提供重要服务的主机几乎必备。但完整备份耗时耗空间，不可能天天做——这就引出累积备份与差异备份。

**累积备份**：第一次完整备份后，每次只备份**与上一次备份**之间的差异。还原时需依次回放：完整备份 → 第一次累积 → 第二次累积 → … → 最近一次累积。

![[vbird-06fb5fd2d322247d.gif]]
*图：累积备份示意图*

特点：备份量小、速度快；还原步骤多。

**工具**：`dd`、`cpio`、`xfsdump`。

`dd` 直接按扇区读取、无视文件系统，可整盘克隆，但非常慢：

```bash
# 将 /dev/sda 整盘克隆到 /dev/sdb（目标盘无需格式化）
dd if=/dev/sda of=/dev/sdb
```

`cpio` 配合 `find` 备份所有文件名（可写入磁带 `/dev/st0`）：

```bash
find / -print | cpio -covB > /dev/st0   # 备份
cpio -iduv < /dev/st0                   # 还原
```

`xfsdump` 是 xfs 文件系统原生支持累积备份的工具（RHEL 默认 xfs）：

```bash
# 完整备份（level 0）
xfsdump -l 0 -L 'full' -M 'full' -f /backupdata/home.dump /home

# 第一次累积备份（level 1，与 level 0 比较）
xfsdump -l 1 -L 'full-1' -M 'full-1' -f /backupdata/home.dump1 /home
```

`tar` 也可做完整备份，配合 `--exclude` 排除虚拟文件系统：

```bash
tar --exclude=/proc --exclude=/mnt --exclude=/tmp \
    --exclude=/backupdata -Jcvp -f /backupdata/system.tar.xz /
```

> [!note] 压缩选项
> 现代 `tar` 用 `-J`（xz）获得更高压缩比，或用 `-z`（gzip）追求速度；旧的 `-j`（bzip2）已较少使用。

### 20.4.2 完整备份之差异备份（Differential backup）

**差异备份**：每次都和**原始完整备份**比较，备份自那以后所有变化。备份量随时间增长变大；还原只需完整备份 + 最近一次差异备份，还原快。

![[vbird-c52359d2aaffbee6.gif]]
*图：差异备份示意图*

| 对比 | 累积备份 | 差异备份 |
|---|---|---|
| 每次比较基准 | 上一次备份 | 原始完整备份 |
| 单次备份量 | 小 | 越往后越大 |
| 还原步骤 | 多（依次回放） | 少（完整 + 一次差异） |

用 `tar -N`（按时间）做差异备份：

```bash
tar -N '2026-08-01' -Jpcv -f /backupdata/home.tar.xz /home
```

用 `rsync` 做镜像（每次都把源端完整同步到目标，相当于差异备份的镜像版）：

```bash
rsync -av /home /backupdata/
# 再次执行会很快——rsync 只传变化的部分
```

> [!tip] rsync -a 的含义
> `-a`（archive）等价于 `-rlptgoD`：递归、保留符号链接、权限、时间戳、属主、属组、设备文件。配合 `-e ssh` 可走加密通道远端备份，已取代旧版 FTP 传输。

### 20.4.3 关键数据备份

主机若不需要 24 小时在线，可只备份关键数据（配置、账号、家目录、数据库导出）。优点：备份快、还原后顺势重装为最新系统；缺点：还原需要熟悉系统配置。

```bash
# 按日期备份 MariaDB 数据目录
tar -Jpcvf mysql.$(date +%Y-%m-%d).tar.xz /var/lib/mysql

# 推荐：用 mysqldump 逻辑导出，避免文件级备份的不一致
mysqldump --single-transaction --all-databases | gzip > mysql_$(date +%F).sql.gz
```

> [!note] 裸机复原工具
> 想做整盘镜像的裸机复原，可使用开源的 **Clonezilla（再生龙）**（[clonezilla.org](https://clonezilla.org/)），它能把整盘/分区打包成镜像文件，再通过启动盘还原。

备份要自动化：写脚本 + `crontab` 定时执行。

## 20.5 备份策略示例

每台主机的角色、数据量、重要性不同，备份策略也不同。下面是一个面向小型 Linux 服务器的示例：每日备份高频变化数据，每周备份低频但重要的目录，远程异地保留一份。

**总体策略**

1. 用独立文件系统挂载到 `/backup` 存放本地备份；
2. 每日备份：数据库（MariaDB 等）；
3. 每周备份：`/home`、`/var`、`/etc`、`/boot`、`/usr/local` 等；
4. 自动化：通过 `/etc/crontab` 调度；
5. 异地：定期把 `/backup` 的快照通过 `rsync` over SSH 传到远端机器。

### 20.5.1 每周备份脚本

```bash
cat > /backup/backupwk.sh <<'EOF'
#!/bin/bash
# 每周备份：将重要目录与服务配置打包到 /backup/weekly
basedir=/backup/weekly
PATH=/bin:/usr/bin:/sbin:/usr/sbin; export PATH
export LANG=C

mkdir -p $basedir/userinfo

# 1. 系统配置 + 自装软件
cd /     && tar -Jpc -f $basedir/etc.tar.xz      etc
cd /usr  && tar -Jpc -f $basedir/local.tar.xz    local

# 2. 账号、家目录、邮件、定时任务
cp -a /etc/{passwd,shadow,group}   $basedir/userinfo/
cd /var/spool && tar -Jpc -f $basedir/userinfo/spool.tar.xz  mail cron at
cd /          && tar -Jpc -f $basedir/userinfo/home.tar.xz   home
EOF
chmod 700 /backup/backupwk.sh
```

> [!note] 脚本要按实际调整
> 上例按 RHEL 9 默认目录布局。若你的服务数据落在别处（如自定义的 `/data/www`、容器卷等），脚本需相应修改，不要照抄。

### 20.5.2 每日备份脚本

```bash
cat > /backup/backupday.sh <<'EOF'
#!/bin/bash
# 每日备份：高频变化的数据
basedir=/backup/daily
PATH=/bin:/usr/bin:/sbin:/usr/sbin; export PATH
export LANG=C
mkdir -p $basedir

# MariaDB 逻辑导出（推荐做法）
mysqldump --single-transaction --all-databases | \
  gzip > $basedir/mysql.$(date +%Y-%m-%d).sql.gz
EOF
chmod 700 /backup/backupday.sh
```

通过 `/etc/crontab` 调度：

```bash
cat >> /etc/crontab <<'EOF'
# 每周日 03:30 做每周备份；每天 02:30 做每日备份
30 3 * * 0 root /backup/backupwk.sh
30 2 * * * root /backup/backupday.sh
EOF
```

> [!warning] 别让备份只存在一份
> `/backup` 与生产数据同机，整机损毁时备份也会丢。必须定期把 `/backup` 复制到外部媒介或异地。

### 20.5.3 远程备份脚本

两台 Linux 之间互为异地备份：通过 `rsync` over SSH 把本地 `/backup/weekly` 镜像到远端。需先配置好 SSH 密钥免密登录。

```bash
cat > /backup/rsync.sh <<'EOF'
#!/bin/bash
remotedir=/home/backup/
basedir=/backup/weekly
host=192.168.1.100
id=backupuser

rsync -av -e ssh $basedir ${id}@${host}:${remotedir}
EOF
chmod 700 /backup/rsync.sh
```

`rsync` 只传变化部分，配合 SSH 加密，是当前主流的远程备份方案。

## 20.6 灾难复原

备份的目的是恢复。两种典型场景：

**硬件损毁（有完整备份）**：先换好硬件（必要时重建 RAID），把最近的完整备份倒回去；若是差异备份，再追加最近一次差异备份即可。

**安全事件（被攻破）**：不能简单还原旧系统——旧系统会被攻破，还原回去还会再次被攻破。建议流程：

1. 断网，对受损系统做完整镜像备份（留作取证）；
2. 分析日志，定位入侵路径与漏洞；
3. 安装最新版发行版并打全补丁；
4. 配置防火墙、最小化服务；
5. 根据 2 的结论修补漏洞；
6. 恢复服务与数据；
7. 上线并持续观察。

> [!note] 取证备份的价值
> 受攻击后第一时间做镜像备份，既可作为还原来源，也可在被追溯为攻击源时佐证"自己是受害者"。

## 20.7 重点回顾

- RHEL 9 系发行版的网络、主机名、时区、语系分别由 NetworkManager（`nmcli`）、`hostnamectl`、`timedatectl`、`localectl` 管理；
- 时间同步默认用 `chronyd`（取代 `ntpd`/`ntpdate`），用 `chronyc` 查询与控制；
- 防火墙默认 `firewalld`（`firewall-cmd`），底层 `nftables`，区分运行时与永久（`--permanent` + `--reload`），默认区域一般是 `public`；
- 硬件信息收集：`dmidecode`（主板/CPU/内存）、`lspci`（PCI 设备）、`lsusb`（USB 设备）、`iostat`（磁盘 I/O）、`smartctl`（磁盘健康）；
- 备份考量：内容、媒介、方式（完整/累积/差异）、频率、工具；
- 推荐备份的关键目录：`/etc`、`/home`、`/root`、`/var/spool/`、`/var/lib/`、`/boot`；不备份 `/proc`、`/sys`、`/run`、`/tmp`、`/mnt`、`/media`；
- RAID 不是备份；重要数据要做异地备份；
- 完整备份常用工具：`dd`、`cpio`、`xfsdump`、`tar`；远程备份与镜像首选 `rsync` over SSH；
- 累积备份：备份量小、还原慢；差异备份：备份量大、还原快；
- 安全事件后不要直接还原旧系统，应重装最新版并修补漏洞。

## 20.8 习题

- 用哪个命令查询系统所有 PCI 设备？想看更详细的信息呢？
  - `lspci`，加 `-v` 或 `-vv` 看更详细输出。
- 只查询 USB 设备呢？
  - `lsusb`（加 `-t` 看树状层级）。
- 网络配置无误但网络不通，应如何排查？
  - (1) 检查网卡/交换机/路由器灯号；(2) `ip addr` 看 IP 与 netmask；(3) `ip route` 看默认网关；(4) `ping -c 3 <网关>`；(5) `ping -c 3 <公网 IP>`；(6) `dig www.google.com` 验证 DNS，失败则查 `/etc/resolv.conf`。
- 常见的完整备份工具有哪些？
  - `xfsdump`/`xfsrestore`、`dd`、`cpio` 配合 `find`、`tar`。
- 调研 Clonezilla（再生龙）的还原机制，判断它属于完整备份还是增量备份。
- 设计一个适合自己的备份策略：明确备份数据、媒介、频率、工具，并用 `crontab` 自动化。
