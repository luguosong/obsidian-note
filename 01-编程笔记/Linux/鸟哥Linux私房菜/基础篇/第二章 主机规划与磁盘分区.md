# 第二章 主机规划与磁盘分区

> [!info] 关于本章
> 以鸟哥原作（CentOS 7 版）为骨架，已更新到当前 **Rocky/AlmaLinux 9** 状态，术语统一为大陆通行写法。关键现代化点：**GPT/UEFI 已成当前默认**（MBR/BIOS 仅作遗留对照）；**NVMe SSD** 有专门命名规则（`/dev/nvme0n1p1`）；分区工具改用 `gdisk` / `parted`；默认文件系统为 **xfs**；CentOS 7 已于 **2024-06-30 EOL**，不再用于新部署。

要安装好一台 Linux 主机，需要针对发行版特性、服务器软件能力、未来升级与硬件扩展等需求进行规划，并理解磁盘分区、文件系统、Linux 常用目录等概念。本章只做先期说明——许多内容（如文件系统细节）初学者可能一时难以理解，可在学完后续章节后再回来查阅。

## 2.1 Linux 与硬件的搭配

Linux 对电脑各元件/设备的分辨方式与 Windows 完全不同——**在 Linux 中，每个设备都是"一个文件"**。这是学习 Linux 设备名前必须先建立的观念：先把 Windows 那种 "C 盘/D 盘/光驱 E" 的概念放下，否则会很难理解。

此外，由于硬件更新速度往往快于 Linux 内核纳入驱动的速度，选购新硬件（尤其网卡、显卡、阵列卡等）时应选择已经过 Linux 兼容性测试的产品，并确认厂商提供 Linux 驱动。主流厂商的硬件大多已被内核内置驱动覆盖。

### 2.1.1 认识电脑硬件

各硬件元件已在第零章介绍，此处仅给出个人电脑各元件的相关性示意图。

![[vbird-1ffbc88ba9209a43.webp]]
*图：个人电脑各元件的相关性*

**硬件选购的几个考量角度**：

| 角度 | 说明 |
|---|---|
| 用途定位 | 游戏机/图形工作站对 CPU、显卡要求高；办公机用入门级即可；服务器强调稳定性与 I/O |
| 性价比 | 不必追最新最贵；"性能/价格"与"性能/每瓦"都是参考维度。服务器 7×24 运行时，每多 50 W 一年约多耗 438 度电 |
| 兼容性 | 选购前确认该硬件对 Linux 提供驱动；优先选主流芯片（如 Intel、Broadcom 网卡），内核支持更好 |

### 2.1.2 选择与 Linux 搭配的主机配备

Linux 对硬件要求并不高——五年内淘汰的电脑（如 i3 等级以上）通常足以胜任一般小型服务器或练习机。但不同任务的硬件侧重不同：

| 角色 | CPU | 内存 | 硬盘 | 网卡 | 显卡 |
|---|---|---|---|---|---|
| 小型主机（无图形界面，如 NAT/网关） | 入门级即可 | ≥ 2 GB | 容量需求低 | 普通千兆 | 任意能识别即可 |
| 桌面/练习机（含图形界面） | 中端多核 | ≥ 4 GB | SSD 优先 | 千兆 | 现代集成/独立显卡均可 |
| 中大型服务器（FTP/Mail/WWW） | 多核中高端 | ≥ 8 GB | RAID / 大容量 | Intel/Broadcom 双口 | 无图形需求可省 |

> [!tip] 服务器建议买品牌机
> 企业用服务器不要自行组装。商用服务器（Dell PowerEdge、HPE ProLiant、联想 ThinkSystem 等）已通过散热与稳定性测试，且有厂商保修；自行组装省的钱，可能因一次故障排查成本就抵消了。

- [Linux 笔记本兼容性](https://www.linux-laptop.net/)

### 2.1.3 各硬件设备在 Linux 中的文件名

Linux 中几乎所有硬件设备文件都在 `/dev` 目录下。常见设备及其文件名：

| 设备 | 文件名 |
|---|---|
| SATA / SAS / USB 硬盘 | `/dev/sd[a-p]` |
| **NVMe SSD** | `/dev/nvme0n1`，分区为 `/dev/nvme0n1p1`、`/dev/nvme0n1p2`… |
| VirtIO 磁盘（虚拟机） | `/dev/vd[a-p]` |
| CD/DVD-ROM | `/dev/sr0`（常见），`/dev/cdrom` 为符号链接 |
| 打印机（USB） | `/dev/usb/lp[0-15]` |
| 软盘（已淘汰） | `/dev/fd[0-1]` |
| IDE 硬盘（已淘汰） | 历史上 `/dev/hd[a-d]`，现也模拟为 `/dev/sd[a-p]` |

> [!note] 设备文件名的分配规则
> - **SATA/USB 设备**使用 SCSI 驱动模块，文件名按**内核检测到设备的顺序**分配，而非插槽代号。例如主板 SATA1 插槽上的盘未必是 `/dev/sda`——以实际识别为准。
> - **NVMe 盘**的命名是稳定的（基于控制器号 + 命名空间号 + 分区号），不随检测顺序变化：`nvme0`（第 0 个控制器）+ `n1`（第 1 个命名空间）+ `p1`（第 1 个分区）。`p` 前缀避免与命名空间号混淆。
> - **虚拟机**若使用 VirtIO 接口，磁盘文件名为 `/dev/vd[a-p]`，性能更佳。

更详尽的内核设备号列表见 [Linux allocated devices（kernel.org）](https://www.kernel.org/doc/html/latest/admin-guide/devices.html)。

### 2.1.4 使用虚拟机学习

现代 CPU（Intel VT-x、AMD-V）均集成硬件虚拟化指令集，普通 PC 即可虚拟出多台独立系统。虚拟机环境便于复现统一的学习环境，且未来工作中接触到的 Linux 服务器也常以虚拟机（或容器）形式交付。

常见虚拟化方案：

| 方案 | 类型 | 适用 |
|---|---|---|
| **KVM / libvirt（virt-manager）** | Type-1（内核模块） | Linux 宿主，本书推荐 |
| **VirtualBox** | Type-2 | Windows / macOS / Linux 宿主，入门友好 |
| **VMware Workstation / Fusion** | Type-2 | 桌面虚拟化，商业 |
| **Hyper-V** | Type-1 | Windows 宿主 |

## 2.2 磁盘分区

Linux 系统安装在磁盘上。一块物理磁盘可被划分为多个**分区（partition）**——类似 Windows 下的 C:、D:、E: 盘。但 Linux 的分区表示、分区表格式与启动检测方式都与 Windows 不同。

### 2.2.1 磁盘连接方式与设备文件名

详见 2.1.3。磁盘盘片上以同心圆划分存储区（物理结构详见第零章）：

- **扇区（sector）**：最小物理存储单位（传统 512 Byte，现代先进格式化 4 K）
- **磁道（track）**：同一同心圆上的扇区集合
- **柱面（cylinder）**：多盘片同一磁道的组合

整块磁盘的**第一个扇区**记录了整块磁盘的重要信息——分区表所在。分区表格式分两种：传统 **MBR** 与现代 **GPT**。

### 2.2.2 MBR 与 GPT 磁盘分区表

**MBR（Master Boot Record）分区表**（遗留方案）

MBR 将分区表与启动记录放在磁盘第一个 512 Byte 的扇区：

| 区域 | 大小 | 用途 |
|---|---|---|
| 主要启动记录区（MBR） | 446 Byte | 安装启动管理程序 |
| 分区表（partition table） | 64 Byte | 记录整盘分区状态 |
| 结束标志 | 2 Byte | `0x55AA` |

分区表仅 64 Byte，每组记录 16 Byte，故**最多 4 组主/扩展分区记录**。MBR 模式下分区分三类：

- **主分区（Primary）**：可直接格式化使用
- **扩展分区（Extended）**：本身不可格式化，用于容纳逻辑分区；最多 1 个
- **逻辑分区（Logical）**：从扩展分区内继续划分；设备号从 5 开始（如 `/dev/sda5`、`/dev/sda6`）

![[vbird-5e97f6c8f01b37cc.webp]]
*图：MBR 分区表的作用*

![[vbird-2144f4cd489c4576.webp]]
*图：使用扩展分区容纳更多逻辑分区*

> [!warning] MBR 的主要限制
> - 单磁盘最大可寻址约 **2.2 TB**；
> - 分区表只有一份，损坏后恢复困难；
> - 启动管理程序仅 446 Byte，容纳不了大程序；
> - 主 + 扩展分区最多 4 个，逻辑分区设备号从 5 开始。

由于 MBR 的 2.2 TB 限制早已无法满足现代硬盘（消费级 20+ TB、企业级阵列可达数十至上百 TB），**当前磁盘默认采用 GPT 分区表**。MBR 仅在需要兼容旧系统时使用。

**GPT（GUID Partition Table）分区表**（当前默认）

GPT 使用 **LBA（Logical Block Address，逻辑块地址，默认 512 Byte）**规划整个磁盘，前 34 个 LBA 记录分区信息，并在**磁盘末尾的 33 个 LBA 做完整备份**——主分区表损坏时可从备份恢复。

![[vbird-98059046e7cbb33e.webp]]
*图：GPT 分区表的结构*

| LBA | 内容 |
|---|---|
| LBA0 | 兼容 MBR 的保护性区块（让不懂 GPT 的工具识别为 GPT 而非空盘，不会误改） |
| LBA1 | GPT 表头：记录分区表位置、大小、备份位置、CRC32 校验码 |
| LBA2–33 | 实际分区记录：每个 LBA 可记 4 笔，共 **128 个分区** |

GPT 每笔记录用 64 位记录起止扇区号，单分区理论上限约 **8 ZB**。GPT **已无主/扩展/逻辑之分**——每个分区都可独立格式化使用。

> [!tip] 分区工具选择
> 老牌的 `fdisk` 不支持 GPT。处理 GPT 磁盘须用 **`gdisk`**（交互式，类 `fdisk`）或 **`parted`**（脚本友好）。这些命令在第二篇详述。

### 2.2.3 开机流程：BIOS 与 UEFI

开机时硬件如何识别并加载操作系统？这涉及固件层的启动检测程序——**BIOS** 与 **UEFI**。

**传统 BIOS + MBR 启动流程**

```mermaid
flowchart LR
    A["BIOS 固件"] --> B["第一个可启动设备<br/>第一个扇区 MBR"]
    B --> C["启动管理程序<br/>boot loader, 446 Byte"]
    C --> D["内核文件"]
    D --> E["操作系统启动"]
```

1. **BIOS**：开机主动执行的固件，识别第一个可启动设备
2. **MBR**：第一个可启动设备的第一个扇区，含启动管理程序（446 Byte）
3. **启动管理程序（boot loader）**：读取并加载内核文件
4. **内核文件**：开始操作系统

boot loader 的三大功能：

- 提供菜单（多重启动选择）
- 加载内核
- 转交控制权给其他 loader（每个分区都有自己的 boot sector）

![[vbird-96586755af2d4ba3.gif]]
*图：启动管理程序的工作流程（多重启动）*

> [!note] 为什么多重启动要先装 Windows 再装 Linux
> Windows 安装时会**覆盖 MBR 与自身分区的 boot sector**，且不提供选择菜单；Linux 安装时可选择安装到 MBR 或分区 boot sector，并能手动配置菜单（含 Windows 项）。先装 Linux 后装 Windows 会把 Linux 的启动菜单覆盖掉，需用 Linux 救援模式修复。

**UEFI + GPT 启动流程**（当前默认）

UEFI（Unified Extensible Firmware Interface）是为取代 BIOS 而设计的固件接口，用 C 语言编写，支持图形界面、驱动加载与 TCP/IP，启动更快。

| 比较项 | 传统 BIOS | UEFI |
|---|---|---|
| 程序语言 | 汇编 | C |
| 资源管理 | 中断（IRQ） | 驱动程序与协议 |
| 处理器模式 | 16 位 | CPU 保护模式（32/64 位） |
| 图形界面 | 差 | 好 |
| GPT 支持 | 需兼容模式 | 原生 |
| 安全启动（Secure Boot） | 无 | 支持 |

```mermaid
flowchart LR
    A["UEFI 固件<br/>(Secure Boot 验证签名)"] --> B["EFI 系统分区 ESP<br/>FAT32, /boot/efi"]
    B --> C["启动管理程序<br/>grub2-efi / shim"]
    C --> D["Linux 内核"]
    D --> E["系统启动"]
```

> [!info] EFI 系统分区（ESP）
> UEFI 系统需一个 **FAT32 格式的 EFI 系统分区**（EFI System Partition，ESP，Anaconda 安装器默认约 600 MB，挂载在 `/boot/efi`），存放启动管理程序（如 `grub2-efi`、`shim`）。RHEL 9 / Rocky 9 安装时会自动创建此分区。

> [!warning] Secure Boot 与 Linux
> Secure Boot 要求启动的操作系统内核被 UEFI 信任的密钥签名。RHEL 9 / Rocky 9 / Ubuntu 等主流发行版的内核已签名，默认可与 Secure Boot 共存；少数自编译内核或小众发行版可能需在固件设置中关闭 Secure Boot。

### 2.2.4 Linux 安装模式下的磁盘分区选择（重要）

**目录树结构**

Linux 中所有数据都以文件形式存在，整个系统建立在**目录树（directory tree）**之上：以根目录 `/` 为根，向下分支。例：`/home/dmtsai/mydata`。

![[vbird-c43e6eef65e04502.gif]]
*图：目录树结构*

**文件系统与目录树的关系：挂载（mount）**

目录树是逻辑结构，数据实际存放在磁盘分区上。**挂载**就是将一个目录作为"入口点"，把分区的数据放到该目录下——进入该目录即可读取该分区。这个入口点目录称为**挂载点**。

![[vbird-1cae304bced27ada.webp]]
*图：目录树与分区之间的关系*

例：上图 partition 1 挂载到 `/`，partition 2 挂载到 `/home`。判断某文件在哪个分区，沿路径**反向追溯**到最近的挂载点即可。

**安装时的分区规划**

强烈建议使用**自定义（Custom）安装模式**：

- **初学者**：只分 `/`（根）和 `swap`（交换分区）即可，避免分错导致无法安装。
- **进阶建议**：预留一部分未分配容量，供后续练习分区与备份使用。

> [!tip] 现代安装的分区建议
> RHEL 9 / Rocky 9 默认方案（UEFI + GPT，使用 LVM）：
> - `/boot/efi`（ESP，FAT32，~600 MB）
> - `/boot`（xfs，~1 GB）
> - `/`（xfs，剩余空间，通常在 LVM 上）
> - `swap`（与内存相近或按需）
>
> 服务器场景按服务类型独立出 `/home`、`/var`、`/tmp` 等读写频繁的目录，避免其故障波及根分区。**RHEL 9 默认文件系统为 xfs**（不再是 ext4）。

## 2.3 安装 Linux 前的规划

### 2.3.1 选择合适的发行版

各发行版使用相同的 Linux 内核，软件大同小异，主要差别在包管理与升级策略。**服务器场景**优先选企业级发行版（升级稳定、支持周期长）：

| 发行版 | 类型 | 支持周期 |
|---|---|---|
| **RHEL 9** | 商业 | 10 年 |
| **Rocky Linux 9 / AlmaLinux 9** | RHEL 兼容（免费） | 与 RHEL 同步 |
| **Ubuntu LTS 24.04** | Debian 系 | 5 年（标准支持） |
| **Debian 12** | 社区 | 约 5 年 |
| **openSUSE Leap 15** | 企业级兼容 | 约 2.5 年/版本 |

> [!warning] CentOS 7 已 EOL
> CentOS 7 已于 **2024-06-30** 停止维护（EOL），不再接收安全更新，不应再用于新部署。原本作为 CentOS 接替者的 **CentOS Stream** 滚动版是 RHEL 的上游，可用于尝鲜但非生产首选；生产环境建议选 Rocky Linux 9 / AlmaLinux 9 这类稳定重建版。

下载镜像建议从官方镜像站获取（如 [Rocky Linux 下载](https://rockylinux.org/download)、[AlmaLinux 下载](https://almalinux.org/get-almalinux/)），国内可选清华、中科大等镜像站加速。常用镜像类型：

- **DVD / Full ISO**：完整安装（离线场景）
- **Minimal**：最小化安装（练手推荐）
- **Boot / Netinstall**：网络安装

下载的 `.iso` 是**映像文件**，不能用普通数据刻录——须用 Rufus、`dd` 或专门工具按"映像"模式写入 U 盘：

```bash
# 将 ISO 写入 U 盘（/dev/sdX 为 U 盘设备名，注意别写错盘）
dd if=Rocky-9-x86_64-minimal.iso of=/dev/sdX bs=4M status=progress && sync
```

### 2.3.2 服务规划与硬件的关系

不同服务对硬件的侧重不同：

| 服务 | 关键硬件 | 备注 |
|---|---|---|
| NAT / 网关 | 网卡 | 流量大；不如硬件路由器省电 |
| SAMBA（文件共享） | 硬盘、网卡 | `/home` 建议独立分区 |
| Mail（邮件） | 硬盘、网卡 | `/var` 建议独立分区 |
| WWW（Web，Apache/Nginx） | 内存、CPU（若有动态语言/数据库） | 提升内存通常最有效 |
| DHCP | 无特殊要求 | 入门级即可 |
| FTP | 硬盘、网卡 | 注意合法合规 |

### 2.3.3 主机磁盘的主要规划

分区规划的核心考量：**数据分类**与**数据安全**（指硬件故障时数据能否保全）。

- **懒人分区法**：只分 `/` 和 `swap`。简单但风险高——根分区任何坏道都可能影响整个系统。
- **推荐分区法**：根据主机用途，把容量大或读写频繁的目录独立出来。常见独立目录：`/boot`、`/home`、`/var`、`/tmp`。

> [!example] 案例（现代化版）
> - **小型家用服务器（NAT + 文件共享）**：退役 PC（如四核 CPU、8 GB 内存、SSD + 大容量 HDD），分 `/`、`/home`、`swap`；装 Rocky Linux 9 Minimal。
> - **研究用计算集群**：双路多核服务器、128 GB+ 内存、10 GbE 网卡、RAID 阵列；系统盘分 `/boot`、`/`、`swap`，数据盘整体挂载到 `/data`。

## 2.4 重点回顾

- 选购硬件需考量用途定位、性价比、能耗与 Linux 兼容性；
- **Linux 中每个设备都是文件**，设备文件位于 `/dev`；常见：SATA/USB 盘 `/dev/sd[a-p]`、**NVMe `/dev/nvme0n1`（分区 `p1`、`p2`…）**、虚拟机 VirtIO `/dev/vd[a-p]`；
- 分区表两种格式：**MBR**（遗留，2.2 TB 限制，最多 4 主/扩展分区，逻辑分区从 5 开始）与 **GPT**（当前默认，最多 128 分区，自带备份）；
- GPT 分区工具用 `gdisk` / `parted`，`fdisk` 不支持 GPT；
- 启动流程：BIOS/UEFI → 启动管理程序 → 内核 → 操作系统；
- UEFI 原生支持 GPT 与 Secure Boot，需一个 FAT32 的 EFI 系统分区（`/boot/efi`）；
- 启动管理程序可装在 MBR 或各分区的 boot sector，多重启动建议先装 Windows 再装 Linux；
- Linux 用目录树组织文件，通过**挂载**把分区接入目录树；
- CentOS 7 已 EOL，新部署用 Rocky/AlmaLinux 9；RHEL 9 默认文件系统为 **xfs**。

## 2.5 本章习题

**问答题**：

1. 一台电脑只要 CPU 够快，整体速度就一定快吗？
   - 不一定。系统速度受内存、硬盘、显卡、I/O 等各元件综合影响（木桶效应）。
2. Linux 对硬件的要求是否一定很高？
   - 视服务种类与规模而定。家用 NAT/网关用入门硬件即可；计算/数据库服务器才需要强 CPU 与大内存。
3. 写出下列设备在 Linux 中的文件名：SATA 硬盘、NVMe SSD、CD-ROM、（USB）打印机。
   - SATA 硬盘：`/dev/sd[a-p]`；NVMe SSD：`/dev/nvme0n1`（分区 `p1`、`p2`…）；CD-ROM：`/dev/sr0`（或 `/dev/cdrom`）；USB 打印机：`/dev/usb/lp[0-15]`。
4. 当前个人电脑主板上常见的硬盘接口有哪些？
   - **M.2 NVMe**（PCIe 通道，主流高速 SSD）、**SATA**（机械盘与旧式 SSD）、外接 **USB**；服务器还有 **SAS**。
5. 为什么大于 2 TB 的磁盘要用 GPT 而非 MBR？
   - MBR 分区表用 32 位记录扇区号，最大约 2.2 TB；GPT 用 64 位，理论上限 8 ZB。

**实作题**：

- 找一台退役 PC（或虚拟机），用 `lsblk`、`fdisk -l`、`gdisk -l /dev/sdX` 查看磁盘与分区表类型，理解自己机器是 MBR 还是 GPT。
