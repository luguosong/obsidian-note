# 第八章 文件与文件系统的压缩、打包与备份

> [!info] 关于本章
> 本章以鸟哥《Linux 私房菜 — 基础学习篇》第八章为骨架，已更新至当前 **Rocky/AlmaLinux 9 / RHEL 9** 状态，术语统一为大陆通行写法。关键现代化点：补入当前内核与包管理广泛采用的 **zstd**（`.zst`）；包管理命令 `yum` → `dnf`；**xfsdump/xfsrestore** 在 RHEL 9 中标为 deprecated（已弃用）但仍随仓库提供、可正常使用；光盘刻录一节因 USB/NVMe 已实质取代光盘而大幅精简，仅留映像制作要点并指向 `xorriso`。

## 8.1 压缩文件的用途与技术

文件太大会带来一连串麻烦：邮件附件超限、归档介质装不下、备份占用大量磁盘空间。**文件压缩**技术就是为解决这些问题而生——通过算法把文件占用的磁盘空间降下来；需要使用时再**解压缩**还原。压缩后与压缩前所占空间之比称为**压缩比**。

**压缩的直觉原理**：计算机最小单位是 bit，但操作系统以 byte（1 byte = 8 bits）存取。记录数字 `1` 时，真正有意义的只有最右 1 个 bit，其余 7 个 bit 都是填充的 0。压缩算法就是把这种"空闲"位与重复模式重新编码丢弃。例如 100 个连续的 `1`，可记录为"100 个 1"，而不必真存 100 个位。

> [!note] 压缩的现代场景
> 除节省磁盘外，压缩在 **Web 传输**（HTTP gzip/brotli）、**包管理**（RPM/zstd、deb/xz、Arch `.pkg.tar.zst`）、**内核与 initramfs 镜像**中无处不在：传输的瓶颈是带宽而非 CPU，先压缩再传输反而更快。

## 8.2 Linux 常见的压缩命令

Linux 下压缩文件的扩展名大多为：`*.gz`、`*.bz2`、`*.xz`、`*.zst`、`*.tar`、`*.tar.gz`、`*.tar.bz2`、`*.tar.xz`、`*.tar.zst`。

> [!tip] 为什么 Linux 这么看重扩展名？
> Linux 文件属性本身与扩展名无关，但压缩工具很多且彼此不互通，给压缩文件一个公认的扩展名，是为了方便人眼快速判断该用哪个命令解压。

| 扩展名 | 压缩命令 | 说明 |
|---|---|---|
| `*.Z` | `compress` | 已淘汰，现用 `gzip` 解 |
| `*.zip` | `zip` / `unzip` | 跨平台，与 Windows 互通 |
| `*.gz` | `gzip` | 应用最广，速度最快 |
| `*.bz2` | `bzip2` | 压缩比优于 gzip，速度较慢 |
| `*.xz` | `xz` | 压缩比最佳，速度最慢 |
| `*.zst` | `zstd` | **当前主流**：速度近 gzip、比介于 gzip/bzip2 之间 |
| `*.tar` | `tar` | 仅打包，未压缩 |
| `*.tar.gz` / `.tar.bz2` / `.tar.xz` / `.tar.zst` | `tar` + 对应压缩器 | 打包并压缩 |

这些命令通常**只能针对单个文件**压缩/解压；要把一整个目录树"包成一个文件"，需要 `tar` 这类打包工具配合。

### 8.2.1 gzip

`gzip` 是应用最广的压缩命令，可解开 `compress`、`zip`、`gzip` 产生的文件，生成的压缩文件为 `*.gz`。

```bash
gzip [-cdtv#] 文件名
zcat 文件名.gz        # 不解压直接查看压缩文本文件内容

# 选项
-c  ：把压缩结果输出到标准输出，可配合重定向写文件（保留原文件）
-d  ：解压缩
-t  ：校验压缩文件一致性
-v  ：显示原文件/压缩文件的压缩比等信息
-#  ：压缩等级，-1 最快（压缩比最差）、-9 最慢（压缩比最好），默认 -6
```

**典型用法**：

```bash
# 压缩（默认删除原文件）
gzip -v services           # services -> services.gz

# 解压缩
gzip -d services.gz

# 最佳压缩比并保留原文件：用 -c 与重定向
gzip -9 -c services > services.gz

# 直接查看压缩文本，或在其中检索关键字（不必先解压）
zcat services.gz
zgrep -n 'http' services.gz
```

> [!warning] gzip 默认会删除原文件
> `gzip` 压缩后原文件消失，`gzip -d` 解压后 `.gz` 消失——这与 Windows 上 WinRAR/7-Zip 的习惯不同。想保留原文件请用 `-c > file.gz` 或 `-k`（较新版本的 gzip 支持）。

`zcat` / `zmore` / `zless` 对应 `cat` / `more` / `less`，可直接读取被压缩的**文本**文件；`zgrep` 可在压缩文本中检索关键字。

### 8.2.2 bzip2

`bzip2` 为追求比 `gzip` 更高的压缩比而生，用法几乎与 `gzip` 相同，扩展名为 `*.bz2`。

```bash
bzip2 [-cdkzv#] 文件名
bzcat 文件名.bz2

# 与 gzip 的差异：
-k  ：保留原文件（不删除）
-z  ：压缩（默认动作，可省略）
```

`bzip2` 的压缩比优于 `gzip`，但大文件耗时明显更长。配套的 `bzcat` / `bzgrep` 等用法同 `gzip`。

### 8.2.3 xz

`xz` 提供更高的压缩比，用法与 `gzip`/`bzip2` 几乎一致，扩展名为 `*.xz`。

```bash
xz [-dtlkc#] 文件名
xzcat 文件名.xz

# 与前两者不同的选项：
-l  ：列出压缩文件的压缩前后大小、压缩比等信息
-k  ：保留原文件
```

> [!note] 速度 vs 压缩比的权衡
> 以同一文件实测（鸟哥原数据）：`gzip` ≈ 0.019 s、`bzip2` ≈ 0.042 s、`xz` ≈ 0.261 s。`xz` 压缩比最佳但耗时约是 `gzip` 的 10 倍以上。**不计时间成本选 `xz`，看重速度选 `gzip`。**

### 8.2.4 zstd（Zstandard）

`zstd` 是 Meta（Facebook）开发的现代压缩算法，目标是**在 gzip 量级的速度下取得明显更好的压缩比**，已全面进入 Linux 生态：

- **内核**：Linux 5.9（2020）起支持 zstd 压缩的内核镜像与 initramfs；
- **包管理**：Fedora 31（2019）起 RPM 包默认用 zstd；Arch Linux 自 2019 年底包格式改为 `.pkg.tar.zst`；
- **内核源码 tarball** 与大量发行版软件包已普遍提供 `.zst` 版本。

```bash
zstd [-d] [-k] [-#] 文件名
# -d 解压；-k 保留原文件；-1..-19 压缩等级（默认 3，另有 --ultra -22）
# 对应打包：tar --zstd -cvf file.tar.zst ...（tar 1.31+ 支持 --zstd / -I zstd）
unzstd file.zst          # 等价于 zstd -d
zstdcat file.zst         # 不解压直接查看
```

> [!tip] 何时用 zstd？
> 需要兼顾**速度与压缩比**的场景首选 zstd——它在解压速度上远快于 xz，压缩比又优于 gzip，是目前内核镜像、initramfs、软件包分发的主流选择。追求极致压缩比、不在乎耗时仍用 xz。

## 8.3 打包命令：tar

`gzip`/`bzip2`/`xz`/`zstd` 只能针对单个文件；对目录压缩其实是"把目录里每个文件分别压缩"，不能像 Windows 的 WinRAR/7-Zip 那样把多个文件**包成一个大文件**。Linux 的打包工具就是 `tar`——它可把多个目录或文件打包成一个大文件，并可选地调用上述压缩器一并压缩。

### 8.3.1 tar 基本用法

```bash
# 打包并压缩
tar [-z|-j|-J|--zstd] [cv] [-f 新文件名] 文件或目录...
# 查看包内容
tar [-z|-j|-J|--zstd] [tv] [-f 既有 tar 文件名]
# 解包 / 解压
tar [-z|-j|-J|--zstd] [xv] [-f 既有 tar 文件名] [-C 目录]
```

| 选项 | 含义 |
|---|---|
| `-c` | 创建打包文件（打包/压缩） |
| `-t` | 查看包内文件名 |
| `-x` | 解包 / 解压（可配 `-C` 指定目录） |
| `-z` | 通过 **gzip** 压缩/解压，文件名建议 `*.tar.gz` |
| `-j` | 通过 **bzip2**，建议 `*.tar.bz2` |
| `-J` | 通过 **xz**，建议 `*.tar.xz` |
| `--zstd` | 通过 **zstd**，建议 `*.tar.zst`（或 `-I zstd`） |
| `-v` | 过程中显示正在处理的文件名 |
| `-f 文件名` | 紧接被处理的文件名；**建议 `-f` 单独写一个选项**，避免与其它选项粘连造成歧义 |
| `-C 目录` | 解压到指定目录 |
| `-p`（小写） | 保留原文件的权限与属性（备份重要配置时常用） |
| `-P`（大写） | 保留绝对路径（含根目录） |
| `--exclude=FILE` | 打包时排除匹配的文件 |

> [!warning] -c / -t / -x 互斥，-z / -j / -J / --zstd 互斥
> 三种动作（创建/查看/解包）只能选其一；四种压缩器也只能选其一。

**最常用三式**（以 xz 为例）：

```bash
# 压缩
tar -Jcv -f filename.tar.xz  要压缩的文件或目录
# 查询
tar -Jtv -f filename.tar.xz
# 解压到指定目录
tar -Jxv -f filename.tar.xz  -C  目标目录
```

> [!tip] 把 -f filename 单独写出来
> 早期很多文档写成 `tar -jcvf filename`，由于选项顺序理论上可换，有人误写 `-jvfc filename`，结果 `-fc` 让生成的文件名变成 `c`。学习阶段建议把 `-f filename` 与其它选项分开写，最不容易出错。

### 8.3.2 实战示例

**备份 `/etc`**（需 root）：

```bash
[root@study ~]# time tar -zpcv -f /root/etc.tar.gz /etc
tar: Removing leading `/' from member names   # 注意这条警告
/etc/
...（中间省略）...
# -p 保留原权限属性；-v 显示处理的文件名

[root@study ~]# time tar -jpcv -f /root/etc.tar.bz2 /etc
[root@study ~]# time tar -Jpcv -f /root/etc.tar.xz  /etc

[root@study ~]# ll -h /root/etc*
-rw-r--r--. 1 root root 6.7M  etc.tar.bz2
-rw-r--r--. 1 root root 7.6M  etc.tar.gz
-rw-r--r--. 1 root root 5.3M  etc.tar.xz
```

> [!note] 压缩比越好，耗时越多
> `gzip` 不到 1 秒但压缩比最差；`xz` 压缩比最佳却耗时约 9 秒（仅 28 MB 的 `/etc`）。备份大容量数据时务必把时间成本算进去。

**查看包内容与"去掉根目录"**

```bash
[root@study ~]# tar -jtv -f /root/etc.tar.bz2
...
-rw-r--r-- root/root  131  2015-05-25 17:48 etc/locale.conf
-rw-r--r-- root/root   19  2015-05-04 17:56 etc/hostname
```

注意每个文件名都**没有根目录 `/`**——这正是上一条警告 `Removing leading '/' from member names` 的含义。

> [!warning] 为什么 tar 默认去掉根目录？为了安全
> tar 记录的文件名就是解压时的实际路径。若保留绝对路径，解压时文件会按原绝对路径覆盖回去，可能用旧备份覆盖现有系统的 `/etc` 等关键目录。去掉根目录后，解压总是落到当前目录下，更安全。**确需备份绝对路径才用 `-P`，一般不建议。**

**解压到指定目录（`-C`）**

```bash
[root@study ~]# tar -jxv -f /root/etc.tar.bz2 -C /tmp   # 解到 /tmp
[root@study ~]# rm -rf /root/etc /tmp/etc               # 清理（rm -rf 务必核对路径）
```

**仅解开单个文件**：先用 `-t` 找到包内完整文件名（注意是相对路径，无前导 `/`），再针对性解包。

```bash
[root@study ~]# tar -jtv -f /root/etc.tar.bz2 | grep 'shadow'
---------- root/root 1210 ... etc/shadow      # 这是我们要的
[root@study ~]# tar -jxv -f /root/etc.tar.bz2 etc/shadow
```

**打包时排除部分文件（`--exclude`）**

```bash
[root@study ~]# tar -jcv -f /root/system.tar.bz2 \
  --exclude=/root/etc* --exclude=/root/system.tar.bz2  /etc /root
```

**只备份比某个时刻新的文件（`--newer-mtime`）**

```bash
[root@study ~]# find /etc -newer /etc/passwd           # 先确认哪些文件更新
[root@study ~]# tar -jcv -f /root/etc.newer.tar.bz2 \
  --newer-mtime="2015/06/17" /etc/*
# 末尾 `file is unchanged; not dumped` 表示该文件未被备份（因不比该时间新）
```

`--newer` 同时考虑 mtime 与 ctime，`--newer-mtime` 只看 mtime。该机制可实现**增量备份**——上次完整备份后只备份变动过的文件。

**tarfile 与 tarball**：仅打包（`tar -cv -f file.tar`）称为 **tarfile**；打包并压缩（如 `tar -jcv -f file.tar.bz2`）称为 **tarball**。

**打包到设备**：tar 可直接写到磁带机等设备，例如 `tar -cv -f /dev/st0 /home /root /etc`。

**通过管道复制目录树**：用 `-` 代表标准输入/输出。

```bash
[root@study tmp]# tar -cvf - /etc | tar -xvf -     # 类似 cp -r /etc .
```

**系统备份范例**：备份重要目录到 `/backups`（仅 root 可进），文件名带日期，并排除已有压缩包。

```bash
[root@study ~]# mkdir /backups && chmod 700 /backups
[root@study ~]# tar -jcv -f /backups/backup-system-20260805.tar.bz2 \
  --exclude=/root/*.bz2 --exclude=/root/*.gz --exclude=/home/loop* \
  /etc /home /root /var/spool/mail /var/spool/cron
```

> [!warning] 解压还原后的 SELinux 问题
> 用 tar 把 `/etc` 等系统文件还原回原系统后，可能因 SELinux 上下文类型丢失而**无法正常登录**。处理办法：
> - 还原后先别重启，执行 `restorecon -Rv /etc` 修复 SELinux 类型；
> - 或在 `/etc/selinux/config` 中临时设为 `permissive`；
> - 或建 `/.autorelabel` 后重启，让系统自动重新标记。
>
> `/var/spool/cron` 即各账号的**定时任务配置文件**（cron）。

## 8.4 XFS 文件系统的备份与还原

`tar` 面向目录树；若想对**整个文件系统**做备份与还原，XFS 提供 `xfsdump` 与 `xfsrestore`。RHEL/Rocky/AlmaLinux 默认文件系统为 XFS，故这两个工具仍常见。

> [!info] 现代化提示
> `xfsdump`/`xfsrestore` 在 **RHEL 9 中已被标记为 deprecated（弃用）**，但仍随 AppStream 仓库提供、完整可用（`dnf install xfsdump`），支持周期内（约至 2032）不会被移除。需注意 `dump`/`restore`（针对 ext2/3/4 的同类工具）已在 RHEL 9 中被移除。

### 8.4.1 xfsdump：文件系统备份

`xfsdump` 支持**完整备份（level 0）**与**增量备份（level 1–9）**。增量备份只记录与上一级差异。

![[vbird-8b66bc73116a1a72.gif]]
*图：xfsdump 的完整备份与增量备份示意*

**使用限制**：

- 只能备份**已挂载**的 XFS 文件系统（不备份未挂载的）；
- 必须 root 权限；
- 只能备份 **XFS**；
- 备份产物只能由 `xfsrestore` 解析；
- 通过文件系统 UUID 区分，**不能备份两个 UUID 相同**的文件系统；
- 默认只支持文件系统级备份，**不能用来备份 `/etc`**（`/etc` 不是独立文件系统）。

```bash
xfsdump [-L S_label] [-M M_label] [-l #] [-f 备份文件] 待备份文件系统
xfsdump -I                          # 查询已有备份信息

# -L  本次备份的 session 标签（简易说明）
# -M  存储介质标签
# -l  等级 0~9（0 为完整备份，默认）
# -f  备份文件（可接 /dev/st0 等设备）
# -I  从 /var/lib/xfsdump/inventory 列出备份状态
```

**完整备份 `/boot`**（须为独立文件系统）：

```bash
[root@study ~]# df -h /boot                          # 先确认 /boot 是独立文件系统
[root@study ~]# xfsdump -l 0 -L boot_all -M boot_all -f /srv/boot.dump /boot
[root@study ~]# ll /var/lib/xfsdump/inventory        # 备份元数据写在此处
```

**增量备份**：先 `dd if=/dev/zero of=/boot/testing.img bs=1M count=10` 制造变动，再做 level 1。

```bash
[root@study ~]# xfsdump -l 1 -L boot_2 -M boot_2 -f /srv/boot.dump1 /boot
[root@study ~]# xfsdump -I                            # 可看到 level 0 与 level 1 两条 session
```

### 8.4.2 xfsrestore：文件系统还原

```bash
xfsrestore -I                                        # 查看备份信息（输出同 xfsdump -I）
xfsrestore [-f 备份文件] [-L S_label] [-s 目录]  目标目录
xfsrestore [-f 备份文件] -r  目标目录               # 通过累积备份还原
xfsrestore [-f 备份文件] -i  目标目录               # 交互模式
```

**还原 level 0**（同名文件被覆盖，目标处其它新文件保留）：

```bash
[root@study ~]# xfsrestore -f /srv/boot.dump -L boot_all /tmp/boot
[root@study ~]# diff -r /boot /tmp/boot              # 用 diff 比较两个目录差异
```

**仅还原某子目录（`-s`）**：

```bash
[root@study ~]# xfsrestore -f /srv/boot.dump -L boot_all -s grub2 /tmp/boot2
```

**依次还原累积备份**：level 0 → level 1 → … 顺序还原。

```bash
[root@study ~]# xfsrestore -f /srv/boot.dump1 /tmp/boot
```

**交互模式（`-i`）**：可在还原前 `ls`/`cd`/`add`/`extract`，只挑需要的文件还原。

## 8.5 光盘映像与刻录（已基本被 USB/NVMe 取代）

光盘（CD/DVD）因容量小、速度慢、不便携，目前除了归档场景外几乎被 **U 盘、移动硬盘、NVMe SSD** 取代，蓝光也主要用于多媒体影音。服务器环境下"刻盘"已很罕见，故本节仅保留要点。需要制作安装 U 盘时，更常用的做法是把 ISO 用 `dd` 或专用工具（如 Ventoy、Rufus、BalenaEtcher）写入 U 盘。

| 传统命令 | 现代替代 | 用途 |
|---|---|---|
| `mkisofs` | `xorriso`、`genisoimage`（`mkisofs` 常为其别名） | 制作 ISO 映像 |
| `cdrecord` / `wodim` | `xorriso` | 刻录光盘（罕见） |
| `dd if=xxx.iso of=/dev/sdX bs=4M` | 同左 / Ventoy 等 | 制作可启动 U 盘（当前主流） |

**制作数据 ISO**（用 `-graft-point` 把多个目录映射到映像内不同路径）：

```bash
[root@study ~]# mkisofs -r -V 'linux_file' -o /tmp/system.img \
  -m /root/etc -graft-point /root=/root /home=/home /etc=/etc
# -r  通过 Rock Ridge 记录 UID/GID/权限等 Unix 属性
# -V  卷标
# -m  排除文件
# -graft-point  映像内路径=实际路径
```

制作可启动 ISO（修改原版安装镜像内容后重新打包）需要保留 isolinux/GRUB 引导信息，可改用 `xorriso -as mkisofs ...` 调用，命令行与 `mkisofs` 兼容。

## 8.6 其他常见的压缩与备份工具

### 8.6.1 dd

`dd` 可直接按扇区读写设备，把整个设备（磁盘/分区/光驱）原样备份成一个文件，也可用于制作启动 U 盘。

```bash
dd if="输入文件或设备" of="输出文件或设备" bs="块大小" count="块数"
# 默认 bs=512 bytes（一个扇区）
```

| 场景 | 命令 |
|---|---|
| 备份普通文件 | `dd if=/etc/passwd of=/tmp/passwd.back` |
| 把光盘做成 ISO | `dd if=/dev/sr0 of=/tmp/system.iso` |
| 把 ISO 写入 U 盘（做启动盘） | `dd if=/tmp/system.iso of=/dev/sdX bs=4M` |
| 整个文件系统镜像备份 | `dd if=/dev/vda2 of=/tmp/vda2.img` |

> [!warning] dd 是"笨"但"通用"的备份
> `dd` 逐扇区复制，**未使用的空间也会被写入备份**，因此镜像文件与设备原始容量一样大（不像 `xfsdump` 只备份已用部分）。但它**不理会文件系统格式**，无论你认不认识其中的文件系统都能完整备份还原，这是它不可替代的价值。

> [!tip] dd 复制 XFS 分区后需重置 UUID
> 用 `dd` 把一个 XFS 分区复制到另一个分区后，两者 UUID 相同会导致无法同时挂载。需先 `xfs_repair -L /dev/sda1` 清空日志，再用 `xfs_admin -U $(uuidgen) /dev/sda1` 赋予新 UUID；若新分区更大，用 `xfs_growfs /mnt` 扩展文件系统占用剩余空间。

> [!warning] 命令行 fdisk 已不适用于现代 GPT/UEFI 系统
> 原作中分区用 `fdisk`（MBR）。现代系统普遍 **UEFI + GPT**，分区应改用 `gdisk`、`parted` 或 `sgdisk`。`fdisk` 在较新版本虽也支持 GPT，但 `gdisk`/`parted` 是更稳妥的选择。

### 8.6.2 cpio

`cpio` 能备份**任何东西**（包括 `/dev` 下的设备文件），但**不会主动找文件**——必须借助 `find` 把文件名通过管道喂给它。因此它常与数据流重定向、管道命令配合使用。

```bash
cpio -ovcB  > [文件或设备]    # 备份
cpio -ivcdu < [文件或设备]    # 还原
cpio -ivct  < [文件或设备]    # 查看

# 备份选项：-o 输出、-B 块大小增至 5120 bytes（加速）
# 还原选项：-i 读入、-d 自动建目录、-u 新覆盖旧、-t 查看
# 通用：-v 显示文件名、-c portable format
```

**典型用法**（务必先 `cd /` 用相对路径，否则解压会覆盖原绝对路径）：

```bash
[root@study /]# find boot | cpio -ocvB > /tmp/boot.cpio   # 备份 /boot
[root@study ~]# cpio -idvc < /tmp/boot.cpio               # 在当前目录还原
# 备份到磁带机：find / | cpio -ocvB > /dev/st0
# 还原：        cpio -idvc < /dev/st0
```

> [!info] initramfs 就是 cpio 存档
> 系统自带的 `/boot/initramfs-<内核版本>.img` 就是一个 cpio 存档，可用 `file` 命令确认（`ASCII cpio archive`），再用 `cpio -idvc < initramfs-xxx.img` 解开查看其内容（含早期加载的 microcode、驱动等）。

## 8.7 重点回顾

- **压缩**通过算法减少文件占用的磁盘空间，压缩后/前容量比即**压缩比**；压缩也广泛用于网络传输、Web、包管理以提升带宽利用率。
- 常见压缩扩展名：`*.gz`、`*.bz2`、`*.xz`、`*.zst`、`*.tar.*`。压缩比 `xz` 最佳、`bzip2` 次之、`gzip` 最快；**`zstd` 在速度近 gzip 的同时压缩比明显更好，是当前内核镜像/initramfs/包分发的主流**。
- `tar` 打包并可配合 `-z`/`-j`/`-J`/`--zstd` 调用 gzip/bzip2/xz/zstd：压缩 `-Jcv -f file.tar.xz`、查询 `-Jtv -f`、解压 `-Jxv -f -C 目录`。
- `tar` 默认去掉文件名前导 `/`（安全考虑），需保留绝对路径才用 `-P`；还原 `/etc` 等系统文件后注意用 `restorecon` 修复 SELinux 上下文。
- `xfsdump`/`xfsrestore` 面向整个 XFS 文件系统，支持 level 0–9 增量备份；RHEL 9 中已弃用但仍可用，`dump`/`restore`（ext）已被移除。
- 光盘刻录（`mkisofs`/`cdrecord`）已基本被 U 盘/NVMe 取代，制作启动盘的主流是 `dd if=iso of=/dev/sdX` 或 Ventoy 等工具；ISO 制作可改用 `xorriso`。
- `dd` 按扇区复制，能备份任何文件系统/设备，但镜像与原设备等大；复制 XFS 分区后需 `xfs_repair -L` + `xfs_admin -U` 重置 UUID。
- `cpio` 可备份任意文件（含设备文件），但需配合 `find` 与管道/重定向；系统的 `initramfs` 即 cpio 存档。

## 8.8 本章习题

- **情境一：清理练习产物。** 把本章练习中产生的临时文件全部删除，例如 `/tmp/services*`、`/tmp/system.*`、`/tmp/boot*`、`/tmp/*.dump*`、`/root/etc*`、`/root/system.tar.*`、`/root/boot` 等。
- **情境二：用 xfsdump 增量备份 `/home`。** 假设 `/home` 是独立分区：
    1. 准备数据：`mkdir /home/chapter8; cp -a /etc /boot /home/chapter8`
    2. 完整备份：`mkdir /backups; xfsdump -l 0 -L home_all -M home_all -f /backups/home.dump /home`
    3. 改动数据：`cp -a /var/log/ /home/chapter8`
    4. 增量备份：`xfsdump -l 1 -L home_1 -M home_1 -f /backups/home.dump.1 /home`；可观察到第二个文件明显小很多。
- **情境三：用 xfsrestore 还原 `/home`。**
    1. 因 `/home` 一旦有用户登录就会被占用，需先**注销所有普通用户**，切到 tty2 直接以 root 登录（不要普通账号 `su` 转 root），才能卸载 `/home`。
    2. `umount /home` 后 `mkfs.xfs -f /dev/mapper/rl-home`（卷组名按实际，Rocky 9 默认为 `rl`）重新格式化。
    3. `mount -a` 重新挂载，确认 `/home` 为空。
    4. 依次还原：`cd /home && xfsrestore -f /backups/home.dump .`；再 `xfsrestore -f /backups/home.dump.1 .`（若有 level 2、3 须按序逐一还原）。
    5. 清理：`rm -rf /home/chapter8`。
