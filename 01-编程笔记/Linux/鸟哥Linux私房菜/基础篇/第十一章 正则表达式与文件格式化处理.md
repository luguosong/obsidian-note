# 第十一章 正则表达式与文件格式化处理

> [!info] 关于本章
> 本章以鸟哥《Linux 私房菜 — 基础学习篇》第十一章为骨架，已更新至 **Rocky / AlmaLinux 9（RHEL 9 系）当前状态**，术语统一为大陆通行写法。关键现代化点：`egrep` 已自 GNU grep 3.8（2022）起被弃用，统一改用 `grep -E`；`ifconfig` 所属的 `net-tools` 在 RHEL 9 不再默认安装，示例改用 `ip addr`；正则与 `awk`/`sed`/`grep` 的核心用法本身仍是当前主流，未变。

正则表达式（Regular Expression, RE）是通过一些特殊字符的排列，用以"搜索/替换/删除"一行或多行文本字符串的一种**表示法**。它本身不是一个工具程序，而是字符串处理的标准依据——要按正则处理字符串，就得用支持正则的工具，如 `grep`、`sed`、`awk`、`vim`。

对系统管理员而言正则表达式尤其重要：系统每天产生的日志信息量极大，管理员通过正则把"有问题"的信息抽取出来分析，就能从千百行日志中迅速定位异常。许多服务器软件（如 Postfix 邮件服务器、各种日志分析工具）都依赖正则做过滤与匹配。

> [!warning] 正则表达式 ≠ 通配符
> 这是初学者最常混淆的两点：
> - **通配符（wildcard）** 是 bash 操作接口的功能，用于匹配**文件名**，如 `*.txt`、`?`、`[abc]`。
> - **正则表达式** 是字符串处理的表示方法，用于在**文件内容**里匹配字符串，如 `.*`、`.`、`[abc]`。
>
> 二者符号看似相似但语义完全不同：通配符中的 `*` 代表"0 到无穷多个任意字符"；正则中的 `*` 代表"重复前一个 RE 字符 0 到无穷多次"。学习本章时，请先暂时忘掉 bash 的通配符。

## 11.1 开始之前：什么是正则表达式

正则表达式就是处理字符串的方法，**以行为单位**进行字符串处理，借助一些特殊符号，可让用户轻易地完成"搜索/删除/替换"某特定字符串的工作。

举一个系统运维常见的例子：你发现系统开机时总出现一个关于 `mail` 的错误，而开机相关的单元都在 `/usr/lib/systemd/system/` 下——你想找出该目录下哪个文件含 `mail` 关键字。手工一个个打开上百个文件显然不现实，但只要一行命令就能完成：

```bash
grep 'mail' /usr/lib/systemd/system/*
```

`grep` 正是支持正则的工具之一。任何工具只要支持这种表示法，就能用于正则字符串处理（`vim`、`grep`、`awk`、`sed` 等）；而 `cp`、`ls` 等不支持正则，只能用 bash 自身的通配符。

> [!note] 基础正则 vs 扩展正则
> 按严谨度不同，正则分为**基础正则**（Basic Regular Expression, BRE）与**扩展正则**（Extended Regular Expression, ERE）。扩展正则多了群组处理，例如用 `|` 表示"或（or）"——一次匹配 `VBird` 或 `netman` 或 `lman`。扩展正则需借助 `(`、`|` 等字符。本章先讲基础，再讲扩展。

## 11.2 基础正则表达式

正则表达式的结果受字符排序相关的**区域设置（locale）**影响，因此先说明区域设置问题，再介绍最简单的字符串提取工具 `grep`，最后进入正则特殊字符的处理。

### 11.2.1 区域设置对正则表达式的影响

文件存储的只是 0/1，文字与数字都通过编码表转换而来。不同区域设置的编码顺序不同，会造成正则提取结果的差异。以英文大小写为例：

| 区域设置 | 编码顺序 |
|---|---|
| `LANG=C`（POSIX 传统） | `0 1 2 ... 9 A B C ... Z a b c ... z` |
| `LANG=zh_CN.UTF-8` | `0 1 2 ... 9 a A b B c C ... z Z`（大小写交替） |

> [!warning] `[A-Z]` 在 UTF-8 区域设置下可能误抓小写
> 若 `LANG=zh_CN.UTF-8`，正则 `[A-Z]` 不再只匹配大写——按编码顺序它会连带抓到 `b B c C ... z` 等小写字符。**解决办法**：要么用 `LC_ALL=C` 强制按字节顺序，要么改用更确定的 POSIX 字符类（见下表）。

POSIX 标准定义了一组与区域设置无关的特殊字符类（重点掌握前几个）：

| 字符类 | 含义 |
|---|---|
| `[:alnum:]` | 英文大小写字母与数字（`0-9 A-Z a-z`） |
| `[:alpha:]` | 任何英文大小写字母（`A-Z a-z`） |
| `[:upper:]` | 大写字母（`A-Z`） |
| `[:lower:]` | 小写字母（`a-z`） |
| `[:digit:]` | 数字（`0-9`） |
| `[:blank:]` | 空格与 `[Tab]` |
| `[:space:]` | 任何会产生空白的字符，包括空格、`[Tab]`、CR 等 |
| `[:punct:]` | 标点符号（`" ' ? ! ; : # $` 等） |
| `[:cntrl:]` | 控制字符（CR、LF、Tab、Del 等） |
| `[:graph:]` | 除空白外的所有可打印字符 |
| `[:print:]` | 任何可打印字符（含空格） |
| `[:xdigit:]` | 十六进制数字（`0-9 A-F a-f`） |

> [!tip] 写法注意：双层中括号
> `[:lower:]` 本身就是"字符集合"，要放进 `[...]` 里使用，因此写法是 `[[:lower:]]`（两层中括号），等价于 `[a-z]`。第一次见到两层中括号不要慌，分开看即可。

### 11.2.2 grep 的一些进阶选项

`grep` 最重要的功能就是字符串比对——以**整行**为单位，把符合需求的行打印出来。在 Rocky/AlmaLinux 9 中，`grep --color=auto` 已默认设在 alias 中，关键字会自动高亮。

```bash
grep [-A] [-B] [--color=auto] '搜索字符串' filename
```

| 选项 | 含义 |
|---|---|
| `-n` | 输出时加上行号 |
| `-v` | 反向选择（不匹配的行） |
| `-i` | 忽略大小写 |
| `-A n` | after，除该行外，后续 n 行也列出 |
| `-B n` | before，除该行外，前面 n 行也列出 |
| `--color=auto` | 匹配字符串着色（默认已开） |

```bash
# 例：从内核消息中找出含 qxl 的行，关键字着色并显示行号
dmesg | grep -n --color=auto 'qxl'

# 承上，关键行的前两行与后三行也一起列出，便于看上下文
dmesg | grep -n -A3 -B2 --color=auto 'qxl'
```

### 11.2.3 基础正则表达式练习

为便于练习，建议用一个固定的测试文件。原文配套文件为 `regular_express.txt`（22 行，部分行带 Windows 的 `\r\n` 换行符 `^M`，便于演示换行差异），可从 [linux.vbird.org](https://linux.vbird.org/linux_basic/0330regularex/regular_express.txt) 下载：

```bash
wget https://linux.vbird.org/linux_basic/0330regularex/regular_express.txt
```

练习前提：用 `export LC_ALL=C` 设置区域设置；`grep` 已带 `--color=auto`。

**例题一、搜索特定字符串**

```bash
# 搜索含 the 的行
grep -n 'the' regular_express.txt

# 反向：不含 the 的行
grep -vn 'the' regular_express.txt

# 不区分大小写搜 the
grep -in 'the' regular_express.txt
```

**例题二、用中括号 `[]` 搜集合字符**

`[]` 不论里面有几个字符，都仅代表**某一个**字符。

```bash
# 匹配 tast 或 test（t 后是 a 或 e）
grep -n 't[ae]st' regular_express.txt

# 匹配含 oo 的行
grep -n 'oo' regular_express.txt

# oo 前面不能是 g（[^] 反向选择）
grep -n '[^g]oo' regular_express.txt

# oo 前面不能是小写字母
grep -n '[^a-z]oo' regular_express.txt
# 等价于
grep -n '[^[:lower:]]oo' regular_express.txt

# 含数字的行
grep -n '[0-9]' regular_express.txt
# 等价于
grep -n '[[:digit:]]' regular_express.txt
```

> [!note] `[^g]oo` 匹配细节
> 第 18 行 `google is the best tools...` 中既有 `goo`（不要的）也有 `too`（要的），整行仍会被列出——只要该行存在某处匹配即整行命中。第 19 行 `gooooogle` 里 `go(ooo)oogle` 中间的 `ooo` 前面是 `o`，同样命中。

**例题三、行首与行尾 `^` `$`**

```bash
# 行首是 the
grep -n '^the' regular_express.txt

# 行首是小写字母
grep -n '^[a-z]' regular_express.txt
grep -n '^[[:lower:]]' regular_express.txt

# 行首不是英文字母
grep -n '^[^a-zA-Z]' regular_express.txt
```

> [!warning] `^` 在 `[]` 内外含义相反
> - `^word`：在 `[]` 之外，定位在**行首**。
> - `[^abc]`：在 `[]` 之内，表示**反向选择**（不要 a/b/c）。

```bash
# 行尾是小数点（. 有特殊含义，需用 \ 转义）
grep -n '\.$' regular_express.txt

# 找出空白行
grep -n '^$' regular_express.txt
```

> [!note] 为什么部分以 `.` 结尾的行没被 `\.$` 抓到？
> 测试文件第 5–9 行是 Windows 换行（`^M$`），行尾实际是 `.\r\n`，`.` 与 `$` 之间还隔着 `^M`，故 `\.$` 抓不到。用 `cat -A` 可看到这种差异。这是不同平台换行符带来的坑。

实战：把配置文件中的空白行和 `#` 开头的注释行都过滤掉，只看有效配置：

```bash
grep -v '^$' /etc/rsyslog.conf | grep -v '^#'
```

> [!tip] 不能用 `grep -v '#'` 直接去除所有 `#`
> 因为有些注释是写在配置项**同一行后面**（如 `key value  # 说明`），直接抓 `#` 会把有效配置一并删掉。只过滤"以 `#` 开头"的行才安全。

**例题四、任意一个字符 `.` 与重复字符 `*`**

| 符号 | 含义 |
|---|---|
| `.`（小数点） | **一定有一个**任意字符 |
| `*`（星号） | 重复**前一个 RE 字符** 0 到无穷多次 |

```bash
# g 与 d 之间必须恰好有两个字符（god、gd 不会命中）
grep -n 'g..d' regular_express.txt

# 至少两个 o（ooo* = oo 加上 0~∞ 个 o）
grep -n 'ooo*' regular_express.txt

# g 开头 g 结尾，中间至少一个 o（gog/goog/gooog...）
grep -n 'goo*g' regular_express.txt

# g 开头 g 结尾，中间任意（.* = 0~∞ 个任意字符）
grep -n 'g.*g' regular_express.txt
```

> [!note] `g*g` 为何抓出这么多行？
> `g*g` 表示"0 或多个 g 再接一个 g"，即匹配 `g`、`gg`、`ggg`……因此只要该行**含至少一个 g** 就命中。想要"g 开头 g 结尾、中间任意"应写 `g.*g`。`.*` 是最常用的"任意字符串"通配形式。

```bash
# 含任意数字（[0-9] 一个数字；[0-9]* 0~∞ 个数字）
grep -n '[0-9][0-9]*' regular_express.txt
```

**例题五、限定连续范围 `{}`**

`{}` 用于限定前一个 RE 字符的重复次数区间。基础正则下 `{` 需转义为 `\{`（扩展正则下 `{` 不需转义）。

```bash
# 恰好 2 个 o
grep -n 'o\{2\}' regular_express.txt

# g 后接 2~5 个 o 再接 g
grep -n 'go\{2,5\}g' regular_express.txt

# g 后接 2 个以上 o 再接 g
grep -n 'go\{2,\}g' regular_express.txt
```

`{n,m}` 三种形式：`\{n\}` 恰好 n 个；`\{n,m\}` n 到 m 个；`\{n,\}` 至少 n 个。

### 11.2.4 基础正则表达式字符汇总

| RE 字符 | 含义与示例 |
|---|---|
| `^word` | 待搜字符串在行首。例：`grep -n '^#' file` |
| `word$` | 待搜字符串在行尾。例：`grep -n '!$' file` |
| `.` | 一定有一个任意字符。例：`grep -n 'e.e' file` 匹配 `eve`/`eae`/`e e`，不匹配 `ee` |
| `\` | 转义字符，去除特殊符号的特殊意义。例：`grep -n \' file` 搜单引号 |
| `*` | 重复前一个 RE 字符 0 到无穷多次。例：`grep -n 'ess*' file` 匹配 `es`/`ess`/`esss`（注意 `*` 前必须紧跟一个 RE 字符，任意串写作 `.*`） |
| `[list]` | 字符集合，仅代表一个待搜字符。例：`grep -n 'g[ld]' file` 匹配 `gl` 或 `gd` |
| `[n1-n2]` | 字符范围集合，`-` 代表编码连续区间。例：`[A-Z]`，依赖区域设置正确 |
| `[^list]` | 反向选择集合。例：`grep -n 'oo[^t]' file` 匹配 `oog`/`ood`，不匹配 `oot`。注意 `[^A-Z]` 是"非大写"，几乎所有行都含非大写字符，会全被列出 |
| `\{n,m\}` | 连续 n 到 m 个前一个 RE 字符；`\{n\}` 恰好 n 个；`\{n,\}` 至少 n 个。例：`grep -n 'go\{2,3\}g' file` |

> [!warning] 再次强调：正则 `*` ≠ 通配符 `*`
> - 通配符：`ls -l a*` 表示以 `a` 开头的任意文件名（`*` = 0~∞ 任意字符）。
> - 正则：`ls \| grep -n '^a.*'` 才是同样语义。两者不可混用。

例题：用 `ls -l` 配合 `grep` 找出 `/etc/` 下的符号链接（`ls -l` 列符号链接时行首是 `l`）：

```bash
ls -l /etc | grep '^l'
```

### 11.2.5 sed 工具

`sed` 是一个管道命令，可分析标准输入，对数据做**替换、删除、新增、提取特定行**等操作，常用于 shell 脚本中的批量文本处理。

```bash
sed [-nefr] [动作]
```

| 选项 | 含义 |
|---|---|
| `-n` | 安静模式（silent），只输出经 sed 处理的行 |
| `-e` | 直接在命令行模式进行 sed 动作编辑（多动作时用） |
| `-f filename` | 从文件读取 sed 动作 |
| `-r` / `-E` | 使用扩展正则语法（默认是基础正则） |
| `-i` | 直接修改读取的文件内容（危险，原文件被改） |

动作格式 `[n1[,n2]]function`，n1/n2 为行号（可选，`$` 代表最后一行）。function 有：

| function | 含义 |
|---|---|
| `a` | 追加（append），字符串出现在当前行的**下一行** |
| `i` | 插入（insert），字符串出现在当前行的**上一行** |
| `c` | 替换（change），字符串替换 n1~n2 之间的行 |
| `d` | 删除（delete） |
| `p` | 打印（print），通常与 `-n` 合用 |
| `s` | 替换（substitute），可搭配正则，如 `s/old/new/g` |

**以行为单位的新增/删除**

```bash
# 列出 /etc/passwd 并加行号，删除第 2~5 行
nl /etc/passwd | sed '2,5d'

# 仅删除第 2 行
nl /etc/passwd | sed '2d'

# 删除第 3 行到最后一行
nl /etc/passwd | sed '3,$d'

# 在第 2 行后追加 'drink tea'（a）
nl /etc/passwd | sed '2a drink tea'

# 在第 2 行前插入（i）
nl /etc/passwd | sed '2i drink tea'

# 追加多行：行尾用反斜线续行
nl /etc/passwd | sed '2a Drink tea or ......\
drink beer ?'
```

> [!note] sed 动作必须用单引号括住
> sed 后接的动作请务必用 `''` 两个单引号括住；多行新增时每行末尾需用反斜线 `\` 续行。

**以行为单位的替换与显示**

```bash
# 将第 2~5 行整体替换为 'No 2-5 number'
nl /etc/passwd | sed '2,5c No 2-5 number'

# 仅列出第 5~7 行（注意 -n 与 p 必须配合，否则会重复输出）
nl /etc/passwd | sed -n '5,7p'
```

**部分数据的搜索并替换**

```bash
sed 's/要被替换的字符串/新的字符串/g'
```

实战：从 `ip addr` 输出中提取 `eth0` 的 IPv4 地址（RHEL 9 默认无 `ifconfig`，改用 `ip` 命令；输出格式为 `inet 192.168.1.100/24 ...`）：

```bash
# 步骤一：观察原始信息
ip addr show eth0

# 步骤二：用 grep 抓出含 inet 的那一行
ip addr show eth0 | grep 'inet '

# 步骤三：删掉 inet 及其前面的部分
ip addr show eth0 | grep 'inet ' | sed 's/^.*inet //g'
# → 192.168.1.100/24 brd 192.168.1.255 scope global ...

# 步骤四：再删掉 / 及其后面的部分
ip addr show eth0 | grep 'inet ' | sed 's/^.*inet //g' | sed 's/\/.*$//g'
# → 192.168.1.100
```

> [!tip] 构造 sed 命令的步骤
> 先观察原始输出 → 一层一层试做 → 不对就改 → 成功后再往下接。正则是逐段逼近目标的，不要指望一步到位。

实战：从 `/etc/man_db.conf` 中取出含 `MAN` 的行，去掉行内 `#` 注释及注释产生的空行、空白行：

```bash
cat /etc/man_db.conf | grep 'MAN' | sed 's/#.*$//g' | sed '/^$/d'
```

**直接修改文件内容（危险）**

`sed -i` 会直接改写原文件，无需管道或重定向，常用于批量处理大文件（百万行级别的文件用 `vim` 打开很慢，`sed -i` 几乎瞬秒）。

```bash
# 将文件中行尾的 . 替换为 !
sed -i 's/\.$/\!/g' regular_express.txt

# 在文件最后一行追加 '# This is a test'
sed -i '$a # This is a test' regular_express.txt
```

> [!warning] 不要拿系统配置文件测试 `sed -i`
> `-i` 直接改原文件且不可撤销。务必先备份或先在小测试文件上验证动作正确，再对正式文件操作。

## 11.3 扩展正则表达式

掌握基础正则后，扩展正则能让命令更简洁。例如"去除空白行和 `#` 开头的行"，基础正则要用两次管道：

```bash
grep -v '^$' regular_express.txt | grep -v '^#'
```

扩展正则可用群组 `|` 一次完成：

```bash
grep -E -v '^$|^#' regular_express.txt
```

> [!info] `egrep` 已被弃用
> 历史上扩展正则用 `egrep`，但自 **GNU grep 3.8（2022 年 9 月）** 起，`egrep`/`fgrep` 被正式弃用，运行时会打印警告，未来版本将移除。**统一改用 `grep -E`（扩展）和 `grep -F`（固定字符串）**。本文后续一律用 `grep -E`。

扩展正则的特殊字符（用法示意均基于 `regular_express.txt`）：

| RE 字符 | 含义与示例 |
|---|---|
| `+` | 重复**一个或以上**的前一个 RE 字符。例：`grep -E -n 'go+d' file` 匹配 `god`/`good`/`goood`... |
| `?` | **零个或一个**前一个 RE 字符。例：`grep -E -n 'go?d' file` 匹配 `gd`/`god` |
| `\|` | 用"或"方式找多个字符串。例：`grep -E -n 'gd\|good\|dog' file` |
| `()` | 群组。例：`grep -E -n 'g(la\|oo)d' file` 匹配 `glad` 或 `good` |
| `()+` | 多个重复群组。例：`echo 'AxyzxyzxyzxyzC' \| grep -E 'A(xyz)+C'` 匹配开头 A、结尾 C、中间一个以上 `xyz` |

> [!note] `go*d`、`go+d`、`go?d` 的关系
> - `go*d`：0~∞ 个 o → `gd`/`god`/`good`...
> - `go+d`：1~∞ 个 o → `god`/`good`...（不含 `gd`）
> - `go?d`：0~1 个 o → `gd`/`god`
>
> `go*d` 的结果集 = `go+d` ∪ `go?d`。

> [!warning] `!` 在正则中不是特殊字符
> 想搜含 `!` 或 `>` 的行直接写：`grep -n '[!>]' file`。反向选择的陷阱题：`'[!a-z]'` 是**错的**（`!` 在 `[]` 内无特殊含义），正确写法是 `'[^a-z]'`。

## 11.4 文件的格式化与相关处理

数据流重定向配合 `printf` 与 `awk`，可以让信息按想要的版式输出；`diff`/`cmp`/`patch` 用于文件比对与打补丁。

### 11.4.1 格式化打印：printf

`printf` 用于把数据按指定格式输出，支持特殊字符与 C 语言风格的变量格式。

```bash
printf '打印格式' 实际内容
```

**特殊字符**

| 符号 | 含义 |
|---|---|
| `\a` | 警告声 |
| `\b` | 退格（backspace） |
| `\f` | 清屏（form feed） |
| `\n` | 换行 |
| `\r` | Enter（回车） |
| `\t` | 水平 `[Tab]` |
| `\v` | 垂直 `[Tab]` |
| `\xNN` | 两位十六进制数字转字符（ASCII） |

**变量格式**

| 格式 | 含义 |
|---|---|
| `%ns` | n 是数字，字符串，占 n 个字符宽 |
| `%ni` | n 是数字，整数，占 n 位 |
| `%N.nf` | 浮点数，总宽 N、小数 n 位。如 `%8.2f` 表示总宽 8（含小数点与小数位） |

准备一份 `printf.txt`（每列用 `[Tab]` 或空格分隔）：

```text
Name     Chinese   English   Math    Average
DmTsai        80        60     92      77.33
VBird         75        55     80      70.00
Ken           60        90     70      73.33
```

`printf` 不是管道命令，须用 `$(...)` 把文件内容取出喂给它：

```bash
# 例一：用 [tab] 分隔列出（每列长度不固定，会错位）
printf '%s\t %s\t %s\t %s\t %s\t \n' $(cat printf.txt)

# 例二：固定列宽，表头之外按 字符串/整数/浮点 对齐
printf '%10s %5i %5i %5i %8.2f \n' $(cat printf.txt | grep -v Name)
#     DmTsai    80    60    92    77.33
#      VBird    75    55    80    70.00
#        Ken    60    90    70    73.33

# 例三：十六进制 45 对应 ASCII 字符
printf '\x45\n'   # 输出 E
```

`%8.2f` 的字段宽度拆解：总 8 字符 = 整数部分 5 + 小数点 1 + 小数部分 2。`printf` 在 `awk` 的格式化输出和 C 语言里也会用到。

### 11.4.2 awk：好用的数据处理工具

`sed` 倾向于整行处理，`awk` 倾向于把一行**按字段**切分处理，适合小型数据表的加工。基本形式：

```bash
awk '条件类型1{动作1} 条件类型2{动作2} ...' filename
```

`awk` 可处理后接文件，也可读前一个命令的标准输出。默认**字段分隔符为空格或 `[Tab]`**。

**字段变量**

| 变量 | 含义 |
|---|---|
| `$0` | 当前整行 |
| `$1`, `$2`... | 第 1、2... 个字段 |
| `NF` | 当前行拥有的字段总数 |
| `NR` | 当前处理的是第几行 |
| `FS` | 当前分隔字符，默认空格 |

```bash
# 从 last 输出取账号与 IP，用 [tab] 隔开（$1 是账号，$3 是 IP）
last -n 5 | awk '{print $1 "\t" $3}'

# 同时显示账号、行号、字段数
last -n 5 | awk '{print $1 "\t lines: " NR "\t columns: " NF}'
```

> [!tip] `awk` 动作用单引号，内部文本用双引号
> `awk` 整个动作用单引号 `'...'` 括住，单引号内若要打印文本（含 `printf` 的格式），需用**双引号**定义字符串。`NR`、`NF` 等内置变量用大写、不加 `$`。

**awk 的逻辑运算**

| 运算符 | 含义 |
|---|---|
| `>` / `<` | 大于 / 小于 |
| `>=` / `<=` | 大于等于 / 小于等于 |
| `==` / `!=` | 等于 / 不等于 |

> [!note] `=` 与 `==`
> `==` 是逻辑判断（相等），`=` 是变量赋值。`awk` 判断相等必须用 `==`。

`/etc/passwd` 以冒号 `:` 分隔字段，第 1 字段是账号、第 3 字段是 UID。查找 UID 小于 10 的账号：

```bash
# FS 在第一行就生效：用 BEGIN 预先设置
cat /etc/passwd | awk 'BEGIN {FS=":"} $3 < 10 {print $1 "\t " $3}'
```

> [!tip] 为何第一行常"没按预期分隔"？
> 若 `{FS=":"}` 写在动作里，第一行读入时仍按默认空格分隔，FS 要到第二行才生效。用 `BEGIN {FS=":"}` 在处理前预先设置，所有行就都正确。对应的还有 `END` 块，在所有行处理完后执行。

**awk 的计算与格式化输出**

对工资表 `pay.txt`（第 1 行表头、第 2 行起是每人三次工资）求总额并格式化：

```bash
cat pay.txt | awk 'NR==1{printf "%10s %10s %10s %10s %10s\n",$1,$2,$3,$4,"Total"}
NR>=2{total = $2 + $3 + $4
printf "%10s %10d %10d %10d %10.2f\n", $1, $2, $3, $4, total}'
```

> [!note] awk 语法要点
> - 多个动作语句用分号 `;` 或换行分隔。
> - 逻辑相等用 `==`。
> - `printf` 格式串末尾务必加 `\n` 才换行。
> - `awk` 内部变量直接用，不加 `$`（`$1`、`$2` 是字段，不是变量）。
> - 动作 `{}` 内还支持 `if (条件)` 语法，与上面的 `条件{动作}` 写法等价。

`awk` 还能做循环等更复杂的处理，属于进阶内容，本文不再展开。

### 11.4.3 文件比对工具

最常用的是 `diff`（以行为单位，比对纯文本文件的新旧版本），辅以 `cmp`（以字节为单位，可比对二进制），以及由 `diff` 生成补丁文件再用 `patch` 升级。

**diff**

```bash
diff [-bBi] from-file to-file
```

| 选项 | 含义 |
|---|---|
| `-b` | 忽略一行中多个空白的差异 |
| `-B` | 忽略空白行的差异 |
| `-i` | 忽略大小写 |

`from-file` 或 `to-file` 可用 `-` 代表标准输入。

先造一对测试文件：

```bash
mkdir -p /tmp/testpw && cd /tmp/testpw
cp /etc/passwd passwd.old
cat /etc/passwd | sed -e '4d' -e '6c no six line' > passwd.new
# sed 接两个以上动作时，每个动作前都要加 -e
```

比对结果：

```bash
diff passwd.old passwd.new
4d3              # 左边第 4 行被删（基准是右边第 3 行）
< adm:x:3:4:adm:/var/adm:/sbin/nologin
6c5              # 左边第 6 行被替换成右边第 5 行
< sync:x:5:0:sync:/sbin:/bin/sync
---
> no six line
```

`diff` 也能比对目录：比较两个目录下**同名文件**的内容差异，并列出仅在一方存在的文件。

> [!info] systemd 时代的运行级别目录
> 原文用 `diff /etc/rc0.d/ /etc/rc5.d/` 演示目录比对，那两个目录是 SysV init 时代的运行级别脚本目录。**RHEL 9 已全面用 systemd**，对应概念是 `runlevel0.target`（关机）、`graphical.target`（原运行级别 5）等 target 单元；`/etc/rc.d/rc0.d`、`/etc/rc.d/rc5.d` 等 SysV 兼容目录仍以符号链接形式保留但大多为空。`diff` 比对目录的**功能**本身仍然有效，只是这个具体例子已不具典型意义。

**cmp**

以**字节**为单位比对，默认只输出第一个不同点；可比对二进制文件。

```bash
cmp [-l] file1 file2
```

```bash
cmp passwd.old passwd.new
# passwd.old passwd.new differ: char 106, line 4
```

`-l` 列出所有不同点的字节位置。

**patch**

`patch` 与 `diff` 配合使用：先用 `diff` 生成补丁文件，再用 `patch` 把旧文件升级到新版本。

```bash
# 制作补丁文件（常用 -Naur 组合选项）
diff -Naur passwd.old passwd.new > passwd.patch
```

补丁文件内容形如：

```text
--- passwd.old  2015-07-14 22:37:43.322535054 +0800
+++ passwd.new  2015-07-14 22:38:03.010535054 +0800
@@ -1,9 +1,8 @@
 root:x:0:0:root:/root:/bin/bash
 bin:x:1:1:bin:/bin:/sbin/nologin
 daemon:x:2:2:daemon:/sbin:/sbin/nologin
-adm:x:3:4:adm:/var/adm:/sbin/nologin     # 删除
 lp:x:4:7:lp:/var/spool/lpd:/sbin/nologin
-sync:x:5:0:sync:/sbin:/bin/sync          # 删除
+no six line                              # 新增
 ...
```

在 Rocky/AlmaLinux 9 上，`patch` 命令由 `patch` 软件包提供，最小化安装可能未带，用 `dnf` 安装：

```bash
sudo dnf install patch
```

打补丁与还原：

```bash
# 更新（把 passwd.old 改成 passwd.new 的内容）
patch -p0 < passwd.patch

# 还原（把新文件还原成旧版本）
patch -R -p0 < passwd.patch
```

`-pN` 表示去掉补丁文件里路径的前 N 层目录；同目录比对时用 `-p0`。更详细的 `patch` 用法见第二十一章（源码编译与 Tarball）。

### 11.4.4 文件打印准备：pr

`pr` 用于给纯文本文件加上文件时间、文件名、页码等标头，便于打印。

```bash
pr /etc/man_db.conf

# 输出形如：
# 2014-06-10 05:35                 /etc/man_db.conf                 Page 1
# ...
```

`pr` 的参数众多，一般用最简单的默认形式即可；详细选项请参考 `man pr`。

## 11.5 重点回顾

- 正则表达式以**行为单位**进行字符串处理，借助特殊符号完成搜索/删除/替换；
- 只要工具支持正则，就能用于正则字符串处理；**正则 ≠ 通配符**（通配符是 bash 匹配文件名的功能，`*` 语义不同）；
- 不同区域设置（locale）下 `[A-Z]` 等范围可能误抓，可用 `LC_ALL=C` 或 POSIX 字符类 `[:upper:]` 规避；
- 基础正则字符：`*`、`.`、`[]`、`[-]`、`[^]`、`^`、`$`、`\{\}` 等；
- 扩展正则字符：`+`、`?`、`|`、`()`、`()+`；**`egrep` 已被弃用，统一用 `grep -E`**；
- `grep`/`sed`/`vim` 是最常用的支持正则的工具；
- `printf` 用特殊符号与 `%ns`/`%ni`/`%N.nf` 等格式做格式化输出；
- `awk` 以**字段**为单位处理，配合 `NR`/`NF`/`FS` 与 `BEGIN`/`END` 做条件过滤、计算与格式化；
- 文件比对用 `diff`（纯文本、行级）与 `cmp`（二进制、字节级）；
- `patch` 可将旧版数据更新到新版（补丁文件由 `diff` 生成）。

## 11.6 本章习题

**情境模拟一：用 `grep` 搜索含星号 `*` 的文件并配合管道处理大量文件**

要点：单引号内的 `*` 是正则字符（要搜"星号"需用 `\*` 转义），而 `find`/shell 里的 `*` 是通配符。

```bash
# 在 /etc 下找含 * 的文件内容（单引号内是正则、* 需转义；/etc/* 是通配符）
grep '\*' /etc/* 2>/dev/null

# 递归连子目录一起搜
grep '\*' $(find /etc -type f) 2>/dev/null

# 只列文件名
grep -l '\*' $(find /etc -type f) 2>/dev/null
```

全系统（`/`）搜索时，`$(find ...)` 展开后参数列表会超限报错：

```bash
grep '\*' $(find / -type f 2>/dev/null)
# -bash: /usr/bin/grep: Argument list too long
```

此时用管道配合 `xargs`，每次只传若干个文件名给 `grep`：

```bash
find / -type f 2>/dev/null | xargs -n 10 grep '\*'
find / -type f 2>/dev/null | xargs -n 10 grep -l '\*'   # 只列文件名
```

**情境模拟二：用 `ip`、`sed`、`awk` 配合做一个 `myip` 命令与 `MYIP` 变量**

> [!info] 现代化说明
> 原文用 `ifconfig eth0` 提取 IP，但 RHEL 9 默认不装 `net-tools`（无 `ifconfig`）。下例改用 `ip addr`。

```bash
# 1. 提取 eth0 的 IPv4 地址
ip addr show eth0 | grep 'inet ' | sed 's/^.*inet //g' | sed 's/\/.*$//g'

# 2. 设为 alias
alias myip="ip addr show eth0 | grep 'inet ' | sed 's/^.*inet //g' | sed 's/\/.*$//g'"

# 3. 存入变量
MYIP=$(myip)
```

若要每次登录都生效，把 alias 与 `MYIP=` 两行写入 `~/.bashrc`。

**简答题**

1. 在 `/etc` 下找出含 `X`、`Y`、`Z` 任一字符的行：
   ```bash
   grep '[XYZ]' /etc/*
   grep '[XYZ]' $(find /etc -type f)
   ```

2. 处理 `/etc/kdump.conf`：去 `#` 注释行 → 去空白行 → 取开头为英文字母的行 → 统计行数：
   ```bash
   grep -v '^#' /etc/kdump.conf | grep -v '^$' | grep '^[[:alpha:]]' | wc -l
   ```
