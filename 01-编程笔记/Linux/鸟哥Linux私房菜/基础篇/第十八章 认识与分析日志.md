# 第十八章 认识与分析日志

> [!info] 关于本章
> 本章以鸟哥《Linux 私房菜 — 基础学习篇》第十八章为骨架，已将原基于 CentOS 7 的内容更新至 **Rocky/AlmaLinux 9 / RHEL 9** 当前状态，术语统一为大陆通行写法。关键现代化点：`rsyslog` 仍是默认持久化日志服务；`systemd-journald` / `journalctl` 已成为查询日志的主流方式；包管理用 `dnf`（替代 `yum`）；端口查询用 `ss`（替代 `netstat`）。

当 Linux 系统出现问题时，第一手的排查依据就是**日志（log）**。日志记录系统在何时、何地（来源 IP）、哪个服务、做了什么动作、产生了什么消息——包括用户身份、故障线索等。善用日志能在第一时间发现错误并定位原因。

日志量极大，人工逐行阅读不现实，通常借助 `shell` 脚本或专用工具（如 `journalctl`、`logwatch`）处理。

## 18.1 什么是日志

**日志**记录系统活动信息：何时、何地（来源 IP）、何人（服务名称）、做了什么动作。换言之，记录系统在什么时候由哪个进程做了什么行为、发生了什么事件。

### 18.1.1 常见日志文件

Linux 主机后台同时运行着大量守护进程（daemon），这些进程产生的消息最终会被记录到日志中。日志文件通常仅 `root` 可读。常见日志文件（Rocky/AlmaLinux 9 与传统 RHEL 系一致）：

| 文件 | 内容 |
|---|---|
| `/var/log/boot.log` | 开机时系统启动各服务的过程信息（仅本次开机） |
| `/var/log/cron` | `cron` / `at` 等定时任务的执行记录 |
| `/var/log/dmesg` | 开机时内核检测硬件的过程信息（也可用 `dmesg` 命令查看） |
| `/var/log/lastlog` | 各账号最近一次登录信息（`lastlog` 命令读取） |
| `/var/log/maillog` 或 `/var/log/mail/*` | 邮件服务（postfix、dovecot）的往来记录 |
| `/var/log/messages` | 系统绝大多数错误与重要信息——出错时必查 |
| `/var/log/secure` | 所有涉及账号密码认证的程序（`login`、`gdm`、`su`、`sudo`、`ssh` 等）的登录信息 |
| `/var/log/wtmp`、`/var/log/faillog` | 成功登录（`wtmp`）与失败登录（`faillog`）记录；`last` 命令读取 `wtmp` |
| `/var/log/httpd/*`、`/var/log/samba/*` 等 | 各网络服务各自的日志目录 |

> [!tip] 日志的重要性
> 通过 (1) 查看屏幕错误消息 + (2) 查阅日志，几乎可以解决大部分 Linux 问题。系统被入侵或被利用攻击他人时，日志也是追查的关键证据。

### 18.1.2 日志相关服务与程序

日志的产生与管理涉及两类机制：

- **应用程序自定义写入**：如 Apache（httpd）自行管理日志格式与文件；
- **统一日志服务**：由发行版提供的日志管理服务集中分类存储，Linux 通用 `rsyslog.service`。

此外，`systemd` 自带 `systemd-journald.service`，以二进制形式记录所有由 systemd 启动的服务的消息。

| 组件 | 作用 |
|---|---|
| `systemd-journald.service` | 最上游的消息收受者，由 systemd 提供；记录在内存中（`/run/log/journal/`），重启后丢失 |
| `rsyslog.service` | 将各类服务消息按规则分类写入 `/var/log/` 下的持久化文件 |
| `logrotate` | 定期对日志文件进行**轮替**（重命名旧文件、创建新文件、过期删除） |

> [!note] 为什么需要 logrotate
> 日志持续增长会占用大量磁盘空间，大文件读写效率也差。`logrotate` 将旧日志改名、新建空日志继续记录，过一段时间后自动删除过旧备份，从而控制日志总量。

### 18.1.3 日志内容的一般格式

每条日志通常包含四项信息：

- **日期与时间**
- **主机名**（日志可集中收集多台主机的消息，故需标明来源主机）
- **服务/程序名称**（如 `systemd`、`CROND`、`su`、`sshd`）
- **消息正文**

以 `/var/log/secure` 为例：

```text
Aug 18 23:45:17 study sshd[18913]: Accepted password for dmtsai from 192.168.1.200 port 41524 ssh2
Aug 18 23:50:25 study sudo: dmtsai : TTY=pts/0 ; PWD=/home/dmtsai ; USER=root ; COMMAND=/bin/su -
|--日期/时间---|--主机-|----服务/程序------|-----------消息正文------>
```

> [!tip] 排查服务启动失败的经验做法
> 启动某服务失败后，立即查看日志：(1) 按当前时间过滤第一字段；(2) 按服务名匹配第三字段；(3) 仔细阅读第四字段找出错误原因。

## 18.2 rsyslog.service：记录日志的服务

确认 `rsyslog` 是否运行：

```bash
# 查看进程
ps aux | grep rsyslog
# 查看服务状态
systemctl status rsyslog.service
```

### 18.2.1 主配置文件 /etc/rsyslog.conf

`rsyslogd` 按"严重等级"将消息分类写入不同文件，规则由 `/etc/rsyslog.conf`（以及 `/etc/rsyslog.d/*.conf`）定义。语法：

```text
服务名称.[=!]消息等级    记录目标（文件/设备/主机）
```

例如 `mail.info  /var/log/maillog_info` 表示：将 mail 服务产生的大于等于 info 等级的消息写入 `/var/log/maillog_info`。

**服务名称（facility）**

`rsyslogd` 依据 syslog 规范将消息分类，主要 facility：

| 序号 | facility | 说明 |
|---|---|---|
| 0 | kern | 内核产生的消息（硬件检测、内核功能） |
| 1 | user | 用户层级产生的信息（如 `logger` 命令） |
| 2 | mail | 邮件收发相关 |
| 3 | daemon | 系统守护进程（如 systemd） |
| 4 | auth | 认证/授权（login、ssh、su 等需要账号密码） |
| 5 | syslog | rsyslogd 自身产生的信息 |
| 6 | lpr | 打印相关 |
| 7 | news | 新闻组服务器 |
| 8 | uucp | Unix to Unix Copy Protocol（早期系统间数据交换） |
| 9 | cron | 定时任务（cron/at） |
| 10 | authpriv | 类似 auth，但记录更多账号私密信息（含 pam 模块） |
| 11 | ftp | FTP 协议相关 |
| 16–23 | local0–local7 | 保留给本机用户使用 |

软件开发者通过调用上述 facility（如 `LOG_MAIL`）记录消息——`postfix`、`dovecot` 都使用 `mail` facility。

![[vbird-704eb2adca992776.gif]]
*图：syslog facility 与软件调用的关系*

**消息等级（severity）**

从不严重到最严重：

| 数值 | 等级 | 说明 |
|---|---|---|
| 7 | debug | 调试信息 |
| 6 | info | 一般说明信息 |
| 5 | notice | 正常但值得注意 |
| 4 | warning（warn） | 警告，可能有问题但不影响运行 |
| 3 | err（error） | 错误，如配置错误导致服务无法启动 |
| 2 | crit | 临界（critical），严重错误 |
| 1 | alert | 警报，比 crit 更严重 |
| 0 | emerg（panic） | 系统几乎崩溃（硬件故障、内核无法运行） |

另有特殊等级 `none`（不记录该服务消息）。

**连接符号 `.[=!]`**

| 符号 | 含义 |
|---|---|
| `.` | 记录**大于等于**该等级（最常用） |
| `.=` | 仅记录该等级 |
| `.!` | 反向，忽略大于等于该等级（即只记录低于该等级） |

**记录目标**

- 文件绝对路径（多为 `/var/log/...`）
- 设备（如打印机 `/dev/lp0`）
- 用户名（显示给指定在线用户）
- 远程主机（`@host` 用 UDP，`@@host` 用 TCP）
- `*`：广播给当前所有在线用户（类似 `wall`）

> [!note] syslog / rsyslogd / rsyslog.service 的区别
> - **syslog**：Linux 内核提供的日志设计规范（定义在 `syslog.h`，可用 `man 3 syslog` 查询）；
> - **rsyslogd**：实现该规范、负责实际消息分类的守护进程（daemon）；
> - **rsyslog.service**：rsyslogd 的 systemd 服务单元（用于统一管理）。

**配置示例**

```text
# 例1：mail 的 info 及以上等级写入指定文件
mail.info                         /var/log/maillog

# 例2：news 与 cron 全部消息写入同一文件，警告等级单独写入另一文件
news.*;cron.*                     /var/log/cronnews
news.=warn;cron.=warn             /var/log/cronnews.warn

# 例3：messages 记录所有信息，但排除 cron、mail、news
*.*;news,cron,mail.none           /var/log/messages
# 等价写法（用 ; 分隔时需重复写等级）
*.*;news.none;cron.none;mail.none /var/log/messages
```

**Rocky/AlmaLinux 9 默认 rsyslog 规则**

RHEL 9 系发行版的 `/etc/rsyslog.conf` 默认规则与下表基本一致（网络接收模块默认注释，并通过 `$IncludeConfig /etc/rsyslog.d/*.conf` 引入额外规则）：

```text
*.info;mail.none;authpriv.none;cron.none   /var/log/messages
authpriv.*                                 /var/log/secure
mail.*                                    -/var/log/maillog
cron.*                                     /var/log/cron
*.emerg                                    :omusrmsg:*
uucp,news.crit                             /var/log/spooler
local7.*                                   /var/log/boot.log
```

> [!note] 文件名前的减号 `-`
> `-/var/log/maillog` 中的减号表示**异步写入**：消息先缓存到内存，达到一定量后再批量刷盘，可提升性能；代价是异常宕机可能丢失部分未刷盘的日志。

**自行新增日志文件**

如让所有 info 及以上消息额外写入 `/var/log/admin.log`：

```bash
# 1. 编辑配置（建议附带注释说明）
vim /etc/rsyslog.conf
# 加入一行：
# *.info      /var/log/admin.log

# 2. 重启服务
systemctl restart rsyslog.service

# 3. 验证文件已生成
ll /var/log/admin.log
```

### 18.2.2 日志的安全性设置

日志一旦被删除或篡改，入侵证据就会消失。可用文件**仅追加**属性保护日志：

```bash
# 设置仅追加（不能删除、不能修改已有内容）
chattr +a /var/log/admin.log
lsattr /var/log/admin.log
# -----a---------- /var/log/admin.log

# 取消（logrotate 轮替前必须先取消）
chattr -a /var/log/admin.log
```

> [!warning] 不要用编辑器打开日志后 :wq 保存
> `rsyslogd` 一旦发现日志文件被外部编辑过，就**不再写入**该文件。若不慎用 `vim` 打开并 `:wq` 保存了日志，必须 `systemctl restart rsyslog.service` 才能恢复写入。给日志加上 `chattr +a` 可避免误修改（无法 `:wq`）。

> [!note] `+a` 属性的局限
> `+a` 只能防误删/误改，无法抵御已获得 root 权限的攻击者（root 可 `chattr -a` 解除）。务必保证 root 密码强度。另外，`logrotate` 轮替会重命名文件，因此轮替前必须先 `chattr -a`、轮替后再 `chattr +a`（见 [18.3.1](#1831-logrotate-的配置文件) 中的 prerotate/postrotate）。

### 18.2.3 日志服务器

将多台主机的日志集中收集到一台**日志服务器**，可统一管理。`rsyslogd` 原生支持此功能，默认监听 UDP/TCP 的 514 端口（配置文件中默认注释，需手动启用）。

![[vbird-382df1f80323c784.webp]]
*图：日志服务器的架构*

**服务器端**（修改 `/etc/rsyslog.conf`，取消注释以启用 TCP 接收；UDP 同理）：

```text
$ModLoad imtcp
$InputTCPServerRun 514
```

```bash
systemctl restart rsyslog.service
# 验证 514 端口已监听
ss -ltnp | grep 514
```

**客户端**（将所有日志转发到服务器 `192.168.1.100`）：

```text
# TCP（两个 @@）
*.*       @@192.168.1.100
# UDP（一个 @）
# *.*     @192.168.1.100
```

```bash
systemctl restart rsyslog.service
```

> [!tip] TCP vs UDP
> 网络稳定、追求性能用 UDP；追求传输可靠（不丢日志）用 TCP。客户端语法必须与服务端启用的协议匹配。

## 18.3 日志的轮替（logrotate）

`logrotate` 用于自动化管理日志容量：将旧日志改名、创建新空日志、过期删除旧备份。它本身不是守护进程，而是通过 `cron` 定时触发（RHEL 9 上由 `/etc/cron.daily/logrotate` 每日执行）。

### 18.3.1 logrotate 的配置文件

| 文件/目录 | 作用 |
|---|---|
| `/etc/logrotate.conf` | 主配置，定义默认轮替策略 |
| `/etc/logrotate.d/` | 子配置目录，每个服务一个文件，覆盖或细化默认策略 |

轮替工作流程：第一次执行后，原 `messages` 变为 `messages.1`（或带日期后缀 `messages-20260805`），同时新建空 `messages` 继续 recording；第二次执行后 `messages.1` 变为 `messages.2`、`messages` 变为 `messages.1`……达到保留份数上限时最旧的备份被删除。

![[vbird-f4258e0312dac302.gif]]
*图：logrotate 轮替结果示意*

**默认策略（`/etc/logrotate.conf`）**

```text
weekly              # 每周轮替一次
rotate 4            # 保留 4 个备份
create              # 轮替后创建新空文件
dateext             # 备份文件名带日期后缀（如 messages-20260805）
#compress           # 是否压缩（默认注释，需要时启用）
include /etc/logrotate.d
```

**单文件配置语法**

```text
日志文件的绝对路径 ... {
    个别参数（monthly / compress 等）
    prerotate
        轮替前执行的命令
    endscript
    postrotate
        轮替后执行的命令
    endscript
}
```

**典型示例：`/etc/logrotate.d/syslog`**

```text
/var/log/cron
/var/log/maillog
/var/log/messages
/var/log/secure
/var/log/spooler
{
    sharedscripts
    postrotate
        /bin/kill -HUP `cat /var/run/syslogd.pid 2> /dev/null` 2> /dev/null || true
    endscript
}
```

> [!note] `postrotate` 中的 `kill -HUP`
> 轮替后旧文件被改名、新空文件已建好，但 `rsyslogd` 仍持有旧文件描述符。`kill -HUP` 让 `rsyslogd` 重新读取配置并重新打开日志文件（相当于 reload），否则新消息会写到已不存在的旧文件。

**结合 `chattr +a` 的写法**（轮替前去属性、轮替后加回）：

```text
/var/log/messages
{
    sharedscripts
    prerotate
        /usr/bin/chattr -a /var/log/messages
    endscript
    sharedscripts
    postrotate
        /bin/kill -HUP `cat /var/run/syslogd.pid 2> /dev/null` 2> /dev/null || true
        /usr/bin/chattr +a /var/log/messages
    endscript
}
```

### 18.3.2 实际测试 logrotate

```bash
# 查看轮替过程（不会真正轮替，除非时间到）
logrotate -v /etc/logrotate.conf

# 强制执行轮替（忽略时间条件）
logrotate -vf /etc/logrotate.conf

# 验证结果
ll /var/log/messages*
lsattr /var/log/messages
```

### 18.3.3 自定义轮替

需求示例：对 `/var/log/admin.log`，每月轮替一次、文件超过 10 MB 立即轮替、保留 5 个备份、压缩、保留 `+a` 属性。

```text
# /etc/logrotate.d/admin
/var/log/admin.log {
    monthly
    size=10M
    rotate 5
    compress
    sharedscripts
    prerotate
        /usr/bin/chattr -a /var/log/admin.log
    endscript
    sharedscripts
    postrotate
        /bin/kill -HUP `cat /var/run/syslogd.pid 2> /dev/null` 2> /dev/null || true
        /usr/bin/chattr +a /var/log/admin.log
    endscript
}
```

## 18.4 systemd-journald.service 简介

传统 `rsyslogd` 必须等到开机完成、守护进程启动后才开始记录，开机过程中的信息要靠额外的 `klogd` 转交。`systemd` 是内核唤醒的第一个进程，可直接调用 `systemd-journald` 记录开机全过程——包括服务启动失败的信息。

`systemd-journald` 将日志保存在内存（`/run/log/journal/`），重启后丢失；因此**建议同时启用 `rsyslog` 做持久化**：journald 用于查询本次开机后的实时信息，rsyslog 用于长期存档到磁盘文件。

### 18.4.1 使用 journalctl 查询日志

```bash
journalctl [-nrpf] [--since TIME] [--until TIME] [过滤条件]
```

| 选项/过滤 | 说明 |
|---|---|
| `-n N` | 显示最近 N 行 |
| `-r` | 反向输出（最新在前） |
| `-p 等级` | 按严重等级过滤（如 `-p err`） |
| `-f` | 类似 `tail -f`，实时跟踪 |
| `--since` / `--until` | 按时间范围过滤 |
| `_SYSTEMD_UNIT=unit.service` | 只看指定 unit 的日志 |
| `_COMM=bash` | 只看指定命令的日志 |
| `_PID=pid` / `_UID=uid` | 按 PID / UID 过滤 |
| `SYSLOG_FACILITY=N` | 按 syslog facility 序号过滤 |

**常见用法**

```bash
# 本次开机的全部日志
journalctl

# 仅今天 / 昨天
journalctl --since today
journalctl --since yesterday --until today

# 指定时间段
journalctl --since "2026-08-04 00:00:00" --until "2026-08-05 00:00:00"

# 只看 crond.service 最近 10 行
journalctl _SYSTEMD_UNIT=crond.service -n 10

# 只看错误等级以上的消息
journalctl -p err

# 实时跟踪（Ctrl+C 退出）
journalctl -f
```

### 18.4.2 logger 命令

`logger` 用于**主动写入**日志消息（常用于脚本中标记任务起止）：

```bash
# 语法
logger [-p 服务名称.等级] "消息内容"

# 示例：以 user.info 记录一条消息
logger -p user.info "I will check logger command"

# 查看刚写入的消息（facility=user 对应序号 1）
journalctl SYSLOG_FACILITY=1 -n 3
```

在备份脚本中标记开始与结束：

```bash
#!/bin/bash
if [ "${1}" == "log" ]; then
    logger -p syslog.info "backup.sh is starting"
fi
# ... 备份逻辑 ...
if [ "${1}" == "log" ]; then
    logger -p syslog.info "backup.sh is finished"
fi
```

### 18.4.3 持久化 journal 日志

默认 journal 存于内存、重启即失。如需持久化（保存到磁盘），创建 `/var/log/journal/` 目录并设置权限：

```bash
mkdir /var/log/journal
chown root:systemd-journal /var/log/journal
chmod 2775 /var/log/journal
systemctl restart systemd-journald.service
```

此后 journal 日志会持久保存到 `/var/log/journal/`，重启后仍可查询。

> [!tip] 是否需要持久化 journal
> 既然已有 `rsyslog` 做持久化存档，通常无需再持久化 journal——让 journal 留在内存中（查询快）即可。仅在偏好 `journalctl` 统一查询、且不依赖 `/var/log/` 文本文件时才启用。注意持久化会持续占用磁盘，需监控容量。

## 18.5 分析日志

逐条阅读日志效率低，常用工具：

- **基础命令**：`last`、`lastlog`、`dmesg` 等；
- **`journalctl`**：按服务、时间、等级灵活过滤；
- **`logwatch`**：每日自动汇总并以邮件发给 root。

### 18.5.1 logwatch

`logwatch` 是一个日志分析汇总工具，每日分析日志后将报告邮件发给 root。

> [!note] logwatch 的可用性
> CentOS 7 时代 `logwatch` 可直接安装；在 RHEL 9 / Rocky 9 / AlmaLinux 9 上，该核心包**未必仍在默认或 EPEL 仓库**中提供（EPEL 9 仅含部分服务的 logwatch 子包）。安装前先 `dnf search logwatch` / `dnf repoquery logwatch` 核实；若无，可从 Fedora 源码 RPM 重新构建，或改用 `journalctl` + 自定义脚本、或第三方工具（如 GoAccess、Loki 等）替代。

如已安装，手动运行一次查看报告：

```bash
# 安装后会写入 cron（/etc/cron.daily/0logwatch），每天自动执行
# 也可手动运行：
/etc/cron.daily/0logwatch
```

报告会分类汇总 PAM 认证、Postfix 邮件、SSH 登录、sudo 使用、磁盘空间等情况，发送到 root 的本地信箱，用 `mail` 命令查看。

## 18.6 重点回顾

- 日志记录事件的**何时、何地、何人、何事**四要素；系统出问题务必先查日志；
- 日志集中存放在 `/var/log/`，其中 `messages` 记录的信息最全；
- 日志相关服务：`systemd-journald.service`（上游，存内存）、`rsyslog.service`（持久化到文件）、`logrotate`（轮替）；
- `/etc/rsyslog.conf` 语法：`服务名称.等级  记录目标`；facility 有 kern/user/mail/... 共 0–23 个序号；
- severity 从轻到重：debug < info < notice < warning < err < crit < alert < emerg；
- `rsyslogd` 自身可作为日志服务器，修改 `/etc/rsyslog.conf` 启用 514 端口；
- `logrotate` 通过 cron 定时执行；配置在 `/etc/logrotate.conf` 与 `/etc/logrotate.d/*`；
- 现代 RHEL 9 系可用 `journalctl` 直接从内存查询日志，效能优于翻文本文件；
- `logwatch` 是常用的日志汇总分析工具（RHEL 9 上需核实可用性）。

## 18.7 本章习题

简答题：

1. 若想把 `auth` 服务中等级高于 `warn` 的消息发送邮件给 root，如何配置？
   - 在 `/etc/rsyslog.conf` 中加入：`auth.warn  root`
2. 系统日志机制需要哪两个服务？
   - `systemd-journald.service` 与 `rsyslog.service`
3. `rsyslogd` 与 `logrotate` 各通过什么机制执行？
   - `rsyslogd` 是常驻守护进程（stand alone daemon）；`logrotate` 是命令，通过 `cron` 定时调用。
