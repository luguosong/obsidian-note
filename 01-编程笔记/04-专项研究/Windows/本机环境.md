# 本机环境

> [!note] 已安装软件扫描思路（供后续 agent 维护本表参考）
> 没有单一数据源能列全所有软件，需多渠道交叉、最后用 winget 兜底查漏：
>
> 1. **注册表卸载项**（覆盖多数 MSI/EXE 安装）：`HKLM` 64/32 位 + `HKCU` 的 `...\CurrentVersion\Uninstall\*`，读 `DisplayName` / `InstallLocation` / `DisplayIcon`（后者可反推安装目录）。
> 2. **命令路径**（CLI 工具）：`Get-Command <exe>` 取 `Source`，如 git / gh / pwsh / node / claude。注意甄别——PATH 里可能是 Store 别名桩（`python` 命中 WindowsApps）或捆绑版（`gh` 命中 copilot-desktop 捆绑的），要找真实安装。
> 3. **Store / MSIX 应用**（不进注册表）：`Get-AppxPackage` 读 `InstallLocation`，如 Windows Terminal、PowerShell 7。
> 4. **便携版 / 免安装**（不进注册表）：用运行中进程定位——`Get-Process` 或 `Get-CimInstance Win32_Process` 的 `ExecutablePath`，或在常用盘按名字找目录，如 Snipaste、TrafficMonitor。
> 5. **用户目录安装点**：`%LocalAppData%\Programs`、`%UserProfile%\.local\bin`、npm 全局 `npm ls -g`、`~/.cargo/bin`——AI / CLI 工具常在此，如 Claude Code、Docker Desktop。
> 6. **winget 广扫兜底**：`winget list` 交叉核对，剔除微软运行时 / SDK / Store 内置应用 / 编解码扩展等噪音后，剩下的即可能漏掉的真实软件。
> 7. **免安装 / 绿色软件的盲区**（上面 1–6 全抓不到）：解压即用的工具（如 Maven）不进注册表 / winget / Appx，也不是常驻进程，仅靠 PATH + 环境变量生效。必须额外：扫 `PATH` 每个条目、读各 `*_HOME` 变量（`MAVEN_HOME` / `GRADLE_HOME` / `JAVA_HOME` / `GOROOT` 等），并探测一份**足够全**的已知命令（`mvn` / `gradle` / `kubectl`…，别只查预期内的几个）。
>
> 本机习惯：应用多装在 `D:\`；语言运行时单列「开发环境版本」表，不重复进已安装清单。
