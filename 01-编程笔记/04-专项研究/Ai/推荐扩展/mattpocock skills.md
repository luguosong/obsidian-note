# mattpocock skills

[github仓库](https://github.com/mattpocock/skills)

Matt Pocock 开源的 Claude Code skill 集，针对 AI 编码的四大失败模式（错位/啰嗦/跑不通/泥球），用需求盘问、TDD、领域建模等纪律辅助做真正的工程。本篇仅速查常用 skill，完整 38 个清单见 [[mattpocock skills README]]。

## 安装

```shell
# 通过 npx 安装
npx skills@latest add mattpocock/skills
```

> [!warning] 必装前置
> `setup-matt-pocock-skills` 必须勾选安装——它负责项目初始化，是使用其它 skill 的前提。

## 项目初始化配置

### setup-matt-pocock-skills（手动）

为工程技能配置此仓库（issue tracker、分流标签、领域文档布局）。在使用其它工程技能之前，每个仓库运行一次，会就以下三项配置做决策：

| 配置项 | 相关 skill | 说明 |
|---|---|---|
| Issue 跟踪器 | to-tickets / triage / to-spec / qa | 决定去哪读写 issue |
| triage 状态标签 | triage | 5 个状态用哪套字符串，需匹配实际配置的名字 |
| domain 文档布局 | improve-codebase-architecture / diagnosing-bugs / tdd | `CONTEXT.md` + `docs/adr/` 怎么放，供这些 skill 学领域语言 |

## 询问该用哪个 skill

### ask-matt

询问哪个 skill（技能）或 flow（流程）适合你的情况。是对本仓库中用户调用技能的路由器。

注意：只局限于 mattpocock 包含的 skill

## 搞明白需求

### grill-with-docs

研讨会式的“问答”环节，同时构建你项目的领域模型，完善术语并在行内更新 CONTEXT.md 和 ADRs。

### wayfinder

将一大块工作规划为在问题跟踪器上作为共享的调查工单地图，超过单次 Agent 会话能容纳的量 — 将它们一次解决一个，直到前往目标的路径清晰为止。

## 编写规格说明

### to-spec（手动，原/to-prd）

将当前对话转成规范并发布到 issue tracker。无需访谈 — 只合成你已经讨论过的内容。

在创建规范之前，会询问你将要涉及哪些模块

## 编写计划

### to-tickets

将任何计划、规范或对话拆分为一组跟踪子任务（tracer-bullet tickets），每个任务声明其阻塞边界 — 以本地文件中的文本形式，或作为真实跟踪器上的原生阻塞链接。

## 实现

### implement

根据规范或一组工单构建工作，在预先约定的接缝处推动 /tdd 并在提交前以 /code-review 结项。

### teach（手动）

在多次会话中教授用户一项新技能或概念，使用当前目录作为有状态的教学工作区。教学工作区的文件结构如下：

| 文件 | 角色 | 用途 |
|---|---|---|

| `reference/*.html` | 参考卡 | 压缩速查卡，长期回查用 |
| `learning-records/*.md` | 学习记录 | 你学到了什么，驱动下一课难度 |

| `NOTES.md` | 偏好便签 | 你的偏好（怎么教你） |
| `GLOSSARY.md` | 术语表 | 术语（可选） |

## CONTEXT.md

> [!note] 定义
> `CONTEXT.md` 建立项目的**共同语言**，帮助 agent 解码项目中使用的术语、减少冗长输出。通过 `grill-with-docs` skill 构建。

> [!tip] 共同语言的收益
> - **变量、函数和文件命名保持一致**，使用共享语言
> - 因此，**代码库对 AI 代理更容易导航**
> - AI 代理还**花费更少的 token（令牌）进行思考**，因为它可以访问更简洁的语言
