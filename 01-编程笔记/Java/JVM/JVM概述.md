# JVM概述

## JVM规范与具体实现

JVM 首先是一份**抽象的规范**——《Java 虚拟机规范》（JVMS）只规定字节码格式、指令集、运行时数据区等「必须做什么」；各厂商按规范实现自己的虚拟机，==同一份 `.class` 字节码可以在任何实现上运行==，这正是 Java「一次编译，到处运行」的基石。

> [!tip] 官方规范文档
> [Java 虚拟机规范（JVMS）](https://docs.oracle.com/javase/specs/jvms/se21/html/)，运行时数据区定义在 [§2.5 Run-Time Data Areas](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-2.html#jvms-2.5)。

### 常见的 JVM 实现有哪些？

| 实现 | 厂商 | 特点 |
| --- | --- | --- |
| **HotSpot** | 源自 Sun，现属 Oracle | ==目前最主流==，Oracle JDK 与 OpenJDK 的默认虚拟机 |
| JRockit | Oracle（源自 BEA） | 面向生产环境优化，主打高性能与可伸缩性；后已并入 HotSpot |
| J9 / OpenJ9 | IBM | IBM JDK 采用自研 J9 虚拟机，后开源为 OpenJ9：内存占用更小、启动更快，低时延 GC 与优化的 JIT 编译器 |
| Azul Zing | Azul Systems | 面向生产环境优化，高性能与实时处理，适合高负载企业应用与实时分析场景 |

## 运行时数据区

规范 §2.5 定义了 JVM 运行期间的 **6 大数据区域**，这是 JVM 学习的主线：

| # | 规范小节 | 原文 | 中文名 | 线程维度 |
| --- | --- | --- | --- | --- |
| 1 | §2.5.1 | The pc Register | 程序计数器 | 私有 |
| 2 | §2.5.2 | Java Virtual Machine Stacks | Java 虚拟机栈 | 私有 |
| 3 | §2.5.3 | Heap | 堆 | 共享 |
| 4 | §2.5.4 | Method Area | 方法区 | 共享 |
| 5 | §2.5.5 | Run-Time Constant Pool | 运行时常量池 | 共享 |
| 6 | §2.5.6 | Native Method Stacks | 本地方法栈 | 私有 |

![[JVM整体结构图.canvas]]

### 程序计数器

一块较小的内存空间，记录**当前线程正在执行的虚拟机字节码指令地址**。线程私有，每个线程都有自己独立的程序计数器。

### Java虚拟机栈

用于存储**栈帧**。每个方法执行时都会创建对应的栈帧，其中保存**局部变量表、操作数栈、动态链接、方法出口**等信息；栈帧的执行细节见 [[字节码解读]]。

### 堆

JVM 所管理的**最大的一块内存**，用于存放对象实例与数组，也是**垃圾收集器（GC）收集垃圾的主要区域**。

### 方法区

存储已被虚拟机加载的**类信息、常量、静态变量、即时编译器编译后的代码**等数据。

### 运行时常量池

**方法区的一部分**（规范 §2.5.4：方法区存储类级结构，含运行时常量池），存放编译期生成的各种**字面量与符号引用**。表中单独列出只是便于逐项学习。

### 本地方法栈

本地方法（native）执行过程中使用，作用与 Java 虚拟机栈十分相似。

### 运行时数据区何时创建、何时销毁？

- **线程共享**（堆、方法区）：随**虚拟机启动**而创建，虚拟机停止时销毁。
- **线程私有**（程序计数器、虚拟机栈、本地方法栈）：随**线程创建**而创建，线程结束时销毁。

不同 JVM 实现对运行时数据区的分配和管理方式可能不同，会对性能和功能产生影响。

## 不同实现

### JDK6的HotSpot


以下是JDK6的HotSpot 年轻代：刚new出来的对象放在这里。老年代：经过垃圾回收之后仍然存活的对象。符号引用：类全名，字段全名，方法全名等。这个时期的永久代和堆是相邻的，使用连续的物理内存，但是内存空间是隔离的。永久代的垃圾收集是和老年代捆绑在一起的，因此无论谁满了，都会触发永久代和老年代的垃圾收集。
