# Linux 系统课 Glossary

从计算机底层到操作系统的规范术语表。各课措辞以此为准；新术语在「已教过、能被正确使用」后才收录。英文术语保留原文，给定中文规范名。

## 计算机底层 / 体系结构

**冯诺依曼架构 (von Neumann architecture)**：
一种计算机组织方式——程序指令与数据**共用同一块内存**，CPU 通过一条总线逐条取出指令执行。当今几乎所有通用计算机的基础模型。
_Avoid_：普林斯顿架构（同义，少用）

**存储程序 (stored-program)**：
冯诺依曼架构的核心思想——程序本身也以二进制形式**当作数据存进内存**，因此机器无需改动硬件即可被重新编程。

**五大单元 (five units)**：
计算机硬件的五个基本功能单元：输入单元、输出单元、控制单元、算术逻辑单元、主存储器。前两者对外，后三者是运算核心（控制单元 + 算术逻辑单元合封在 CPU 内）。

**CPU (中央处理器, Central Processing Unit)**：
执行指令的芯片，内含控制单元与算术逻辑单元；是整机的运算与协调中枢。

**控制单元 (Control Unit, CU)**：
CPU 内负责**取指、解码、协调**各单元工作的部分——发号施令者，本身不做算术。

**算术逻辑单元 (Arithmetic Logic Unit, ALU)**：
CPU 内负责**算术运算与逻辑判断**的部分——真正「算」的地方。

**主存 / 内存 (main memory / RAM)**：
存放**当前正在运行的程序与数据**的高速可读写存储；掉电即失。CPU 处理的一切（不管程序还是数据）最终都来自这里、写回这里。
_Avoid_：内存条（指硬件实体时才用）

**寄存器 (register)**：
CPU 内部**最快、最小**的存储，直接参与指令执行（如存放操作数、地址）。存储层次的最顶端。

**指令周期 (instruction cycle)**：
CPU 处理一条指令的重复循环：**取指 (fetch) → 解码 (decode) → 执行 (execute) → 写回 (writeback)**。每秒重复数十亿次。

**程序计数器 (Program Counter, PC)**：
CPU 内一个寄存器，存放**下一条要执行的指令在内存中的地址**；每取一条指令便前进。

**冯诺依曼瓶颈 (von Neumann bottleneck)**：
因指令与数据**共用一条 CPU↔内存总线**、且内存远慢于 CPU，导致 CPU 常在等待数据的性能限制。缓存、多级存储、流水线都是为缓解它。

**总线 (bus)**：
连接 CPU、内存、设备、在它们之间搬运数据/地址/控制信号的公共通路。

**缓存 (cache)**：
夹在 CPU 与主存之间的**小而快**的存储，缓存近期用到的数据/指令以缓解冯诺依曼瓶颈；现代 CPU 多为多级（L1/L2/L3）。

**指令寄存器 (Instruction Register, IR)**：
CPU 内寄存器，取指后存放**当前正在解码/执行的那条指令**。与 PC 分工：PC 记「下一条在哪」，IR 记「这条是什么」。

**操作码 / 操作数 (opcode / operand)**：
一条机器指令的两部分——操作码说「做什么」（加、载、存…），操作数说「对谁做」（哪个寄存器或内存地址）。指令本身就是这串位。

**加载 / 存储 (load / store)**：
CPU 与内存间搬数据的两类指令：load 把内存数据读进寄存器，store 把寄存器结果写回内存。真正的运算只在寄存器之间进行。

**内存墙 (memory wall)**：
CPU 逐年变快、主存速度跟不上，二者差距持续拉大的现象；是冯诺依曼瓶颈的量化体现，也是多级缓存存在的根本理由。

## CPU 与指令集

**ISA (指令集架构, Instruction Set Architecture)**：
CPU 承诺听得懂的**全部指令清单**，是**硬件与软件之间的契约**。编译器面向 ISA 生成指令；同一 ISA 可由多种微架构实现。例：x86-64、ARM 的 AArch64、RISC-V。

**微架构 (microarchitecture)**：
硬件**怎么**兑现某个 ISA 契约的具体实现——流水线、缓存、执行单元的电路设计。例：Intel Core、AMD Zen、Apple Firestorm。与 ISA 正交：契约相同、实现可千差万别。

**微操作 (micro-op, μop)**：
CPU 把一条（尤其 CISC 的）复杂指令在内部拆成的、类 RISC 的定长小操作；乱序流水线真正执行的是 μops。现代 x86「界线模糊」的关键。

**RISC / CISC**：
两种 ISA 设计哲学——RISC（精简、定长、单条简单）如 ARM/RISC-V；CISC（复杂、变长、单条能干更多）如 x86。**现代界线已模糊**：x86 内部 RISC 化、ARM 也在加指令，差别更多在功耗与生态而非速度。

**SMT / 超线程 (simultaneous multithreading / Hyper-Threading)**：
让一个**物理核**对操作系统呈现为**两个逻辑核**，靠共享空闲的运算单元提升吞吐。Intel 叫 Hyper-Threading，AMD 叫 SMT（非 Intel 独有）。

**字长 (word size)**：
CPU 一次能处理 / 寻址的位宽。32 位最多寻址 4GB（2³²），64 位则近乎无限。今天通用设备普遍 64 位。

**Dennard scaling (登纳德缩放) / 功耗墙**：
「晶体管越小、单位功耗越低」的历史规律，约 2005 年失效；此后再堆主频就撞发热/功耗墙，逼使产业从「单核更快」转向「多核 + SMT」。

## 存储层次

**存储层次 / 金字塔 (memory hierarchy)**：
按「速度快→慢、容量小→大、每字节贵→便宜」自上而下排列的存储分层：寄存器 → L1/L2/L3 缓存 → 主存 → SSD → HDD。用慢而便宜的大层兜底、快而贵的小层加速。

**局部性原理 (locality of reference)**：
程序访问内存的统计规律，使分层缓存有效。分两类——**时间局部性**：刚访问过的很快会再访问；**空间局部性**：访问某地址后，其邻近地址很快也会被访问。

**缓存命中 / 未命中 (hit / miss)**：
CPU 要的数据在某层缓存里找到叫命中（快），找不到得往下层取叫未命中（慢）。命中率高低直接决定实际性能。

**缓存行 (cache line)**：
缓存与主存之间搬运的最小块，通常 **64 字节**。一次搬一整行、而非单字节，是对**空间局部性**的押注。

**SRAM / DRAM**：
两种 RAM。SRAM 快、不需刷新、贵而密度低，用作 CPU 缓存；DRAM 慢些、需周期刷新、便宜而密度高，用作主存。二者都**易失**。

**易失性 / 持久 (volatile / non-volatile)**：
易失 = 断电即失（寄存器、缓存、DRAM 主存）；持久 = 断电仍在（SSD、HDD、ROM）。「没保存会丢、关机文件还在」的分界线。

**DDR5**：
2021 年起主流的 DRAM 接口标准，单条带宽约 38 GB/s（远超 DDR3-1600 的 12.8 GB/s）。取代鸟哥停留的 DDR4。

**NVMe SSD / NAND 闪存**：
NAND 闪存（非机械、电子寻址）做的固态盘，走 PCIe 的 NVMe 协议时延迟 ~µs 级、带宽 7000+ MB/s，已是主流系统盘；机械 HDD 退居大容量冷存储。

## 数据表示

**位 (bit)**：
计算机最小信息单位，取 0 或 1（对应硬件的两个稳定电平）。binary digit 的缩写。

**字节 (byte)**：
8 个 bit 打包成的单位，是内存/文件寻址的基本粒度。1 byte 可表示 2⁸ = 256 种状态（0x00~0xFF）。

**十六进制 / 半字节 (hex / nibble)**：
逢 16 进 1 的记数法，符号 0-9A-F；一个 hex 位对应 4 个二进制位（= 半字节 nibble），两个 hex 位正好一字节。程序员用它做位的速记（地址、颜色、字节值），前缀 `0x`。

**二进制前缀 vs 十进制前缀 (KiB vs KB)**：
IEC 二进制前缀 KiB/MiB/GiB = 1024ⁿ（内存、系统显示用）；SI 十进制 KB/MB/GB = 1000ⁿ（硬盘厂商、速度、主频用）。二者混用是「1TB 硬盘显示约 931GiB」的根源。

**字符编码 (character encoding)**：
把「字符」与「字节」互相映射的对照表。存文字时按表把字符转成字节、读时反转；用错表就出现乱码。

**ASCII**：
最早的英文编码，7 位、128 个字符，每字符 1 字节（如 A=0x41）。装不下非英文字符。

**Unicode / 码点 (code point)**：
给世界上每个字符分配唯一编号（码点，如「中」= U+4E2D）的字符集标准。它只管「编号」，不管「怎么存成字节」。

**UTF-8**：
把 Unicode 码点编码成字节的**变长方案**（1–4 字节），且**兼容 ASCII**（ASCII 字符仍 1 字节）。今日全网约 99% 网页的编码，事实标准。汉字多为 3 字节、emoji 多为 4 字节。

## 操作系统

**机器码 (machine code)**：
CPU 能直接执行的二进制指令（某个 ISA 的 opcode+operand 的位）。人类一般不直接写，由编译器/解释器从高级语言产生。

**编译器 / 解释器 / 字节码 (compiler / interpreter / bytecode VM)**：
三种把高级语言变成可执行的路线——编译器运行前一次性翻成机器码（C/Rust/Go）；解释器运行时逐句翻译执行（Python/JS）；字节码方案先编译成中间字节码，再由虚拟机解释或 JIT（Java/JVM、C#）。

**操作系统 (Operating System, OS)**：
管理硬件、分配资源、隔离保护、并为程序提供统一开发接口的软件层。= 内核 + 一圈外围程序。Linux 就是一个操作系统。

**内核 (kernel)**：
操作系统的核心——唯一直接碰硬件、常驻内存、受保护的程序。四大职责：进程管理、内存管理、文件系统、设备驱动。

**系统调用 (system call)**：
程序向内核请求服务的受控入口（如 open/read/write/fork）。程序不能直接碰硬件，只能经系统调用让内核代劳。

**用户态 / 内核态 (user mode / kernel mode)**：
CPU 硬件强制的两种权限级别：普通程序跑在用户态（碰不到硬件），内核跑在内核态（能操作一切）。系统调用时从用户态「陷入」内核态。是「一个程序崩溃不拖垮整机」的根基。

**驱动程序 (device driver)**：
内核里（或可加载模块）驱动某类硬件、把它包装成统一接口的程序。通常由硬件厂商按 OS 接口开发，故 Windows 驱动不能用于 Linux。

**虚拟内存 (virtual memory)**：
内核给每个进程一块「独占的」逻辑地址空间的假象，底层映射到物理内存/交换区（swap）。让进程互相隔离、且内存不足时仍能运行。

## Unix / Linux 谱系

**Unix**：
1969 年 Ken Thompson 造原型、1973 年 Ritchie 用 C 重写的操作系统，Linux 的思想「老大哥」。强调多用户多任务、可移植、小工具组合。纯种分支为 BSD 与 System V。

**Unix 哲学 (Unix philosophy)**：
Unix 的设计信条——「一切皆文件；每个程序只做一件事并做好；让程序用管道协作、处理文本流」。Linux 命令行强大而优雅的根源。

**管道 (pipe, `|`)**：
把前一个命令的输出接到后一个命令的输入，让小工具串联协作（如 `ls | grep foo`）。Unix 哲学「组合小工具」的落地机制。

**可移植性 (portability)**：
同一套软件（尤其用高级语言写的）稍加重编译即可在不同硬件/ISA 上运行的能力。1973 用 C 重写 Unix 换来的关键特性，也是开源能跨硬件生长的前提。

**BSD / System V**：
两大「纯种」Unix 分支。BSD（1977，Berkeley）→ 影响 Sun、FreeBSD，macOS 内核亦承其血脉；System V（1979，AT&T）→ 商业 Unix（AIX、Solaris）规范源头。

**GNU**：
Stallman 1983 发起的自由软件计划（GNU's Not Unix，递归缩写），目标是做一套完全自由的类 Unix 系统。攒下 gcc、bash、coreutils、Emacs 等大量工具，唯独内核 Hurd 难产——后与 Linux 内核合体成 GNU/Linux。

**自由软件 (free software)**：
强调「自由」而非「免费」的软件（free as in speech, not beer）。四种自由：运行、复制、研究/修改（需源码）、再发行改进版。可以卖钱（卖服务）。

**GPL / copyleft (著佐权)**：
GNU General Public License。copyleft 是其核心机制：用了 GPL 代码，衍生作品也必须以 GPL 开源，让自由「传染」下去、无法被私有化。Linux 内核用 GPLv2。与 MIT/BSD 等「宽松许可」（允许闭源商用）相对。

**开源 (open source)**：
1998 年 OSI 提出的名词，绕开 free 的歧义、更亲商业。强调源码公开可改可再散布。GPL 是开源的一种（传染性强）。

**POSIX**：
可移植操作系统接口（IEEE 标准），规范内核与应用之间的接口。Linux 遵循 POSIX，故天然兼容 Unix 软件。

**GNU/Linux**：
严格意义上的完整系统名：Linux 提供内核，GNU 提供大部分用户空间工具（bash/coreutils/gcc/glibc）。日常口语常把整套系统简称「Linux」。

## 发行版与生态

**发行版 (distribution / distro)**：
把 Linux 内核 + GNU 工具 + 应用软件 + 包管理器 + 安装器 + 发行商自有工具，打包成可完整安装的成品系统。如 Ubuntu、Debian、RHEL、Fedora、Rocky。内核版本 ≠ 发行版版本，是两套编号。

**内核版本号 / LTS**：
形如 `6.6.9`（主.次.补丁）。2.6 前次版本奇=开发/偶=稳定；3.0（2011）起废弃奇偶、改时间制（每约 9–10 周一次、全稳定）。LTS = 长期支持内核（维护约 6 年，如 6.1/6.6/6.12），生产环境首选。`uname -r` 查看。

**包管理器 / RPM 系 vs DPKG 系**：
装/删/更新软件的工具，是发行版分家族的主线。RPM 系（`rpm`/`dnf`，如 RHEL/Fedora/Rocky/openSUSE）与 DPKG 系（`dpkg`/`apt`，如 Debian/Ubuntu）。独立派如 Arch（`pacman`、滚动更新）、Gentoo（源码编译）。

**FHS (文件系统目录标准)**：
Filesystem Hierarchy Standard，规范 `/etc`、`/home`、`/usr` 等目录含义。各发行版都遵循，故命令与目录八成通用（第 6 章详讲）。

**CentOS Stream / Rocky Linux / AlmaLinux**：
CentOS Linux（RHEL 免费重编译版）已被红帽终止：2020 转 CentOS Stream（变 RHEL 上游测试版），CentOS 7 于 2024-06-30 EOL。社群接棒的 RHEL 重编译替代品为 Rocky Linux 与 AlmaLinux，是老 CentOS 的 drop-in 替代。

**man page (手册页)**：
系统内置的命令/系统调用/配置文件官方手册，用 `man <名>` 查阅。学 Linux「读一手（RTFM）」的第一去处；在线权威版见 man7.org。
