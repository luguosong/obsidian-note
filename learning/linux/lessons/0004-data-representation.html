数据表示：位、十六进制与文字编码

前三课里，寄存器、缓存、内存、硬盘、总线上跑的全是位。 可人类要的是数字和文字——它们怎么变成 0 和 1？这一课讲透表示：数字靠进制、文字靠编码。 顺便填两个真实世界的坑：KiB≠KB，以及为什么「中」占 3 个字节。

这节课的收获：你能说清「计算机里一切都是位」；看懂 bit / byte / 十六进制 的关系与换算；分清 KiB vs KB（1024 vs 1000）；并讲出文字编码从 ASCII → Unicode/UTF-8 的演进——为什么中文和 emoji 能存、为什么会乱码。

1. 一切都是位：bit 与 byte

计算机底层只认「有没有通电」——两个稳定状态，记作 0 和 1。这一个 0/1 就是 位（bit，binary digit）。用两个状态而不是十个，是因为硬件上两个电平最稳、最抗干扰。

1 个 bit 太小，于是把 8 个 bit 打包成 1 个字节（byte）——这是内存/文件寻址的基本单位：

1 Byte = 8 bit，能表示 2⁸ = 256 种状态（0000 0000 ~ 1111 1111）。

回接前几课：寄存器里的数、缓存行的 64 字节、内存里的 a、SSD 上的文件、总线上传的指令——无一例外，都是一串字节（位）。剩下的问题只有一个：怎么把人类的数字和文字，映射成这串位。

2. 十六进制：给人看的位速记

二进制对机器友好，对人太长——一个字节 11010010 谁看得清？于是有了十六进制（hex）：它的一位正好顶 4 个二进制位（这 4 位叫半字节 nibble），符号是 0-9 再加 A-F（A=10 … F=15）。

换算就是「4 位一组」：一个字节 1101 0010 → 拆成 1101(D) 和 0010(2) → 0xD2（十进制 210）。所以一个字节总能写成两个 hex 位，0x00~0xFF 正好覆盖 0~255。

为什么程序员到处见到 hex

内存地址（0x7ffee3b0）、颜色（#FF5733 就是 RGB 三个字节）、字节值（0xFF）、UTF-8 编码（下面就见到）——都用 hex，因为它和字节严丝合缝：两位一字节，比二进制短、比十进制更贴近底层。前缀 0x 表示「这是十六进制」。

3. KiB vs KB：一个真实世界的坑

字节太多时要用大单位，但这里藏着一个经典混淆——1024 还是 1000？

  • KB / MB / GB（SI 十进制）：K = 1000，逐级 ×1000。硬盘厂商、网速、主频用这套（鸟哥：速度单位用十进制，1 GHz = 10⁹ Hz）。
  • KiB / MiB / GiB（IEC 二进制）：Ki = 1024（2¹⁰），逐级 ×1024。内存、操作系统显示容量用这套。
你买的「1 TB」硬盘（厂商按 10¹² 算），装进系统按 2⁴⁰ 换算却显示约 931 GiB——不是缺斤少两，是两套单位打架。1 TB ÷ 1024³ ≈ 931 GiB。

严谨写法就用 IEC 后缀（KiB/MiB/GiB）区分——鸟哥当年也提到了这个 i。可惜多数系统仍把 1024 进制的量标成「GB」，坑就一直在。

4. 文字编码：从 ASCII 到 Unicode / UTF-8

数字好办，文字呢？文字也得变成位，靠一张「字符 ↔ 数字」对照表，这就是编码。演进有三幕：

  1. ASCII：只够英文

    用 7 位、编 128 个字符（英文字母、数字、标点），每字符 1 字节。A = 65 = 0x41。问题：装不下中文、日文……

  2. 各国各造 → 冲突乱码

    中文有 Big5 / GBK（每字 2 字节），其它语言又各搞一套。互不兼容，同一串字节在不同表里含义不同——鸟哥举过 Big5 的「許、蓋、功」被误判成引号的经典坑。

  3. Unicode + UTF-8：一统天下

    Unicode 给世界上每个字符一个唯一编号（码点 code point，如「中」= U+4E2D）。UTF-8 则规定这个码点怎么变成字节：变长 1–4 字节、兼容 ASCII。

关键：Unicode 和 UTF-8 是两层，别混

Unicode = 字符的「身份证号」（码点）；UTF-8 = 把号码落成字节的「编码方案」。UTF-8 的妙处：ASCII 字符仍是原来的 1 字节（老英文文件天然兼容），其它字符用 2–4 字节。如今 UTF-8 占了全网约 99% 的网页——它就是事实标准。鸟哥当年只说「记得把编码改成 UTF-8」，没讲这两层，我们补上。

5. 走一遍：A / 中 / 😀 怎么变成位

把「文字是位」彻底坐实。三个字符，经 Unicode 码点 → UTF-8 字节：

😀U+1F600F0 9F 98 804

其中 A 落到底层就是 0x41 = 0100 0001 这 8 个位。三个洞察收束全课：

  • 一切都是位：连一个 emoji 也不过是 4 个字节 F0 9F 98 80。
  • UTF-8 变长：ASCII 范围 1 字节，多数汉字 3 字节，冷僻字符/emoji 4 字节——这就是「中」比「A」占得多的原因，也是「字符数 ≠ 字节数」的由来。
  • 乱码的本质：字节没变，对照表拿错了。用 UTF-8 存、却按 GBK 读，E4 B8 AD 就被对成别的字。

5. 为什么同一份 UTF-8 文本里「中」占 3 字节、「A」只占 1 字节？

进阶挑战：为什么同一个文本文件，用错编码打开会出现乱码？（先想，再展开）

文件里存的只是一串字节，本身不带「我是什么编码」的标签。编码是一张「字节 ↔ 字符」对照表：存的时候用 A 表（比如 UTF-8）把「中」写成 E4 B8 AD，读的时候若用 B 表（比如 GBK）去对照，同一串字节被翻成了别的字——这就是乱码。有意思的是，纯英文往往不乱，因为 UTF-8 兼容 ASCII，那段字节在两张表里恰好一致；中文 / emoji 最容易乱，因为它们在各编码里的字节安排完全不同。解决办法：统一用 UTF-8，并让程序知道文件是 UTF-8。
