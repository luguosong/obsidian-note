内存与存储层次：金字塔与局部性原理

第 1 课埋过一个伏笔——「CPU 直接读主存」是简化，真实是一座金字塔； 第 2 课看到内存墙逼出了多核。 这一课把金字塔补全：从寄存器到硬盘，为什么非得分层？答案是一个朴素又深刻的规律——局部性。

这节课的收获：你能画出存储金字塔（寄存器→L1/L2/L3→主存→SSD→HDD），说清「越往下越大、越慢、越便宜」的三重权衡，并用局部性原理解释：为什么一小块缓存就能让整体又快又便宜。

1. 存储金字塔：一张全景图

把第 1 课的延迟表往下补全，加上容量和持久性。周期数按 4 GHz（一个周期 ≈ 0.25 ns）估算：

层介质典型容量延迟（≈周期）断电后
寄存器SRAM数百字节~0.3 ns（1）易失
L1 缓存SRAM~64 KB~1 ns（~3）易失
L2 缓存SRAM~1 MB~3 ns（~10）易失
L3 缓存SRAM~32 MB~10 ns（~30）易失
主存DRAM（DDR5）16–64 GB~70 ns（~280）易失
SSDNAND 闪存（NVMe）~1 TB~50 µs（~20 万）持久
HDD磁介质数~十几 TB~5 ms（~2000 万）持久

三重权衡，一眼看清：越往下 → 越大、越慢、每 GB 越便宜。中间还有一道分水岭：主存及以上易失（断电即失，volatile），SSD 及以下持久（断电仍在，non-volatile）——这就是为什么关机后文件还在硬盘、而没保存的内容会丢。

2. 为什么必须分层：局部性原理

每一层都被逼着二选一：要么快（但小又贵），要么大且便宜（但慢）。那凭什么整机能同时做到又快、又大、又便宜？靠一个关于「程序怎么访问内存」的规律——局部性原理（locality of reference）：

  • 时间局部性（temporal locality）：刚访问过的东西，很快还会再访问（循环变量、热点函数）。
  • 空间局部性（spatial locality）：访问了某个地址，它邻近的地址很快也会被访问（数组顺序遍历、指令一条接一条）。

因为程序普遍有局部性，一块很小的快缓存只要装着「最近用过 + 邻近」的数据，就能接住绝大多数访问（命中，hit）。于是——

平均速度逼近顶层（缓存命中时的快），单位成本逼近底层（大而便宜的慢层）。金字塔不是魔法，是在吃程序的局部性红利。
— 综合 Wikipedia《Locality of reference》/ CSAPP 第 6 章

缓存行：一次搬一整块（押注空间局部性）

缓存和主存之间，一次不搬 1 字节，而搬一整块——缓存行（cache line，通常 64 字节）。你只要了 a，硬件顺手把 a 周围的 64 字节一起搬来，赌你马上会用到邻居。这就是空间局部性被硬件「物化」的样子。

3. 主存 DRAM 的现代实况

为什么缓存用一种内存、主存用另一种？因为它们是两种 RAM：

SRAM（静态）DRAM（动态）
用在CPU 缓存 L1/L2/L3主存（内存条）
特点快、不用刷新；贵、密度低慢些、需不断刷新；便宜、密度高

主存用 DRAM，图的就是便宜、大容量。它易失（断电即失），且需要周期性「刷新」才能保住数据。DRAM 的接口标准一路演进 DDR→DDR2→DDR3→DDR4，鸟哥 2015 停在「DDR4 是服务器级超快」——

纠偏：今天是 DDR5 的时代

DDR5（2021 年起）已是消费级主流：单条 DDR5-4800 带宽约 38 GB/s，双通道 >76 GB/s，远超鸟哥表里 DDR3-1600 的 12.8 GB/s。多通道（双/四通道）把位宽翻倍来加带宽的思路不变。另外，鸟哥讲的开机固件 BIOS 也早被 UEFI 取代了（第 5 课再展开）。

4. 持久层的现代真相：SSD 取代机械盘

这是鸟哥最需要纠偏的地方。他以机械硬盘为主角、SATA3（600 MB/s）为主流接口。而 2015 之后，存储层的底部彻底换了主角：

介质接口延迟带宽今日角色
NVMe SSDPCIe~20–100 µs7000+ MB/s主流系统盘
SATA SSDSATA~50–200 µs~550 MB/s老机器过渡
HDD（机械）SATA/SAS2–12 ms100–250 MB/s大容量冷存储 / 备份

关键在机制差异：机械 HDD 靠机械手臂寻道（seek）+ 盘片旋转，随机访问要等物理移动，所以慢；SSD 是闪存（NAND flash），纯电子寻址、没有机械寻道，随机读写快出几个数量级。加上 NVMe 走 PCIe（而非老 SATA 总线），带宽再上一个台阶。「加块 SSD 让老电脑飞起来」的底层原因就在这。

5. 走一遍：一次缓存命中 / 未命中之旅

回到第 1 课的 c = a + b。当 CPU 要读 a，它逐层往下问，直到找到：

  1. 第一次读 a：一路未命中（miss）

    查 L1（~1ns）没有 → L2（~3ns）没有 → L3（~10ns）没有 → 主存（~70ns）取到，顺手把含 a 的整条 64 字节缓存行灌进各级缓存。慢，但只慢这一次。

  2. 再读 a：L1 命中（hit）

    这次 L1 就有（~1ns）——快了几十倍。这就是「第一次慢、第二次快」的真相：时间局部性被缓存接住了。

  3. 读 a 的邻居（如数组下一个元素）：也命中

    它早随那条 64B 缓存行一起被搬来了——空间局部性。所以顺序遍历数组远快于随机跳访问。

一句收束：分层 + 局部性，就是对抗第 2 课「内存墙」的答案。写「缓存友好」的代码（顺序 > 随机），本质就是喂饱局部性。（题外：若 a 所在的页被换出到了 SSD，还得从 SSD 调回来，慢十万倍——那是虚拟内存，留给后面讲操作系统。）

进阶挑战：为什么「第一次访问 arr[0] 慢，紧接着访问 arr[0]…arr[7] 却都很快」？用两种局部性解释。（先想，再展开）

第一次读 arr[0] 未命中，得一路到主存（~70ns）——但硬件会把含 arr[0] 的整条 64 字节缓存行（覆盖了后面好几个相邻元素）一并灌进 L1。于是：再读 arr[0] 靠时间局部性命中（~1ns）；读 arr[1]…arr[7] 靠空间局部性命中（邻居已在同一缓存行里）。这正是顺序遍历远快于随机访问的底层原因——顺序访问把每条缓存行的 64 字节都用满了。
