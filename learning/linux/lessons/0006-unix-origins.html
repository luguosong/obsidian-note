Unix 的诞生与哲学：Linux 的思想源头

第 0 章我们从硬件一路铺到了操作系统。现在正式认识 Linux——但要懂 Linux，得先认识它的「老大哥」Unix。 Linux 骨子里流着 Unix 的血：两条 1969 年的设计信念，至今还活在你敲的每一条命令里。

这节课的收获：你能讲出 Unix 的来历（1969 Thompson 造原型 → 1973 Ritchie 用 C 重写）、「用 C 重写 → 可移植」为什么是历史转折，以及 Unix 两大哲学（一切皆文件 + 小工具各做一件事）——它们正是 Linux 的基因。

1. Unix 从哪来：Multics 的教训 → Thompson 的一个月

1965 年，贝尔实验室、MIT、通用电气联手搞 Multics——一个想「大而全、支持 300+ 终端」的雄心项目。结果进度落后、资金短缺，贝尔实验室 1969 年退出了。

但项目里的人带走了点子。Ken Thompson 就是其一。1969 年，他借到一台没人用的 PDP-7，趁妻儿探亲的一个月，用汇编写出了一个极简的核心 + 文件系统——这就是 Unix 的原型（当时戏称 Unics）。

教训藏在对比里

Multics 大而全，失败了；Unics 小而精，活了下来。这不是巧合——「简单、能组合」的取向，马上就凝成了 Unix 最核心的两条哲学（下一节）。这也呼应第 5 课「裸硬件三难题」里那个朴素道理：好系统靠克制。

2. 两条奠基信念：Unix 哲学

Thompson 那个系统，带着两个此后深刻影响 Linux 的概念（鸟哥原文点出）：

  1. 一切皆文件

    程序、设备……都被统一当成文件来读写。你以后在 Linux 里能 cat 一个硬盘、往 /dev 里的设备写数据，根就在这。

  2. 每个程序只做一件事，并做好

    不造大而全的巨兽，而是许多小而专的工具，各司其职。

后来 Doug McIlroy 把它补全成一句话：「写只做一件事的程序；让它们协作；让它们处理文本流。」文本流 + 小工具，靠管道（pipe，|）串起来，就能拼出复杂功能。

这套 Unix 哲学不是博物馆展品——它就是你即将天天用的操作手感：ls | grep | wc 那种「小工具用管道拼起来」的爽感，正是 1969 年那两条信念的活化石。
— Unix 哲学，Doug McIlroy / E. Raymond《The Art of Unix Programming》

3. 用 C 重写 → 可移植：改变历史的转折

原型 Unics 是汇编写的——回接第 2/5 课：汇编专一、不可移植，每换一种机器就得重写。这太痛了。

于是 1973 年，Dennis Ritchie 把 B 语言改造成 C 语言，再用 C 重写了整个 Unix 核心，正式发行 Unix。这一步的分量怎么强调都不过分：

  • 高级语言 C 与硬件解耦（第 5 课：编译器把 C 翻成各 ISA 的机器码）→ Unix 从此能移植到不同机器，只需重新编译。
  • 可移植性让 Unix 遍地开花，也让 20 年后的 Linux 能在 386 上重生。
  • C 语言本身沿用至今——Linux 内核就是 C 写的。

一句话：「用 C 重写」既是 Unix 的技术根基，也是整个开源世界能跨硬件生长的前提。

4. 两大分支：BSD 与 System V

因为可移植 + 早期宽松，Unix 很快开枝散叶，长出两条「纯种」主干：

分支来历血脉延续
BSD（1977）Berkeley 的 Bill Joy 拿 Unix 源码改出的版本→ Sun、FreeBSD；macOS 内核就源自 BSD
System V（1979）AT&T 官方版，开始支持 x86 个人电脑→ 商业 Unix（AIX、Solaris…）的规范源头

但 1979 年 AT&T 出于商业考量收回版权，甚至规定「不可对学生提供源码」——学界一片哗然。这份「封闭」，恰恰给下一课埋了伏笔：正是 Unix 的商业封闭，催生了自由的 GNU 与 Linux。

现代回响：你的 Mac 是 Unix 后裔

BSD 血脉没断——macOS（内核 Darwin/XNU）承袭自 BSD，还是官方认证的 UNIX。所以「Unix 老古董」其实一直在你身边跑着。（安卓和 ChromeOS 则是 Linux 系，另一条线——下一课讲。）

5. 走一遍：一条命令里的 Unix 哲学

把 1969 年那两条信念，落到一条你以后天天敲的命令上——统计日志里有多少个 404：

cat access.log | grep 404 | wc -l
#  读文件      筛出404行   数行数

拆开看，全是哲学的活化石：

  • 每个工具只做一件事：cat 只负责读、grep 只负责筛、wc 只负责数——没有一个「大而全」的巨兽。
  • 管道 | 把它们串起来：前一个的输出，变成后一个的输入，拼出「数 404」这个原本没有专门命令的功能。
  • 一切皆文本流：它们之间流动的就是文本，谁都能接。

收束：Unix 哲学不是历史，是你即将上手的手感。下一课，我们看这套理念如何遇上「自由软件」，最终在 1991 年长成 Linux。

进阶挑战：为什么 ls | grep foo 这种「用管道串小工具」的写法，是 Unix 哲学的直接体现？（先想，再展开）

因为它同时兑现了那两条信念：ls 只做「列文件」、grep 只做「筛选」——每个程序只做一件事并做好；而 管道 | 把 ls 的输出当作 grep 的输入，让两个小工具协作出「列出含 foo 的文件」这个新功能，中间流动的是文本流（一切皆文件/文本）。于是无需一个专门的「列出匹配文件」的大命令——组合小工具就够了。这正是 Linux 命令行强大又优雅的根本原因。
