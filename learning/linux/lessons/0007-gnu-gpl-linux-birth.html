GNU、自由软件与 Linux 的诞生

上一课末尾埋了个伏笔：正是 Unix 的商业封闭，催生了自由的 Linux。 这一课讲清那条线——Stallman 的自由软件运动造好了满地工具却缺个内核，Torvalds 1991 用这些工具写出了内核。 两半一合，才是你今天用的系统。所以它其实该叫 GNU/Linux。

这节课的收获：你能说清 GNU / 自由软件 / GPL（copyleft） 是什么、「自由」为何不是「免费」；并讲出 Linux 的诞生——Torvalds 的内核 + GNU 的工具 = 完整系统，以及 GPL 为什么是让它滚雪球的引擎。

1. Stallman 与 GNU：一场关于「自由」的运动

1979 年后 Unix 被 AT&T 商业封闭（上一课），激怒了 MIT 的黑客 Richard Stallman。1983 年他发起 GNU 计划——名字是个程序员式的递归玩笑：GNU = GNU's Not Unix（GNU 不是 Unix），目标是做一套完全自由的类 Unix 系统。1985 年他又成立 FSF（自由软件基金会）。

他说的「自由软件」（free software），free 指的是自由，不是免费——用他那句名言：

"Free software" is a matter of liberty, not price. Think of "free speech", not "free beer".
— Richard Stallman

具体是四种自由：运行、复制、研究/修改（需源码）、再发行改进版。这就是为什么源码必须一起释出——不然你没法真正「修改」。

纠正鸟哥一处小年份

鸟哥写「1984 创立 GNU 与 FSF」。更准确的是：GNU 计划1983 年 9 月发起、次年开始开发；FSF 1985 年才成立。差不了几年，但顺序值得记清。

2. GPL 与 copyleft：自由的「防护罩」

光把源码放出来还不够——怕有人拿去改一改、做成闭源专利软件再卖，自由就断了。于是 Stallman 设计了 GPL（GNU General Public License）这张版权声明，核心机制叫 copyleft（著佐权，跟 copyright 唱反调）：

只要你用了 GPL 的代码，你的衍生作品也必须同样以 GPL 开源。自由像「传染」一样一代代传下去，谁也没法把它私有化。

几个常被误解的点（鸟哥特意澄清过）：

  • 自由软件可以卖钱：不能「单纯卖软件」，但可以卖服务、售后、手册——这正是 Linux 厂商的商业模式。
  • 你不能取消它的 GPL 授权，哪怕你大改过。
  • 版本：GPLv2（1991）与 GPLv3（2007）——Linux 内核至今用 GPLv2。

（顺带：1998 年 OSI 提出「开源」（open source）一词，绕开 free 的歧义、更亲商业。GPL 属于「传染性强」的一类；MIT/BSD/Apache 等宽松许可则允许闭源商用，这是后来公司更爱它们的原因。）

3. Torvalds 1991：用 GNU 工具写出的内核

芬兰的 Linus Torvalds，1988 年进赫尔辛基大学接触 Unix，但全校一台机器、要排队等终端，烦透了：「我何不自己搞一部？」他买了台 Intel 386，装上 Minix（Tanenbaum 教授写的教学用类 Unix，带源码）边用边学，还做了个著名的 386 多任务测试（三个小程序轮流输出 ABABAB…）。

不满 Minix 的封闭，1991 年他决定自己写内核。关键一步：他用的是 GNU 的工具——gcc 编译器 + bash shell（第 5 课：写程序要编译器和环境）。然后在 BBS 上发了那则传世帖子：

I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu) for 386(486) AT clones… I've currently ported bash and gcc…
— Linus Torvalds, 1991（comp.os.minix）

因为他放内核的 FTP 目录叫 Linux，大家就这么叫开了，首个公开版本是 0.02。他还让 Linux 遵循 POSIX 标准（内核与应用间的接口规范），从而天然能跑 Unix 上的软件——这个正确决定让 Linux 起步就体质优良。

4. 合体：为什么叫「GNU/Linux」

这里是全课的「aha」。到 1990 年，GNU 已经攒下 gcc、bash、Emacs 和一大堆工具——唯独内核（GNU Hurd）难产。而 Linux 恰好只是个内核、缺一圈工具。一套操作系统 = 内核 + 外围工具（第 5 课）：

GNU（有工具、缺内核）＋ Linux（是内核、缺工具）＝ 一套完整的自由类 Unix 系统。
这就是 Stallman 坚持叫它 GNU/Linux 的理由。

而 GPL 是让它滚雪球的引擎：因为开源，全球黑客志工能读码、写驱动、回馈补丁——从 Torvalds 单人维护 → 志工涌入 → 分层分工（Alan Cox 等副手先测试再汇总），这群素未谋面的人被称为虚拟团队（后有 kernel.org）。进步快到「用户要虚拟内存，一周后新版就有了」。1994 年发布 1.0，吉祥物是企鹅 Tux。

现代回响

2005 年 Torvalds 又为管理内核协作亲手写了 Git——没错，你天天用的 Git 就是为 Linux 内核而生的。今天开源已无处不在：Linux 跑着几乎整个互联网服务器、Android（30 亿+ 设备，用 Linux 内核）、全部 Top500 超算、绝大多数云。这台雪球，1991 年从一个「just a hobby」滚起。

5. 走一遍：你系统里哪些是 GNU、哪个是 Linux

把「GNU/Linux」坐实。当你在终端里干活，其实是两拨东西在协作：

你接触的东西其实来自角色
调度进程、管内存、驱动硬件Linux内核（第 5 课四大职责）
bash（你敲命令的 shell）GNU外围工具
ls / cp / cat（coreutils）GNU外围工具
gcc（编译器）、glibc（C 库）GNU外围工具

所以严格讲，「Linux」只是那个内核；你敲的绝大多数命令是 GNU 的工具。合起来才是 GNU/Linux 这套系统。时间线一眼看完：

  • 1983 GNU 发起 → 1985 FSF/GPL → 1991 Linux 0.02（用 GNU 工具写成）→ ~1992 GNU+Linux 合体 → 1994 Linux 1.0 → 2005 Git 诞生。

进阶挑战：为什么说「你装的 Ubuntu，严格讲是 GNU/Linux 加上更多」？（先想，再展开）

因为 Ubuntu ≠ Linux 本身。它由三层拼成：① Linux 内核（调度、内存、驱动硬件——第 5 课四大职责）；② GNU 的用户空间工具（bash、coreutils 的 ls/cp、gcc、glibc……你敲的命令几乎都是它）——这两层合起来就是「GNU/Linux」；③ 再叠上发行版特有的东西：包管理器（apt）、桌面环境（GNOME）、安装器、预装软件、配置与美化。所以「Linux」这个词日常被拿来指整套系统，但严格说：内核才是 Linux，工具是 GNU，剩下的是发行版加的料——这正是下一课的主题。
