code-review · 两轴并行 + Fowler 12 坏味道

一张卡钉死：审查的两条正交轴怎么跑、Standards 轴那套 12 个 Fowler 坏味道全表、以及绑住它的两条铁律。配套 第 20 课，适合打印贴墙。

一条主线：两轴正交，不合并不重排

审「fixed-point → HEAD」的 diff，沿两条刻意分开的正交轴：Standards（怎么写·合不合规范 + Fowler 基线）× Spec（做对没·忠不忠实实现 issue）。两轴作 parallel sub-agents 跑、互不污染 context，聚合时并列不 merge、不 rerank——因为一个改动能过一轴失另一轴，合并会让一轴掩盖另一轴。

轴问什么参照过/失
Standards怎么写·合规范？仓库规范 + Fowler 基线合规范但做错东西＝Standards 过·Spec 失
Spec做对没·实现对？originating issue / spec做对但破坏约定＝Spec 过·Standards 失

model-invoked：implement 每片提交前自动调（顺序 tdd→测试→code-review→提交）。手动跑只为换 fixed point / 范围（整条分支对 main、别人 PR、review since X）。

Fowler 12 坏味道基线（Standards 轴）

就算仓库零文档，Standards 轴也永远带这套（《重构》ch.3 · 治 ball-of-mud）。每条读「是什么 → 怎么修」：

坏味道是什么 → 怎么修
Mysterious Name名字没揭示它干什么/存什么 → 改名；起不出诚实名＝设计浑浊
Duplicated Code同一逻辑形状在多处出现 → 抽出共享形状、两处都调
Feature Envy方法总够别的对象的数据多过自己的 → 把方法搬到它眼馋的数据那边
Data Clumps同几个字段/参数总一起旅行 → 打包成一个类型、传它
Primitive Obsession用基本类型/字符串顶替该有自己类型的领域概念 → 给概念立小类型
Repeated Switches同一 switch/if 级联对同一类型反复出现 → 换多态，或两处共享一张 map
Shotgun Surgery一个逻辑改动逼你散弹式改一堆文件 → 把一起变的收进一个模块
Divergent Change一个模块因几件不相关的事被反复改 → 拆开、让每个模块只为一个原因变
Speculative Generality为 spec 没提的需求加的抽象/参数/钩子 → 删掉、inline 回去到真需求出现
Message Chains长长的 a.b().c().d() 导航、调用者不该依赖 → 藏到第一个对象的一个方法后
Middle Man一个类/函数大多只是往下转发 → 砍掉、直接调真正的目标
Refused Bequest子类/实现忽略或覆盖了继承来的大部分 → 弃继承、改用组合

绑住基线的两条铁律

  • repo overrides（仓库覆盖基线）：仓库文档化的标准永远赢——它认可的做法，把基线里对应 smell 压掉。（＝间接层：setup 写下的仓库现实凌驾通用基线。）
  • always a judgement call（永远判断题）：每个 smell 只是带标签的启发式（「possible Feature Envy」），不是硬违规；tooling 已强制的（linter/formatter）一律跳过。

对比：documented-standard 的违反可以是硬违规；baseline smell 永远是判断题。两者别混。
