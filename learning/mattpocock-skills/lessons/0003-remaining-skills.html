mattpocock/skills 系统课 · 第 3 课 · 基于 v1.1.0

剩余 skill 速览：地图与工作流之外的那些

第 1、2 课覆盖了主流程 + 三条匝道里的 triage / diagnosing-bugs / wayfinder。 这节课把剩下没展开的 skill 一次性点名定位——每个给触发场景 + 产出 + 一个关键约束/误区。 细节留后续单 skill 课；这节课让你看到名字就知道何时用。

这节课的收获：听到任何一个 Matt Pocock skill，你能立刻归类（原语 / standalone / 词汇层 / 体检 / 前置）并说出它何时该上场——不再有"这名字眼熟但不知道干嘛"的盲区。

1. 共享原语：grilling

v1.1 把"relentless interview"抽成的独立 model-invoked skill。触发：想 stress-test 一个 plan/design 时（或任何 grill 触发词）。产出：达到共识的对齐。关键：一次只问一个问题、每个带推荐答案；事实去查代码库、决策留给你；带确认 gate——共识前不 enact plan。它是 grill-me 和 grill-with-docs 背后的引擎。⚠️ 别让 agent 自问自答——一个会回答自己问题的 grilling agent 已经坏了 HITL 契约。

2. Standalone（在主流程之外）

grill-me（productivity · user-invoked）

触发：想锐化一个 plan/design，但没有代码库（非代码用途、或纯想法）。产出：对齐后的思路。关键：stateless——不存任何东西到本地、不建 CONTEXT.md。和 grill-with-docs 跑同一个 grilling 原语，区别只在于"留不留痕迹"。

prototype（engineering · model-invoked）

触发：一个设计问题在纸上聊不清、得跑起来看（状态模型对不对、UI 该长啥样）。产出：一个一次性的小程序（终端 app 验证状态/逻辑，或几套差异巨大的 UI 变体从一个路由切换）。关键：从第一天就是一次性的——留答案，删代码。它是主流程第 2 步的那个分支，但任何时候设计问题难定都可单独用。

research（engineering · model-invoked）

触发：需要读一手源回答一个问题，但又不想自己读（查第三方 API、读文档、翻知识库）。产出：一份 cited Markdown 文件落在 repo 里。关键：作为后台 agent 跑——你继续干活，它在后台读。产出的文件是要带进主流程 grill-with-docs 的素材，不是替代思考。

teach（productivity · user-invoked）

触发：想跨多个会话学一个概念/技能。产出：一个有状态的教学工作区（MISSION / lessons / learning-records / reference）。关键：你正在上的这门课本身就是 teach 产出的——它就是最好的例子。

writing-great-skills（productivity · user-invoked）

触发：要写新 skill、编辑现有 skill、或把重复工作流沉淀成 skill。产出：可预测的 SKILL.md。关键：这是参考不是流程。⚠️ 本课 Out of scope——学写 skill 与你的 superpowers 触发机制课重叠，这条线不在本课展开。

3. 词汇层（垫在所有 skill 下面）

两个 model-invoked 引用，各是各自词汇的唯一真相。当问题是"词"而非"流程"时直接 reach 它们。

domain-modeling

触发：领域术语出问题——词模糊、一个词身兼数职（"account" 干了三件事）、要记一个难撤销的决策。产出：磨尖的术语 + 更新过的 CONTEXT.md glossary + ADR。关键：它是 grill-with-docs 背后让 CONTEXT.md 保持干净的那股力——管的是领域语言。

codebase-design

触发：要设计/改进一个模块的形状、找加深机会、定 seam 放哪、让代码更可测/可被 AI 导航。产出：深模块设计（大量行为藏在简单接口后、落在干净 seam 上）。关键：它持有一套词汇（module / interface / depth / seam / adapter / leverage / locality），tdd 和 improve-codebase-architecture 都说这套话——管的是模块形状语言。

4. 代码库健康（非功能工作 · upkeep）

improve-codebase-architecture（user-invoked）

触发：有空闲时，给代码库做体检（防失败模式 #4 ball of mud，Matt 建议几天跑一次）。产出：扫出"可加深"的机会，做成可视化 HTML 报告，挑一个就生成一个 idea。关键：它不在主流程上——它找候选，挑中的 idea 拿去从 grill-with-docs 进主流程；而 codebase-design 是你设计选中那个的工作台（体检 vs 设计台）。

5. 前置（每个 repo 跑一次）

setup-matt-pocock-skills（user-invoked）

触发：在一个 repo 第一次用工程 skill 之前。产出：配好 issue tracker（GitHub / Linear / 本地文件）、triage labels、文档存放位置——这是其他 skill 默认存在的东西。关键：code-review / wayfinder / triage / to-spec / to-tickets 都靠它配的 tracker 指针（docs/agents/issue-tracker.md）解析 issue tracker——没配过它们会提示你先跑这个。

综合练习 · 给场景选 skill

Q1.「我接入了某个第三方 API，想把它能做什么、有哪些限制读清楚整理成文档，但我自己不想读」——用哪个？

Q2.「improve-codebase-architecture 给我挑了一个可加深的模块，现在我要设计它的接口形状」——直接用哪个？

Q3.「我想锐化一个非代码的计划（比如一场活动的策划），没有 repo」——用哪个？
