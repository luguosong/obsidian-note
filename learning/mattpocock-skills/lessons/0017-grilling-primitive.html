那台「把你逼到想清楚为止」的访谈机——grilling 原语与确认闸门

grilling（拷问）你已在 wayfinder、improve-codebase-architecture、grill-with-docs 里反复撞见——它是那台「一次一问、逼到共识才罢休」的机器。上一课讲透了 grill-with-docs 的一半（domain-modeling）；这节补上另一半、也是最底层的那块：grilling 本身。

一句话收获：grilling 是一个极小的、可复用的 model-invoked 原语（v1.1 专门抽出来的），只有四条规则：①沿决策树一支支relentless（不留情）追问、每题给推荐答案；②一次只问一个；③事实自己去查环境、决策留给你；④达成共识前绝不动手（confirmation gate，确认闸门——承重的那条）。两个 grill-* 只是它的薄包装：grill-me ＝裸 grilling；grill-with-docs ＝ grilling + domain-modeling（边问边沉 CONTEXT.md/ADR）。它还垫在 wayfinder、improve-codebase-architecture 底下。

1. 定位：为什么把它抽成一个原语

grilling 是 model-invoked（你说「grill 我一下 / 帮我压一压这个想法」就触发，无 disable-model-invocation）。v1.1 的一个关键重构，就是把这套「relentless interview（不留情访谈）」从各处抽成一个独立的共享原语——因为好几个 skill 都要用它「先把想法逼清楚」这件事。抽出来之后，它不归 engineering / productivity 任何一桶，而是作为底层件被上层反复引用。

它有多小？——整份 SKILL.md 就一段

grilling 的 SKILL.md 正文只有四句话。这正是「原语」的样子：小、单一职责、可被组合。它不试图沉文档（那是 domain-modeling 的活）、不试图画地图（那是 wayfinder）——它只干一件事：把一个想法拷问到共识。别的 skill 需要这一步时，就把它拿去当积木。

2. 四条规则：这台访谈机怎么运转

逐条拆开一手源（全文就这四句）：

  1. Relentless + 决策树，每题给推荐答案

    "Interview me relentlessly… Walk down each branch of the decision tree, resolving dependencies between decisions one-by-one. For each question, provide your recommended answer." 不是随便聊——是沿决策树一支支往下走、把决策间的依赖一一解开，而且每问一题都先给出它推荐的答案（让你在「同意 / 改」之间轻松表态，而非从零构造）。

  2. 一次只问一个

    "Ask the questions one at a time, waiting for feedback on each question before continuing. Asking multiple questions at once is bewildering." 一次一个、等你答完再继续。一口气抛一堆问题令人晕头转向——这条是 grilling 体验的命脉。

  3. 事实自己查，决策留给你

    "If a fact can be found by exploring the environment (filesystem, tools, etc.), look it up rather than asking me. The decisions, though, are mine." 能靠翻文件 / 用工具查到的事实，它自己去查、不拿来烦你；只有决策（要你拍板的）才一条条摆到你面前。别让 agent 替你决策，也别让它拿事实来考你。

  4. 确认闸门：共识前不动手

    "Do not act on it until I confirm we have reached a shared understanding." 这是承重的一条：在你明确确认「我们达成共识了」之前，它绝不 enact（执行）任何计划。它把「对齐」和「动手」用一道闸严格隔开——正是 4 失败模式 #1 misalignment（没做对你要的）的直接解药。

3. 同一原语，两种薄包装

两个你会手动敲（user-invoked，都带 disable-model-invocation）的 grill-* skill，本体都只有一行——薄到几乎透明：

grill-megrill-with-docs
本体（整份 SKILL.md）「Run a /grilling session.」「Run a /grilling session, using the /domain-modeling skill.」
= 什么裸 grillinggrilling + domain-modeling
桶productivity（无代码库）engineering（有代码库）
额外产物无——只把想法问清边问边沉 CONTEXT.md / ADR
典型场景压一个纯想法 / 计划（不碰码）主流程开头：磨 feature + 立领域文档

这就是组合模式：grilling 是可复用积木，grill-me / grill-with-docs 只是把它（和 domain-modeling）拼一下的薄壳。上一课那句 grill-with-docs = grilling + domain-modeling，现在两半都认全了。

4. grilling 出没地图：它不止在两个 grill-* 里

把「同一原语在不同宿主里」一次性归位——你之前撞见的那些 grilling，其实都是这块积木被别处拿去用：

宿主 skillgrilling 在那儿干什么
grill-me / grill-with-docs本体——裸用 / 配 domain-modeling 用
wayfinder · Chart 命名终点跑 grilling + domain-modeling 把 destination 拍下来
wayfinder · grilling 票型默认票型：一次一问地解一个决策（HITL）
improve-codebase-architecture · 第 3 步对你挑中的那一张候选卡跑 grilling（范围已利、无雾）

回扣第 12 课那句澄清：improve-arch 用的是 grilling、不是 wayfinder

第 12 课特意点破——架构深化对挑中的卡跑的是 grilling（范围已明、无雾可拨），不是 wayfinder。现在你从原语这头看得更清楚：grilling 是「把一个已聚焦的问题问到共识」；wayfinder 是「给一片有雾的大地画决策地图」。前者是积木，后者是工程。别再混。
