第 3 课 · 单 skill 深挖 ①

teach：你正在体验的这门课，就是它

这是一次自指深挖——你眼前这个 learning/mattpocock-skills/ 工作区，正是 teach 的产物。这一课不讲"怎么写这个 skill"，只讲一件事：作为学习者，你该怎么驾驶它——找谁交流、后续问题是改课还是加课、怎么用得好。

一句话收获：作为学习者你只需抓两件事——① 你有两个交流对象（老师＝当前 agent（AI 代理），社区＝RESOURCES.md（资源清单）里的 Wisdom（智慧））；② 任何后续问题，看它落在哪个工作区文件上，就知道该"原地改"还是"新增"。

1. 它是什么、何时跑

一个 user-invoked（用户手动触发）的技能，住在 productivity（生产力）桶（disable-model-invocation: true（禁用模型自动触发）——你手动敲 /teach，agent 不会自己触发）。它的 argument-hint（参数提示）就一句："What would you like to learn about?" README 的定位是：

Teach the user a new skill or concept over multiple sessions, using the current directory as a stateful teaching workspace.（跨多个会话教用户一样新技能或概念，把当前目录当成有状态的教学工作区）
— skills/productivity/README.md

和其它工程 skill 最大的不同：它不产代码、不碰 issue tracker（工单系统）——它产的是"一门课"，而你的全部学习状态都落在当前目录。所以它是有状态、跨会话的：这次没学完，下次 /teach 接着读同一批文件、从你的最近发展区续上。

为什么它必须"有状态"

Matt 把这点当介绍视频的开篇：skill 分 stateless（无状态：无记忆、不落盘，跑完即忘——如 grill-me）与 stateful（有状态：落盘、越用越准——如 grill-with-docs 会存 ADR 架构决策记录 / 术语表）。好的教学天然 stateful——"老师记得你学到哪、下次从那儿接上"，所以 teach 必须落盘。两者无优劣，只是场景不同。

怎么跨会话续？下次坐下来直接 /teach，把近况告诉老师（"X 我会了，Y 还没形成肌肉记忆"）。它会先读整个工作区状态、给你一个诊断，再现做一节正好卡在你 ZPD（最近发展区）的课——就像和一位一对一老师复盘：你报卡点，它设计下一课。

一个目录 = 一个 mission（使命）

你现在其实有两个教学工作区并行：这门 mattpocock-skills/，和隔壁 superpowers/。规则是一个工作区只装一个使命（见 MISSION.md）。想学第三样不相关的东西？换个空目录再 /teach，别塞进来污染这门课的 ZPD。

2. 工作区的文件，就是你学习状态的全部载体

要搞懂"改课还是加课"，先认清这个目录里每类文件各管什么。左边全是你真实躺着的文件：

文件管什么你这门课的现状
MISSION.md（使命）为什么学——一切教学的锚全局地图→实战→逐个深挖
lessons/*.html（课程页）主产物：一次一课、单一收获已 4 课（含本课）
reference/*.html（参考卡）压缩速查卡：长期回查用本课首次建立
learning-records/*.md（学习记录）你学到了什么——驱动下一课难度0001–0005
RESOURCES.md（资源清单）可信一手源 + 社区Knowledge 满、Wisdom 待补
NOTES.md（偏好便签）你的偏好（怎么教你）语言/水平/视觉已记
GLOSSARY.md（术语表）术语（可选）尚未建，按需再说

最近发展区（ZPD）：老师靠 learning-records + MISSION 算出"你现在被挑战得刚刚好的下一步"。这就是为什么你诚实暴露水平这么重要——喂错了，课要么太浅要么太高。

3. 你有两个交流对象（回答："有疑问该找谁"）

这是你问得最实的一点。答案不是一个人，是两个，分工清清楚楚：

对象它管什么时候找它
老师 ＝ 当前 agent（我）Knowledge + Skill（知识 + 技能）：紧反馈回路没讲清、想更深/更浅、发现讲错了、想再练一题——随叫随到
社区 ＝ RESOURCES.md 的 WisdomWisdom：真实世界的判断与验证"我这么用到底好不好""业界实际怎么做"——超出课堂的实战判断

skill 的原文写得很直白：每节课底部都必须有一句"不清楚就问 agent，它是你的老师"；而遇到需要智慧的问题，老师"先尝试回答，但最终引向一个社区"——因为智慧只能在真实世界里练出来。

我做这个 teach skill 的想法，不是把你钩在 agent 上学一切——而是给你足够的底气走出去、和一个社区一起干，把你送进真实世界。这才是它的梦想。
— Matt Pocock，介绍视频 9:42（意译）

所以记住：老师是脚手架，不是终点。teach 的设计意图就是把你毕业到社区——"最终引向社区"不是敷衍，而是这门 skill 的目标本身。别只在这里问，练到一定程度就去 Discussions（讨论区）亮出你的理解、接受真实反馈。

一句话分流

知识/技能的卡点 → 找老师（紧回路、即时）。智慧/实战好坏的判断 → 找社区（真实世界检验）。本工作区的 Wisdom 目前只列了 Matt 的 skills newsletter（技能通讯），Discord（社群平台）/讨论区还是个 Gap（缺口）——需要就让我帮你补一条高声望社区进 RESOURCES.md。

4. 后续问题：改课还是加课？看它落在哪个文件

"修改课程还是增加课程"不是二选一——取决于你的问题属于哪一层。把你可能说的话对号入座：

你说……老师的动作落在
"这段没讲清 / 讲错了 / 太快太慢"把那节课回炉重修（原地改）lessons/ 同一个文件
"我想学个相邻的新点"新增一节课lessons/ 编号 +1
"给我一张能长期回查的速查"建/更新参考卡reference/*.html
"这个术语固定叫什么"写进/改术语表（原地改）GLOSSARY.md
"我的目标其实变了"原地改 MISSION ＋记一条学习记录（先跟你确认）MISSION.md ＋ learning-records/
"我搞懂了 X / 原来就会 Y / 纠正了个误解"追加学习记录（只增不改）learning-records/ 编号 +1
"以后都用中文 / 每课别超一屏"记进偏好便签NOTES.md

心智模型：三种"改法"

lessons＝教学事件：以累加为主，也可被老师回炉重修（这门课的前 3 课就被合并重写过）。
reference · glossary（术语表）· MISSION＝活的真相：永远原地改，保持唯一最新版。
learning-records＝只增不改的账本：旧记录不删，被推翻时标 superseded by LR-NNNN（被第 NNNN 号记录替代），留下"理解如何演化"的痕迹。

5. 最佳实践（学习者视角 8 条）

  • 先把 MISSION 说具体：要"能观察到的现实目标"，别用"想理解 X"。目标变了就明说，让老师改 MISSION。
  • 一次只吃一小口：每课就一个明确收获，守在工作记忆里；别要求"一课讲完整个 skill"。
  • 反馈回路拉到最紧、越"富"越好：不懂立刻问、练完立刻自评；测验只是兜底——能要到更真的练习（可交互、真上手操作）就别停在选择题。
  • 诚实暴露水平："我已经会 X""这点没懂"——喂准 ZPD，避免重教或跳太高。
  • 回看用 reference，不用 lesson：课是一次性教学事件，参考卡才是长期回查处。
  • 盯 storage strength（存储强度），别信 fluency（流畅强度）：当场看懂 ≠ 记住；靠间隔重来、检索练习固化。
  • 智慧去社区验：判断题、实战好坏交给社区/newsletter，不要只问 agent。
  • 偏好一次性落 NOTES：说清"怎么教我"，之后每课自动遵循，不用重讲。

6. 延伸：teach 不只用来学"这门课"

Matt 给了两类高价值场景——学完这门课，它是你手里的一件通用工具：

  • 给代码库做 onboarding（新人上手）：新人在自己的工作区里、被点向你的代码库，独立学到"这套栈 / 这个领域"——比写一份很快过时、又不贴新人 ZPD 的文档强，"record time（极短时间）里就多一个能干活的人"。
  • 纯个人自学：副业、下棋开局、还原魔方、发声和声……任何你"一直想学、却没空系统学"的东西。Matt 自己就用它学会了还原魔方。
