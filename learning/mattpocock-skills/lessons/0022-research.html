把「读文档」这件苦力活派给一个后台 agent——research

你在 第 11·13·14 课见过 research 的身影（wayfinder 的 research 票型、后台子 agent、落 research/<name> 分支）。这节短课正面讲它——它小得只有三句话，但每句都要害。

一句话收获：research 起一个后台 agent去查资料——让你一边继续干活、它一边读（AFK）。它的三条铁律：①只认一手源（primary sources）——官方文档 / 源码 / 规格 / 第一方 API，不吃二手转述，每一条论断都追回到拥有它的那个源；②把发现写进一份带引用的 Markdown 文件（每条论断都标源）；③存到这个仓库本来放这类笔记的地方（match 既有约定，没有就找个合理的地方并说明）。它是 standalone（独立）——任何「决策卡在一个需要去查的事实上」时都能用。

1. 三条铁律

  1. 后台跑（AFK），你不必等

    一手源第一句："Spin up a background agent to do the research, so you keep working while it reads." 它不占用你——派出去、你接着干别的，它读完回报。这也是它在 wayfinder 里被归为 AFK 票型（agent 单独跑、无需真人在环）的原因。

  2. 只认一手源，每条论断追回源头

    "against primary sources — official docs, source code, specs, first-party APIs — not a secondary write-up… Follow every claim back to the source that owns it." 不吃博客/二手总结这类转述；每一条结论都要能指回拥有它的那个原始出处。这正是本课 RESOURCES.md 顶部那句「一手源优先 · 不信参数记忆」的机器化身。

  3. 一份带引用的 Markdown，存对地方

    发现写进单独一份 Markdown 文件、每条论断都标出它的源；存到仓库本来放这类笔记的地方——match 既有约定，若没有，放个合理位置并说清放哪了。

2. 它怎么嵌进别处

research 很少被你直接手动叫；更多是别的 skill 把它当子 agent 拿去用——这也是你之前见到它的方式：

宿主research 在那儿
wayfinder 的 research 票型AFK：一张需要「去查个事实、决策才能推进」的票，起一个 /research 子 agent，findings 落 throwaway research/<name> 分支、票上留 context pointer（第 14 课）
ask-matt 拓扑standalone：不汇入主流程——它的产出是带进上游讨论的素材，用完即止（第 13 课把它判为独立、非匝道）

一句话记牢它和 prototype 的分工

两者都是 standalone、都常落 throwaway 分支——但research 去读（AFK，查已存在的事实），prototype 去造（HITL，做个便宜东西看感觉）。wayfinder 的四票型里，它俩正好各占一格：知识在外面 → research；「长啥样 / 怎么跑」要试 → prototype。
