第 4 课 · 单 skill 深挖 ②

setup-matt-pocock-skills（首次配置）：给整套 skill 铺一层间接层

从这一课起进入逐个 skill 深挖阶段。第一站选它，因为它是所有工程 skill 的前置——而且你的 obsidian-note 仓库其实已经躺着一份它的产物，正好当活教材。

一句话收获：setup 不是"装东西"，而是给这套 skill 铺一层间接层。工程 skill 只认三个抽象角色（issue tracker 工单系统 / triage labels 分诊标签 / domain docs 领域文档），setup 把这三个角色一次性绑定到"你这个仓库的现实"——之后每个 skill 都不必知道你用 GitHub 还是 Linear、标签叫什么、CONTEXT.md（领域上下文档）在哪。

1. 它是什么、何时跑

一个 user-invoked（用户手动触发）的前置 skill（disable-model-invocation: true（禁用模型自动触发）——你手动敲，agent（AI 代理）不会自己触发）。它的定位只有一句：

Configure this repo for the engineering skills … Run once before first use of the other engineering skills.（为工程 skill 配好这个仓库；首次使用其它工程 skill 前跑一次）
— setup-matt-pocock-skills / SKILL.md（description）

它是 prompt-driven（提示驱动），不是确定性脚本："Explore, present what you found, confirm with the user, then write."（探查 → 展示发现 → 与你确认 → 再落笔） 先探你的 repo（仓库）、把发现摆给你看、你确认、它才动笔——不会闷头写。

2. 它配三样东西，产三个文件

三个角色，各绑一个 docs/agents/（agent 配置目录）文件；再在 CLAUDE.md／AGENTS.md 里放一个 ## Agent skills（指针索引块）当指针索引。

3. 核心洞察：为什么需要它 = 间接层

翻开任何一个工程 skill，它写的都是角色，不是命令：

  • "publish to the issue tracker" —— 没说 gh issue create
  • "apply the ready-for-agent label" —— 没说你实际的标签串
  • "read CONTEXT.md" —— 没说它在根目录还是 src/*/

setup 就是把这些角色解析成本仓现实：GitHub → gh issue create；ready-for-agent → 你的标签串；CONTEXT.md → 根目录路径。于是一份 skill 能跑遍所有 repo，可移植性正来自这层间接。

你已经见过这个思想

这跟 writing-great-skills（写 skill）里的 context pointer / single source of truth（上下文指针 / 单一真相源） 是同一招，只是落在仓库配置层：skill 指向角色、角色在一个文件里绑定一次。改 tracker（GitHub→Linear）只改 issue-tracker.md 一处，不用动任何 skill。这也是为什么 wayfinder（探路）等"通过 CLAUDE.md 指针解析 tracker doc，不写死路径"。

4. 五步流程 + 两条关键规则

  1. Explore（探现状）

    读 git remote、CLAUDE.md／AGENTS.md、CONTEXT.md、docs/adr/、docs/agents/、.scratch/，并判断 triage 是否已装、有无 monorepo（单体大仓）信号。原则："Read whatever exists; don't assume."（读一切已存在的，别假设）

  2. Present & ask（一节一问）

    逐节确认，每节先给推荐答案（一个词就能接受）；exploration 已定的节直接跳过，不啰嗦。

  3. Confirm（先看再写）

    把三个文件草稿 + ## Agent skills 块摆给你，让你先改再写。

  4. Write（落盘）

    见下方"选文件规则"。## Agent skills 块已存在就原地更新、不追加重复。

  5. Done

    告诉你哪些工程 skill 现在会读这些文件；以后直接改 docs/agents/*.md 即可，除非要换 tracker 才需重跑。

规则一 · 选哪个文件写 ## Agent skills：CLAUDE.md 优先 → 其次 AGENTS.md → 两者都无才问你建哪个。绝不在已有一个时创建另一个。

规则二 · 按需跳过整节：triage 没装 → Section B（labels）整节跳过；domain 默认 single-context（单上下文）直接写，只有探到 monorepo 信号才提 multi-context（多上下文）。

5. 你的仓库就是一份"已完成的 setup"

好消息：obsidian-note 里 docs/agents/ 三个文件都在，根用的是 CLAUDE.md。逐一对照，你会认出上面每一条：

你的文件绑定结果

triage-labels.md默认 5 标签原样（needs-triage…wontfix）
domain.mdsingle-context；CONTEXT.md／ADR 尚未创建——缺了就静默继续，留给 domain-modeling 惰性创建

动手 30 秒

打开你自己的 docs/agents/issue-tracker.md，找到 "PRs as a request surface: no" 那一行——那就是 triage 会读的 flag（标志位）。把它翻成 yes，triage 就会把外部 PR（拉取请求）也拉进队列。这一行，就是"间接层"最小的活样本。
