第 5 课 · 单 skill 深挖 ③ · 通用方法

控制边界：读懂一个 skill「管什么 / 不管什么」——以 teach 为例

你上一课追问"teach 不控制课程网页风格？"——答案是对的，而这个问题背后藏着一个能迁移到任何 skill 的元技能：一眼看出它在哪里画线。

一句话收获：读任何 skill，先把它的要求劈成三层——硬契约（锁死、必须照做）、软目标（只定调、不定死）、留白（压根不管、交你自定）。以 teach 为例：文件模型与账本规矩是硬契约，"好看 + 一致"是软目标，而课程的具体视觉风格（我们这门课的「墨夜」暗色）落在留白——teach 一个字都不管。

1. 用一个 skill 之前，先找它的"分界线"

读一个 skill 最常见的两种栽跟头：以为它什么都规定（于是不敢自由发挥，问"能不能换配色"）、或以为它什么都不管（于是踩了它锁死的规矩，比如去改只增不改的账本）。真正会用一个 skill ＝ 知道它在哪画线：哪些必须照做、哪些留给你。

好消息：这条线对任何 skill 都能用同一把尺子去找。本课用你最熟的 teach（你正被它教）当例子，但学到的是一套可迁移的读法——下次读 triage（分诊）、wayfinder（探路）也照套。

2. 把要求劈成三层：硬契约 / 软目标 / 留白

任何 skill 的要求，都能按"它管得多紧"落进三层（越往下越松）：

层skill 的态度teach 里的例子
① 硬契约
（锁死，必照做）		写死规则，不照做就破坏这个 skill 的运作工作区文件模型（谁管什么）· 命名（lessons·learning-records 用 0001-slug 递增）· 各文件 FORMAT（格式）· 账本规矩（learning-records 只增不改 + supersede）· 每课必备件（单一收获 / 绑 mission（使命）/ 荐一手源）
② 软目标
（定调，不定死）		只给目标形容词，不给具体值课要 beautiful（好看）· Tufte 风 · 打印友好 · 一致——给方向，不给任何配色 / 字号 / 布局
③ 留白
（不管，你自定）		skill 压根没提，整个交给工作区具体视觉风格（配色 / 字体 / 布局）· 教什么 / 顺序 / 深浅 · 语言 · 目录位置 · git 提交 · 组件怎么实现

一个类比：teach 像课程的「操作系统 + 施工规范」——规定"文件怎么摆、每课要有哪些承重结构、账本只能追加"，然后把"内容写什么、墙刷什么色"整个留给你和老师。所以同一个 teach，能长出你这门暗色硬核课，也能长出一门粉色瑜伽课。

3. 活样本：你的"暗色风格"为什么落在留白层

直接翻 teach 的 SKILL.md（技能定义文件），关于课"长什么样"全部只有两句：

A lesson should be beautiful — clean, readable typography… Think Tufte.（课要好看、排版清爽可读……走 Tufte 那种风）
A shared stylesheet is the first component every workspace earns… so the lessons look like one consistent course rather than a pile of one-offs.（共享样式表是每个工作区最先该有的组件……让各课看起来像同一门课，而非一堆各写各的）
— skills/productivity/teach/SKILL.md

就这些。它只要求「好看 + 一致」（软目标），从不要求「长这样」。我们这门课的「墨夜」kami 暗色（近黑底＋暖白字＋暖金强调）是你和我在这个工作区自己定的——写死在 assets/style.css，约定记在 NOTES.md（偏好便签）的"写课视觉契约"和 learning/README.md。换个空目录重开一门 teach 课，完全可以是纯白学术风，teach 一个字都不拦。

留白 ≠ 放任

teach 把风格留白，不等于让你每课乱来。软目标"一致"还在头上管着——所以我们才用一个共享 style.css 把风格锁在一处（正是 SKILL.md 说的"shared stylesheet 是第一个该建的组件"）。留白由工作区自己立规矩填上：teach 不规定颜色，但我们的 NOTES「视觉契约」规定了——填留白的是你，不是放任。

4. 可迁移技能：用"三问"给任何要求定层

下次读任何 skill，遇到一条要求，就按顺序问这三句，落到哪层立刻清楚：

  1. 问一：不照做，会破坏这个 skill 的运作吗？

    会 → 硬契约。（如改了只增不改的账本、课不绑 mission——skill 的机制就塌了）

  2. 问二：它给的是"目标形容词"还是"具体值"？

    只给形容词（beautiful / 一致 / 短）→ 软目标。你按自己判断把它落成具体值。

  3. 问三：翻遍 SKILL.md，它压根没提？

    没提 → 留白。工作区自己立规矩填上，并记进 NOTES.md / README，免得下次又即兴。

别和第 3 课的"三层改法模型"搞混

两个"三层"讲的是不同轴：第 3 课的三层改法讲"工作区文件怎么改"（教学事件 / 活真相 / 只增不改账本）；本课的三层控制边界讲"skill 管多紧"（硬契约 / 软目标 / 留白）。一个管你怎么动文件，一个管 skill 在哪画线。

检索练习 · 三连

选中即判。答错会揭示正解与解析——错一次记得更牢。

1. 关于课程网页的视觉风格，teach 的真实态度是？

2. 某 skill 只说产出要 "readable"（可读）、没给任何格式规定。按三问法它落在哪层？

3. 下面哪一条动了就会破坏 teach 的运作（属于硬契约）？

推荐一手源

验证"边界画在哪"，去 teach 自己的定义文件最直接。本课最高优先级：

  • skills/productivity/teach/SKILL.md —— 本课全部论断的出处：视觉那两句（beautiful / Tufte / shared stylesheet）在此，硬契约的文件模型、每课必备件、教学哲学也在此。读它时刻意分辨每句是"规则"还是"形容词"，就是在练三问法。
  • 四个 *-FORMAT.md（MISSION / LEARNING-RECORD / RESOURCES / GLOSSARY）—— 硬契约里"格式"层的细则，每类文件的具体写法。
