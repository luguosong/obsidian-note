第 7 课 · 宏观地图 · 生态全景

这套 skill 到底管几块文件？一张谁写 · 谁读 · 怎么维护的全景图

你要先从宏观捋清：整套 skill 落到你的仓库，其实只碰 4 块文件区域。看懂每块的产出者 / 读取者 / 维护方式，前面那些散点 skill 就从一堆名字连成一张网。

一句话收获：整套 skill 在你仓库只管 4 块文件——① 配置层（setup 写、几乎所有工程 skill 读）② 领域层（domain-modeling 写、要词汇的 skill 读）③ 工单层（规划 / 分诊类 skill 读写）④ 拒绝知识库（triage 自产自用）。而维护只有 3 种模式：一次性脚手架 / 活的真相（原地改）/ 只增不改账本（追加）。

3. 后续如何维护：只有 3 种模式

你问"执行结束后这些文件怎么维护"——答案很干净，所有文件只落进三种模式之一。认出一份文件属于哪种，就知道该怎么动它：

  1. 一次性脚手架（配置层）

    setup 首配时写一次 docs/agents/*.md + 指针块。之后直接手改这些文件即可（改标签名、翻 PR flag…）；只有换 issue tracker 或推倒重来才需要重跑 setup。日常几乎不动。

  2. 活的真相 · 原地改（CONTEXT.md · docs/agents/*.md）

    永远反映"当下的真相"，术语一变就地更新、旧值直接覆盖。CONTEXT.md 尤其要克制——只当词汇表，不塞实现细节、不当 spec、不当草稿纸。

  3. 只增不改账本 · 追加（docs/adr/ · .out-of-scope/）

    记的是"当时为什么这么决定 / 为什么拒了它"。只新增、被推翻标 superseded 不删——删了就丢掉了"我们如何走到今天"的痕迹。

这个二分你已经见过

第 3 课教 teach 工作区时，MISSION.md/词汇表是活的真相（原地改）、learning-records 是只增不改账本（supersede）。同一种智慧在这里复现："当下状态"就地覆盖，"历史决策"只增不删。区别只是一个在你的学习工作区、一个在代码仓库。

推荐一手源
