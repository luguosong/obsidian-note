# 课程重排为「工作流顺序」7 组：nav 分组 + footer 重接，文件名/编号保持稳定 ID（方案 A）

2026-07-31 用户指出「课程顺序有点混乱」——课是按用户点单深挖的**创建序**（L1–L23）长出来的，不是按学习/工作流顺序，侧边栏读起来跳。用户要求按正常工作流重排。经与用户对齐（先摆方案再动手，正好实践「先对齐后动手」家法），选**方案 A（低风险）**落地。

**决策：重排导航与 footer，不动文件名与课内编号**
- **文件名 `000N-*.html` 与课内「第 N 课」＝创建序稳定 ID，一律不动**——这样所有跨课 wikilink（`href="0011-..."` / 正文「第 11 课」）、12 张 reference 卡的链接、40 条学习记录的引用**全部零改动、零死链风险**。
- **课程顺序改由 `nav.js` 的 `GROUPS` 承载**：按工作流分 7 组——① 入门与全局（1/13/5/3）② 工程前置（4）③ 主流程 idea→ship（2/17/16/18/19/20）④ 三条匝道（6/15/11/14）⑤ 词汇层与架构（12；codebase-design 待补）⑥ 领域层·文件全景（7/8/9/10）⑦ 独立小件与工具（21/22/23）。
- **footer 的上一课/下一课重接成 GROUPS 扁平化后的线性路径**：MISSION→1→13→5→3→4→2→17→16→18→19→20→6→15→11→14→12→7→8→9→10→21→22→23→MISSION。用脚本 `files/rewrite-footers.ps1` 正则替换每课唯一的 `<footer>` 块批量完成（已验证 23 课各仅一个 footer，安全）。

**实现细节**
- `nav.js`：`LESSONS` 数组 → `GROUPS`（组名 + items），build 渲染分组标题 + 各组列表；`node --check` 通过；active 高亮仍按 filename 匹配。
- `style.css`：新增 `.coursenav-group`（暖金小标题，复用 `:root`，遵「新视觉先加类」契约）。
- `NOTES.md` 写课契约第 1、2 点更新：新增课＝插进 GROUPS 对应分组 + 只重接插入点前后两课 footer；文件名/编号为创建序稳定 ID、不随重排变。
- footer 抽查（L1 首=MISSION→13 / L2=4→17 / L23 末=22→MISSION）中文无乱码、无吃内容；UTF-8 no-BOM 读写。

**Implications：**
- 「第 N 课」语义从「顺序位置」转为「稳定 ID」——课内叙述里的「第 11 课」等**仍指向正确文件**（因文件名不变），只是不再等于侧边栏第 11 个。可接受，且是许多课程「稳定 lesson ID + 策展学习路径」的通行做法。
- 未来新增课的落位规则已写进 NOTES：先归组、再重接前后两课 footer（不必全量重跑脚本，除非大改顺序）。`rewrite-footers.ps1` 留作全量重排的可复用工具（在 session files 下，非仓库）。
- **codebase-design 待补**：它归在第⑤组（词汇层与架构），补上后插进 GROUPS 第⑤组 improve-arch 之前、并重接该处 footer 即可。
- 盘点：23 课 + 12 卡 + 42 记录；课程现按工作流 7 组呈现，导航连贯性问题已解决。实战闭环仍是 mission 唯一未兑现支柱。
