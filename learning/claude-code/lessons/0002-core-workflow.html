Claude Code 系统课 · 第 2 课

核心工作流与基本用法

Claude Code 的日常使用围绕三件事：读懂代码库、执行任务、管理会话上下文。 这节课把最高频的操作路径全部走一遍——从启动会话到完成任务， 理解 Claude 的「工具调用」模型，学会控制权限提示， 为后续的 Hooks、Sub-agents 等高级功能打好底层认知。

一句话收获：掌握日常 80% 的 Claude Code 用法——对话、代码编辑、命令执行、会话管理，知道每个动作背后发生了什么。

1. Claude Code 如何理解你的代码库

启动 Claude Code 后，它并不立刻把整个项目塞入上下文。它按需读取：

  1. 首先读 CLAUDE.md（如果存在）获取项目级指令
  2. 根据你的提问，决定要读哪些文件（Read 工具）
  3. 需要搜索时用 Grep / Glob 定位文件
  4. 需要了解 git 状态时执行 git 命令

为什么这样设计？

大型项目可能有数千个文件，全量读取既昂贵又超出上下文窗口。 「按需读取」让 Claude 能处理任意大小的代码库， 代价是：你的提问越具体，它越能找到正确文件。 含糊的问题会导致它猜测、多读无关文件、甚至找错地方。

让 Claude 更快找到正确文件的技巧

  • 提到具体文件名：「修改 src/auth/login.ts 中的…」
  • 提到函数名或符号：「找到 validateToken 函数，给它加一个日志」
  • 提到报错信息原文：把错误堆栈直接粘贴进来

2. Claude 的工具模型

Claude Code 不是简单地输出文字——它通过工具调用（Tool Calls）与文件系统和终端交互。了解有哪些工具，就能理解它的能力边界：

工具作用触发时机
Read读取文件内容需要查看代码时
Write写入/覆盖文件创建新文件时
Edit对文件做精准替换修改已有代码时
Bash执行 shell 命令运行测试、git、构建等
Glob按文件名模式搜索需要找一类文件时
Grep在文件内容中搜索需要找特定代码时
Task启动子智能体（Sub-agent）并行处理复杂任务时（第 4 课）

每次 Claude 要使用 Bash、Write、Edit 等有副作用的工具时，默认会弹出权限提示，要求你确认。这是 Claude Code 的安全机制核心。

3. 权限提示与自动允许

权限提示分两类：

类型场景处理建议
文件编辑（Write/Edit）创建或修改文件逐次确认，或在 settings 中设置 allow 规则
命令执行（Bash）运行 shell 命令谨慎，危险命令（rm -rf、git push）应保持提示

在 settings.json 中配置允许规则

对于频繁使用的安全命令，可以预先放行，避免每次都弹提示：

// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(git diff*)",
      "Bash(git status)",
      "Bash(git log*)"
    ],
    "deny": [
      "Bash(git push*)",
      "Bash(rm -rf*)"
    ]
  }
}

规则语法要点

  • Bash(命令前缀*)：匹配以该前缀开头的 Bash 命令，* 是通配符
  • Write(路径/glob)：允许写入匹配路径的文件
  • deny 优先于 allow：同一命令既被 allow 又被 deny 时，deny 生效

4. 日常交互模式

模式一：对话式（默认）

在项目目录运行 claude，进入交互会话：

cd my-project
claude

# 直接描述任务
> 给 src/utils/date.ts 的 formatDate 函数补充 JSDoc 注释

# 查看当前 git 状态
> 我刚才做了哪些修改，帮我写一条 commit message

模式二：一次性执行（-p / --print）

适合脚本或 CI：执行完自动退出，不进入交互。

claude -p "帮我分析 src/ 目录下有哪些TODO注释"
claude -p "运行 npm test 并告诉我哪些测试失败了"

模式三：管道输入

把其他命令的输出传给 Claude：

# 让 Claude 解释报错
npm test 2>&1 | claude -p "帮我解释这个错误并给出修复方案"

# 让 Claude 审查 diff
git diff | claude -p "审查这个 diff，找出潜在问题"

5. 会话管理

Claude Code 会自动保存对话历史。以下命令管理会话：

命令作用
claude --continue继续上一次会话（恢复上下文）
claude --resume列出历史会话，选择一个恢复
/clear清除当前会话上下文（保留配置）
/compact压缩上下文（减少 token 占用）
/status查看当前会话状态和 token 用量

什么时候需要 /clear 或 /compact？

Claude 的上下文窗口有限（约 200K token）。随着对话增长：

  • 速度变慢、成本升高 → 用 /compact 压缩（Claude 自动总结历史）
  • 任务切换了，不想带着旧上下文 → 用 /clear 重新开始
  • Claude 开始「遗忘」之前的内容 → 说明上下文接近上限，先 compact

6. 常用斜杠命令速查

在对话中输入 / 触发内置命令：

命令作用
/help查看所有可用命令
/model切换模型（Sonnet / Opus 等）
/config查看/修改当前配置
/diff查看当前会话中 Claude 做的所有文件修改
/undo撤销上一次文件修改
/cost查看本次会话的费用统计
/exit退出 Claude Code

7. CLAUDE.md：给 Claude 的「岗位说明书」

每次启动会话，Claude 会自动读取项目根目录的 CLAUDE.md。 写好这个文件可以省掉大量重复提示：

# 项目说明（CLAUDE.md 示例）

## 项目概述
这是一个用 TypeScript + Express 构建的 REST API 服务。

## 编码规范
- 所有函数必须有 JSDoc 注释
- 使用 async/await，不用 .then() 链
- 错误处理统一用 AppError 类（见 src/errors.ts）

## 常用命令
- 启动开发服务器：npm run dev
- 运行测试：npm test
- 类型检查：npm run typecheck

## 注意事项
- 不要修改 src/legacy/ 目录下的文件
- 数据库迁移需要先在 staging 环境测试

CLAUDE.md 的黄金准则

写「Claude 必须知道才能做对事情」的内容，而不是「Claude 通过读代码就能发现」的内容。 过长的 CLAUDE.md 会吃掉宝贵的上下文，只写高价值信息。
