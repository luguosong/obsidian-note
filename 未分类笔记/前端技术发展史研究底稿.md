## 一、Web 诞生（1989–1993）

### 1989-03｜Tim Berners-Lee 提出「万维网」提案

- **日期**：1989 年 3 月（提案文档署 "March 1989, May 1990"，3 月为首版）。
- **事实**：CERN 英国科学家 Tim Berners-Lee 向上司 Mike Sendall 提交《Information Management: A Proposal》，提出以超文本系统管理 CERN 的加速器与实验信息；上司在封面批注 "Vague, but exciting"。该系统即后来的 World Wide Web。
- **历史意义**：整个 Web 的起点文件，HTTP/URL/HTML 三大支柱均由此提案发端。
- **来源**：
	- [提案原文（W3C 存档）](https://www.w3.org/History/1989/proposal-msw.html)
	- [CERN Web 30 周年官方页面](https://web30.web.cern.ch/index.html)

### 1990-12｜WorldWideWeb 浏览器/编辑器与第一个网站上线

- **日期**：1990 年 12 月（常引 12 月 20 日，见附录一存疑项）。
- **事实**：Berners-Lee 在一台 NeXT 机器上开发出第一个浏览器兼编辑器 **WorldWideWeb**（后改名 Nexus），并在 CERN 的 `info.cern.ch` 服务器上部署了世界上第一个网站。
- **历史意义**：浏览器 + 网站 + HTTP 服务器的最小闭环首次跑通；「网站」这一形态自此诞生。
- **来源**：
	- [info.cern.ch（第一个网站原址，CERN 维护）](http://info.cern.ch/)
	- [worldwideweb.cern.ch（CERN 2021 年重建 WorldWideWeb 浏览器项目页）](https://worldwideweb.cern.ch/)

### 1991-08-06｜Web 向公众公开

- **日期**：1991 年 8 月 6 日（发帖日；「8 月初」粒度最稳）。
- **事实**：Berners-Lee 在 Usenet 新闻组 **alt.hypertext** 发帖，公开邀请感兴趣的人访问并试用万维网，Web 走出 CERN。
- **历史意义**：Web 第一次面向全球技术社区公开，扩散的起点。
- **来源**：
	- [Web Foundation 官方 Web 历史](https://webfoundation.org/about/vision/history-of-the-web/)
	- [CERN Web at 30 历史页](https://web30.web.cern.ch/web-history.html)

### 1993-04-30｜CERN 将 Web 放入公有领域

- **日期**：1993 年 4 月 30 日。
- **事实**：CERN 发表声明，将 Web 三大基础软件（行模式浏览器、服务器、libwww 库）以**免版税**方式放入公有领域，任何人可自由实现与商用。
- **历史意义**：Web 免于专利与授权费枷锁，才有后来 Mosaic、Netscape 与整个商业 Web 的爆发——这是 Web 战胜 Gopher 等同期竞争者的制度性转折点。
- **来源**：
	- [CERN 官方 Licensing the Web](https://home.cern/science/computing/the-birth-of-the-web/licensing-web/)
	- [CERN：30 Years of a Free and Open Web](https://home.cern/30-years-free-and-open-web/)

## 二、浏览器格局变迁（1993–2022）

### 1993-04｜NCSA Mosaic 1.0 发布

- **日期**：1993 年 4 月（⚠ 存疑：Wikipedia 记 4 月 21 日，Wired 等媒体记 4 月 22 日）。
- **事实**：伊利诺伊大学 NCSA 的 Marc Andreessen 与 Eric Bina 发布 Mosaic 1.0（X11 版），首个在大众层面流行起来的图形化浏览器，图文混排、安装即用。
- **历史意义**：把 Web 从物理学家工具变成普通人可用的媒体，直接引爆 90 年代 Web 增长；团队后来西迁创立 Netscape。
- **来源**：
	- [NCSA 官方 Mosaic 项目页](https://www.ncsa.illinois.edu/research/project-highlights/ncsa-mosaic/)
	- [Wired：April 22, 1993 Mosaic Browser Lights Up Web With Color](https://www.wired.com/2010/04/0422mosaic-web-browser/)

### 1994-10-13｜Netscape Navigator 发布

- **日期**：1994 年 10 月 13 日（首发 0.9 版，随首份新闻稿供免费下载）；**1.0 版为 1994-12-15**。
- **事实**：Andreessen 与 Jim Clark 创立的 Mosaic Communications Corporation（同年 11 月更名 Netscape）发布 Navigator 0.9，对非商业用户免费；年底 1.0 上市。
- **历史意义**：第一款大规模商业成功的浏览器，一度占 80–90% 市场份额，定义了 90 年代中期 Web 的形态（cookie、JS、frame 等均由其首创）。
- **来源**：
	- [CNET 存档的 Netscape 原版新闻稿（1994-10-13）](https://www.cnet.com/tech/services-and-software/netscapes-original-browser-press-release/)
	- [Wikipedia: Netscape Navigator](https://en.wikipedia.org/wiki/Netscape_Navigator)

### 1995-08｜Internet Explorer 1.0 登场

- **日期**：1995 年 8 月（⚠ 存疑：初版常记 8 月 16 日随 Plus! for Windows 95 附带，Wikipedia 记 8 月 24 日随 Windows 95 发布日面世）。
- **事实**：微软基于授权的 Mosaic 代码推出 IE 1.0，作为 Windows 95 的附加组件；次年起的 IE 3/4/5 版本迭代中逐步捆绑进操作系统、免费化。
- **历史意义**：第一次浏览器战争（约 1995–2001）的起点——微软以「免费 + OS 捆绑」击溃 Netscape 的收费模式，并由此引发美国反垄断诉讼（见下条及附录三衔接说明）。
- **来源**：
	- [Wikipedia: Internet Explorer version history](https://en.wikipedia.org/wiki/Internet_Explorer_version_history)
	- [Web Design Museum: Internet Explorer 1.0 in 1995](https://www.webdesignmuseum.org/software/internet-explorer-1-0-in-1995)

### 1998-11-24｜AOL 收购 Netscape

- **日期**：1998 年 11 月 24 日（1999 年 3 月完成交割）。
- **事实**：America Online 以约 42 亿美元换股收购 Netscape，同时与 Sun 达成 Java 合作。此时 Netscape 市场份额已被 IE 反超并持续崩塌。
- **历史意义**：第一次浏览器战争的实质终局—— Netscape 作为独立公司谢幕，其浏览器团队与开源遗产（Mozilla）转入新的演化轨道。
- **来源**：
	- [Computer History Museum：November 24 AOL Buys Netscape](https://www.computerhistory.org/tdih/november/24/)
	- [NYT：AOL to Acquire Netscape（1998-11-24 当日报道）](https://www.nytimes.com/library/tech/98/11/biztech/articles/24aol.html)
	- [CNET：AOL buys Netscape for $4.2 billion](https://www.cnet.com/tech/services-and-software/aol-buys-netscape-for-4-2-billion/)

### 2001–2003｜IE 6 绝对垄断

- **日期**：IE 6.0 发布于 2001 年 8 月 27 日（随 Windows XP）；2002–2003 年市场份额峰值约 95%+（二手统计口径，量级可靠）。
- **事实**：捆绑 Windows XP 的 IE 6 占据绝对垄断，Netscape 消失、微软解散大部分 IE 团队，此后五年 IE 几乎停滞。
- **历史意义**：垄断的副作用——浏览器创新冻结、Web 标准化倒退（IE6 专属 hack 时代），为 Firefox、Safari 的崛起提供了全部空间。
- **来源**：
	- [Wikipedia: Internet Explorer 6](https://en.wikipedia.org/wiki/Internet_Explorer_6)
	- （份额为事后统计估算，无单一一手来源，收录时建议只写「约九成半」量级）

### 2003-01-07｜Apple 发布 Safari 公测（WebKit 的起点）

- **日期**：2003 年 1 月 7 日（Macworld 旧金山，公开测试版）；正式 1.0 版于 2003 年 6 月发布（日粒度未逐手验证）。
- **事实**：Apple 发布自研浏览器 Safari 公测版，内核 **WebKit** fork 自 KDE 项目的 KHTML/JS 引擎 KJS，以 LGPL 保持开源。
- **历史意义**：埋下第二条独立浏览器引擎血脉——WebKit 后来统治移动端（iOS/Android 早期），又派生出 Chromium/Blink，是今天绝大多数浏览器共享的祖先。
- **来源**：
	- [Apple 官方新闻稿：Apple Unveils Safari（2003-01-07）](https://www.apple.com/newsroom/2003/01/07Apple-Unveils-Safari/)
	- [Wikipedia: Safari (web browser)](https://en.wikipedia.org/wiki/Safari_(web_browser))

### 2004-11-09｜Firefox 1.0 发布

- **日期**：2004 年 11 月 9 日。
- **事实**：Mozilla 基金会发布 Firefox 1.0（前身 Phoenix/Firebird，源自 Netscape 开源遗产），首年下载量过亿，逐渐蚕食 IE 份额至两成以上。
- **历史意义**：终结 IE 独占时代、重启浏览器竞争的第一推动力；标签页、扩展生态、Web 标准倡导均由其普及。
- **来源**：
	- [Mozilla 官方新闻稿（2004-11-09）](https://blog.mozilla.org/press/2004/11/mozilla-foundation-releases-the-highly-anticipated-mozilla-firefox-1-0-web-browser/)
	- [Mozilla 官方 20 周年回顾](https://blog.mozilla.org/en/firefox/firefox-milestones/)

### 2008-09-02｜Google Chrome 发布，V8 引擎开源

- **日期**：2008 年 9 月 2 日（Windows 测试版，100 余国家）；1.0 稳定版 2008-12-11。官方博客预热文《A fresh take on the browser》发布于 9 月 1 日。
- **事实**：Google 发布基于 WebKit 渲染层 + 自研 **V8** JavaScript 引擎（BSD 开源）的 Chrome，主打多进程沙箱与 JS 执行速度。
- **历史意义**：V8 触发 JS 引擎军备竞赛（Safari SquirrelFish、Firefox TraceMonkey/JägerMonkey 应声提速），直接催生 Node.js；Chrome 自身则开启通往浏览器市场第一的十年。
- **来源**：
	- [Google 官方博客：A fresh take on the browser（2008-09-01）](https://googleblog.blogspot.com/2008/09/fresh-take-on-browser.html)
	- [V8 官方博客：Celebrating 10 years of V8（确认 2008-09-02 开源）](https://v8.dev/blog/10-years)

### 2013-04-03｜Google fork WebKit 创建 Blink

- **日期**：2013 年 4 月 3 日。
- **事实**：Google 在 Chromium 官方博客宣布放弃 WebKit，fork 出渲染引擎 **Blink**，移除 WebKit 兼容多浏览器的抽象层；Opera 随即宣布跟进（此前已宣布弃用自研 Presto）。
- **历史意义**：浏览器引擎从「四强」（Trident/Gecko/WebKit/Presto）走向整合的关键一步——自研引擎的 Opera 转投 Blink，此后引擎层只剩三大血脉。
- **来源**：
	- [Chromium 官方博客：Blink: A rendering engine for the Chromium project](https://blog.chromium.org/2013/04/blink-rendering-engine-for-chromium.html)
	- [Chrome 官方开发者文档：What is Blink?](https://developer.chrome.com/docs/web-platform/blink)

### 2018-12-06 / 2020-01-15｜微软 Edge 转投 Chromium 内核

- **日期**：2018 年 12 月 6 日官宣；2020 年 1 月 15 日新版 Edge 正式发布。
- **事实**：微软在 Windows 官方博客宣布放弃自研引擎 EdgeHTML，改用 **Chromium 开源项目**重建桌面版 Edge，并使其登陆 Windows 7/8 与 macOS。
- **历史意义**：引擎格局的终局性事件——Trident 一脉（IE→EdgeHTML）正式退出历史，四大浏览器中三个（Chrome/Edge/Opera 及国内绝大多数）共用 Blink，独立引擎仅剩 Gecko 与 WebKit。
- **来源**：
	- [Windows 官方博客：Microsoft Edge: Making the web better through more open source collaboration（2018-12-06）](https://blogs.windows.com/windowsexperience/2018/12/06/microsoft-edge-making-the-web-better-through-more-open-source-collaboration/)
	- [Microsoft Edge Dev 官方博客：Upgrading to the new Microsoft Edge（2020-01-15）](https://blogs.windows.com/msedgedev/2020/01/15/upgrading-new-microsoft-edge-79-chromium/)

### 2022-06-15｜Internet Explorer 正式退役

- **日期**：2021 年 5 月 19 日官宣；2022 年 6 月 15 日 IE 11 桌面版结束支持（2023-02-14 被彻底禁用）。
- **事实**：微软宣布终结 IE 11 桌面应用，用户被引导至带「IE 模式」的新 Edge。
- **历史意义**：统治 Web 十七年（1999–2006 绝对垄断期）的浏览器王朝落幕，也宣告第一次浏览器战争的最终句点。
- **来源**：
	- [Windows 官方博客：The future of Internet Explorer on Windows 10 is in Microsoft Edge（2021-05-19）](https://blogs.windows.com/windowsexperience/2021/05/19/the-future-of-internet-explorer-on-windows-10-is-in-microsoft-edge/)
	- [Microsoft Lifecycle 官方公告：IE 11 end of support](https://learn.microsoft.com/en-us/lifecycle/announcements/internet-explorer-11-end-of-support)

## 三、HTML 标准演进（1995–2019）

### 1995-11｜HTML 2.0（RFC 1866，IETF 时代）

- **日期**：1995 年 11 月（RFC 文档只署年月，日粒度不标）。
- **事实**：IETF HTML 工作组发布 RFC 1866《HTML 2.0 Specification》（Berners-Lee 与 Dan Connolly 主笔），是 HTML 第一个正式标准（Standards Track；现标记为 Historic）。
- **历史意义**：HTML 标准化的开端——「先实现后标准」，2.0 实为对既有实现的共同子集追认。
- **来源**：
	- [RFC Editor: RFC 1866](https://www.rfc-editor.org/rfc/rfc1866)
	- [Wikipedia: HTML](https://en.wikipedia.org/wiki/HTML)

### 1997-01-14｜HTML 3.2（W3C 接掌后的首个推荐标准）

- **日期**：1997 年 1 月 14 日。
- **事实**：W3C 发布 HTML 3.2 Reference Specification（Dave Raggett 主笔），纳入表格、applet、上标等浏览器厂商已实现的功能。
- **历史意义**：HTML 标准主导权从 IETF 移交 **W3C**（1994 年 10 月由 Berners-Lee 创立于 MIT，见 [W3C 官方历史页](https://www.w3.org/about/history/)）；3.2 与浏览器大战中「追随厂商实现」的定标准模式确立。
- **来源**：
	- [W3C TR：HTML 3.2 Reference Specification](https://www.w3.org/TR/REC-html32-19970114)

### 1997-12-18 / 1999-12-24｜HTML 4.0 与 4.01

- **日期**：HTML 4.0 于 1997 年 12 月 18 日；HTML 4.01 于 1999 年 12 月 24 日成为 W3C 推荐标准。
- **事实**：Raggett、Le Hors、Jacobs 主笔，引入样式表分离（配合 CSS）、框架、表单增强，并区分 Strict/Transitional/Frameworks 三种 DTD。
- **历史意义**：HTML 在 20 世纪的最终形态——「结构靠 HTML、表现靠 CSS」的分层理念自此定调，此后 HTML 标准**冻结近十年**，直到 HTML5。
- **来源**：
	- [W3C TR：HTML 4.0 Specification](https://www.w3.org/TR/REC-html40-971218/)
	- [W3C TR：HTML 4.01 Specification](https://www.w3.org/TR/1999/REC-html401-19991224/)

### 2004-06｜WHATWG 成立：W3C 路线分裂

- **日期**：2004 年 6 月。W3C「Web Applications and Compound Documents」研讨会于 6 月 1–2 日在圣何塞举行；会后不久（常引 6 月 4 日，⚠ 存疑）Apple、Mozilla、Opera 的成员成立 **WHATWG**。
- **事实**：研讨会上 Mozilla 与 Opera 联名提案「演进 HTML 以支持 Web 应用」被 W3C 成员投票否决（彼时 W3C 主推 XHTML 2.0 路线）。三家厂商出走成立 WHATWG，由 Ian Hickson 起草 **Web Applications 1.0** 规范（其个人首稿更早，见附录一）。
- **历史意义**：HTML 标准史上最重要的分裂事件——「厂商联盟 vs 标准组织」的路线之争由此展开，Web Applications 1.0 即 HTML5 的前身；XHTML 2.0 最终于 2009 年被 W3C 放弃。
- **来源**：
	- [W3C 官方研讨会页面（2004-06-01/02）](https://www.w3.org/2004/04/webapps-cdf-ws/)
	- [WHATWG 官方 FAQ（确认 2004 年由 Apple/Mozilla/Opera 创立）](https://whatwg.org/faq)
	- [W3C HTML 工作组官方 wiki 历史（含 2007 年重启决策）](https://www.w3.org/html/wg/wiki/History)

### 2014-10-28｜HTML5 成为 W3C 推荐标准

- **日期**：2014 年 10 月 28 日。
- **事实**：W3C 发布 HTML5 推荐标准（2007 年 3 月 W3C 重启 HTML 工作组并以 WHATWG 草案为起点，2008-01-22 首份公开工作草案，历时约 7 年完成）。
- **历史意义**：为「Web 应用平台」正名——语义化标签、音视频（`<video>/<audio>`）、Canvas、本地存储等首次进入核心语言标准，Web 正式向应用平台转型；这也是 W3C 与 WHATWG 双轨并行的第一份成果。
- **来源**：
	- [W3C TR：HTML5 Recommendation (28 October 2014)](https://www.w3.org/TR/2014/REC-html5-20141028/)
	- [W3C 官方新闻稿：Open Web Platform Milestone Achieved with HTML5](https://www.w3.org/press-releases/2014/html5-rec/)

### 2019-05-28｜W3C 与 WHATWG 签署 MoU：HTML Living Standard 定于一尊

- **日期**：2019 年 5 月 28 日（2021 年 6 月有修订）。
- **事实**：W3C 与 WHATWG 签署谅解备忘录：HTML 与 DOM 规范由 **WHATWG 作为唯一出版方**维护（Living Standard 滚动更新模式），W3C 不再发布独立的 HTML/DOM 快照标准。
- **历史意义**：十五年「双 HTML 标准」分裂的终点——版本化推荐标准模式让位于持续演进的 Living Standard，HTML 标准化范式自此定型。
- **来源**：
	- [W3C：Memorandum of Understanding Between W3C and WHATWG（原文）](https://www.w3.org/2019/04/WHATWG-W3C-MOU.html)
	- [W3C 官方新闻（2019-05-28 签署公告）](https://www.w3.org/news/2019/w3c-and-the-whatwg-have-just-signed-an-agreement-to-collaborate-on-the-development-of-a-single-version-of-the-html-and-dom-specifications/)

## 四、CSS（1994–2017）

### 1994-10-10｜Håkon Wium Lie 提出级联样式表

- **日期**：1994 年 10 月 10 日（提案 v0.92 署 10 Oct 1994）。
- **事实**：Lie（Tim Berners-Lee 在 CERN 的同事）发布《Cascading HTML style sheets – a proposal》，提出样式表 + **级联**（作者/读者影响力竞争）机制，解决「HTML 借表现层标签排版」的混乱。
- **历史意义**：CSS 的概念起点；「级联」让样式可叠加、可覆盖，是 CSS 之所以叫 CSS 的原因。Lie 后与 Bert Bos 推动 CSS 标准化，被称为 CSS 之父。
- **来源**：
	- [提案原文（W3C 存档）](https://www.w3.org/People/Howcome/p/cascade.html)
	- [Wikipedia: Håkon Wium Lie](https://en.wikipedia.org/wiki/H%C3%A5kon_Wium_Lie)

### 1996-12-17｜CSS1 成为 W3C 推荐标准

- **日期**：1996 年 12 月 17 日。
- **事实**：W3C 发布 CSS Level 1 推荐标准（Lie 与 Bos 主笔），定义字体、颜色、边距等基础样式属性与级联规则。IE 3 已于 1996 年 8 月抢先实现部分支持。
- **历史意义**：「结构与表现分离」从理念变成标准；CSS 兼容性此后成为浏览器大战的主要战场之一。
- **来源**：
	- [W3C TR：Cascading Style Sheets, level 1（REC 17-Dec-1996）](https://www.w3.org/TR/REC-CSS1-961217)

### 1998-05-12｜CSS2

- **日期**：1998 年 5 月 12 日。
- **事实**：W3C 发布 CSS Level 2（Bos、Lie、Lilley、Jacobs 主笔），引入定位（position）、媒体类型、双向文本等。
- **历史意义**：CSS 首次具备「布局」能力的雏形（absolute 定位）；但其实现混乱，最终 2011 年以修订版 CSS 2.1 收场——「大版本」模式的困境促使 CSS3 转向模块化。
- **来源**：
	- [W3C TR：Cascading Style Sheets, Level 2（REC 12-May-1998）](https://www.w3.org/TR/1998/REC-CSS2-19980512/)

### 2000 年前后｜CSS3 转向模块化

- **日期**：模块化路线图首份公开工作草案为 2000 年 4 月 14 日（css3-roadmap；更早的内部草案自 1999 年）；2011 年 6 月 7 日 CSS Color Level 3 与 2011 年 9 月 29 日 Selectors Level 3 成为最早到达推荐标准的 CSS3 模块。
- **事实**：CSS 工作组放弃「单一大规范」，将 CSS3 拆为几十个可独立演进的模块（选择器、颜色、背景、动画、布局……），各模块自行走 WD→CR→REC 流程。
- **历史意义**：CSS 标准的组织形态沿用至今——现代 CSS（圆角、渐变、动画、变量）全是以模块方式渐进落地的；代价是「CSS3 已完成」的时点并不存在，需以模块为单位叙事。
- **来源**：
	- [W3C TR：CSS3 introduction（2000-04-14 首份路线图 WD）](https://www.w3.org/TR/2000/WD-css3-roadmap-20000414)
	- [W3C TR：CSS Color Module Level 3（REC 2011-06-07）](https://www.w3.org/TR/2011/REC-css3-color-20110607/)

### 2017-03｜CSS Grid 三周内三大浏览器落地（现代布局元年）

- **日期**：2017 年 3 月——Firefox 52（3 月 7 日）、Chrome 57（3 月 14 日）、Safari 10.1（3 月下旬）在约三周内先后**无前缀**实现 CSS Grid Layout。
- **事实**：Grid 规范（CSS Grid Layout Module Level 1）经多年打磨（IE10 曾于 2012 年率先实现旧版草案），2017 年 3 月实现跨浏览器同步首发——CSS 史上首次有如此规模的规范在各大浏览器协调落地。
- **历史意义**：Web 获得「真正的二维布局系统」，表格式 hack 与浮动布局时代结束；与 **Flexbox**（首份 WD 2009-07-23、新版语法 CR 2012-09-18，2013–2015 年间普及）共同构成现代 CSS 布局的基础。
- **来源**：
	- [Mozilla Hacks 官方：Firefox 52 – Introducing WebAssembly, CSS Grid（2017-03）](https://hacks.mozilla.org/2017/03/firefox-52-introducing-web-assembly-css-grid-and-the-grid-inspector/)
	- [Rachel Andrew 当周记述：CSS Grid lands in Firefox 52（2017-03-07）](https://rachelandrew.co.uk/archives/2017/03/07/css-grid-lands-in-firefox-52/)
	- [W3C 规范历史页：css-flexbox-1（2009-07-23 首稿 / 2012-09-18 首次 CR）](https://www.w3.org/standards/history/css-flexbox-1/)

## 五、JavaScript 与 ECMAScript（1995–2015）

### 1995-05｜Brendan Eich 十天创造 Mocha

- **日期**：1995 年 5 月上中旬（HOPL 论文记述：十天冲刺完成原型并演示，约 5 月 16 日前后嵌入 Navigator 2.0 pre-alpha）。
- **事实**：Netscape 的 Brendan Eich 为赶进度，约**十天**写出浏览器脚本语言原型，内部代号 **Mocha**；定位为「Java 的伴 scripting 语言」。
- **历史意义**：Web 唯一原生语言的创世时刻；十天赶工的取舍决定了语言 nearly-everything-is-object、原型链、弱类型等根本形态。
- **来源**：
	- [HOPL-IV 论文《JavaScript: The First 20 Years》（Wirfs-Brock 与 Eich 合著，一手）](https://www.wirfs-brock.com/allen/jshopl.pdf)
	- [Brendan Eich 本人博客：Popularity（2008，自述 early-to-mid-May）](https://brendaneich.com/2008/04/popularity/)

### 1995-09-18 / 1995-12｜LiveScript 发布与更名 JavaScript

- **日期**：1995 年 9 月 18 日 Navigator 2.0 beta 1 携 **LiveScript** 首发；1995 年 12 月上旬（常引 12 月 4 日，Netscape 与 Sun 联合公告）beta 3 起更名 **JavaScript**。
- **事实**：语言公开亮相时先叫 LiveScript，两个月后为蹭 Java 热度、配合 Netscape-Sun 合作而改名——与 Java 语言本身无技术关系。
- **历史意义**：名称营销造成至今未消的混淆，也令 JS 借 Java 东风迅速普及。
- **来源**：
	- [Wikipedia: Netscape Navigator 2](https://en.wikipedia.org/wiki/Netscape_Navigator_2)
	- [HOPL-IV 论文（含更名时间线）](https://www.wirfs-brock.com/allen/jshopl.pdf)

### 1997-06｜ECMAScript 1：语言标准化

- **日期**：1997 年 6 月（ECMA 大会通过，ECMA-262 第 1 版）。
- **事实**：Netscape 将 JavaScript 提交 Ecma International，标准化为 **ECMAScript**（ECMA-262），以规避 Sun 的 Java 商标问题；微软的 JScript 亦纳入同一标准轨道。
- **历史意义**：JS 成为国际标准语言，跨浏览器互操作有了共同基准。
- **来源**：
	- [ECMA 官方 PDF：ECMA-262 1st edition (June 1997)](https://ecma-international.org/wp-content/uploads/ECMA-262_1st_edition_june_1997.pdf)
	- [TC39 官方现行规范（含各版沿革声明）](https://tc39.es/ecma262/)

### 1999-12｜ECMAScript 3：此后十年的基准

- **日期**：1999 年 12 月。
- **事实**：ES3 加入正则表达式、try/catch、更完善的字符串与控制语句，成为此后十年的语言实际基准（经典 AJAX 时代的 JS 即 ES3）。
- **历史意义**：ES3 的长寿（1999–2009）塑造了整整一代前端开发者的语言认知。
- **来源**：
	- [ECMA 官方 PDF：ECMA-262 3rd edition (December 1999)](https://ecma-international.org/publications-and-standards/standards/ecma-262/)
	- [TC39 规范沿革声明](https://tc39.es/ecma262/)

### 2008-07｜ES4 弃案与「Harmony」妥协

- **日期**：2008 年 7 月底（TC39 奥斯陆会议达成妥协；8 月中旬对外公开）。
- **事实**：激进的 ES4（类、命名空间、可选类型，Adobe/Mozilla/Opera 支持）与保守的 ES3.1（微软/Yahoo 支持）路线激斗多年后，TC39 在奥斯陆达成妥协：放弃 ES4，ES3.1 继续推进（后成为 ES5），另立 **Harmony** 项目吸收 ES4 遗产——Harmony 之名即取「休战 harmony」之意。
- **历史意义**：JS 语言史上最大的流产事件，也是治理转折点：由此确立 TC39 共识决策、后续按年度小步快走的模式，直接铺就 ES2015 的大爆发。
- **来源**：
	- [HOPL-IV 论文（一手，详载奥斯陆会议）](https://www.wirfs-brock.com/allen/jshopl.pdf)
	- [Brendan Eich 本人博客：Harmony of My Dreams（2011）](https://brendaneich.com/2011/01/harmony-of-my-dreams/)

### 2009-12｜ECMAScript 5

- **日期**：2009 年 12 月（Ecma 大会通过）。
- **事实**：ES5 落地严格模式、JSON 支持（`JSON.parse/stringify`）、数组方法增强、getter/setter 等，多为 ES3.1 时代的修复与克制增强。
- **历史意义**：十年停滞后语言重启的第一步；JSON 内建为后来 Ajax/REST 生态的标配铺路。2011 年 6 月出对齐 ISO 的 ES5.1。
- **来源**：
	- [ECMA 官方 PDF：ECMA-262 5th edition (December 2009)](https://ecma-international.org/wp-content/uploads/ECMA-262_5th_edition_december_2009.pdf)
	- [TC39 规范沿革声明（确认 2009 年 12 月大会通过）](https://tc39.es/ecma262/)

### 2015-06-17｜ECMAScript 2015（ES6）：语言史上最大更新

- **日期**：2015 年 6 月 17 日（Ecma 第 109 届大会，蒙特勒）。
- **事实**：ES6/ES2015 批量落地 class、模块（`import/export`）、箭头函数、`let/const`、解构、Promise、生成器、`Map/Set` 等——语言面貌整体翻新；同时确立**此后每年一版**（以年份命名）的发布节奏。
- **历史意义**：JS 从「玩具脚本」蜕变为大型应用语言的关键一跳；模块与转译（Babel 生态）自此成为前端工程的地基。
- **来源**：
	- [Ecma International 官方新闻稿（2015-06-17 大会批准）](https://ecma-international.org/news/at-the-june-17-2015-ecma-general-assembly-in-montreux-ecma-262-6th-edition-ecmascript-2015-language-specification-and-ecma-402-2nd-edition-ecmascript-2015-internationalizat/)

## 六、前端工程化与框架（1999–2017）

### 1999｜IE 5 引入 XMLHTTP（Ajax 的技术前提）

- **日期**：1999 年（随 IE 5 的 MSXML 库交付；当事人记述赶在 IE5 beta 2 前数周塞进 `msxml.dll`）。
- **事实**：微软 Exchange 团队（Outlook Web Access）为实现浏览器内收发邮件不整页刷新，由 Alex Hopmann 等实现 **XMLHTTP** ActiveX 组件，随 IE 5 交付。
- **历史意义**：异步 Web 应用的技术原型——五年后它被 Gmail/Google Maps 用出震撼效果，再被命名 Ajax，最终反向标准化为各浏览器的 `XMLHttpRequest`。
- **来源**：
	- [当事人第一方记述：Alex Hopmann, The Story of XMLHTTP](https://www.alexhopmann.com/page/the-story-of-xmlhttp)
	- [Wikipedia: Ajax (programming)](https://en.wikipedia.org/wiki/Ajax_(programming))

### 2004-04-01｜Gmail 发布

- **日期**：2004 年 4 月 1 日（因恰逢愚人节曾被当玩笑；邀测制，2007 年全面开放）。
- **事实**：Google 发布 Gmail，以近乎桌面软件的交互（免刷新收发、聊天式对话视图、1GB 免费容量）重新定义网页应用的可能性。
- **历史意义**：「Web 应用」形态的第一次大众级演示，XHR 异步交互的教科书案例，直接启发 Ajax 概念的提出。
- **来源**：
	- [Google 官方新闻稿博客（2004-04-01）](https://googlepress.blogspot.com/2004/04/google-gets-message-launches-gmail.html)
	- [Wired：April 1, 2004 Gmail Hits Webmail G-Spot](https://www.wired.com/2011/04/0401gmail-launches/)

### 2005-02-08｜Google Maps 发布

- **日期**：2005 年 2 月 8 日。
- **事实**：Google Maps 上线，拖拽地图、滚轮缩放、即时搜索——纯浏览器内的地图体验。
- **历史意义**：与 Gmail 共同为 Ajax 提供「现象级 Demo」，两个月后 Ajax 术语即诞生；「像桌面软件的网页」自此成为产品标配追求。
- **来源**：
	- [Google 官方博客 15 周年回顾（官方确认 2005-02-08）](https://blog.google/products-and-platforms/products/maps/look-back-15-years-mapping-world/)
	- [Wikipedia: Google Maps](https://en.wikipedia.org/wiki/Google_Maps)

### 2005-02-18｜「Ajax」术语提出

- **日期**：2005 年 2 月 18 日。
- **事实**：Adaptive Path 公司的 Jesse James Garrett 发表《Ajax: A New Approach to Web Applications》，把 Gmail/Google Maps/Google Suggest 背后「异步 JavaScript + XML + DOM」的组合命名为 **Ajax**。
- **历史意义**：命名即转折——零散技术获得统一叙事后迅速引爆框架生态（Prototype、script.aculo.us、jQuery 等直接受益），Web 开发范式从「页面」转向「应用」。
- **来源**：
	- [原文（Adaptive Path 官方，2005-02-18，MIT 存档 PDF）](https://designftw.mit.edu/lectures/apis/ajax_adaptive_path.pdf)
	- [Garrett 本人 20 周年回顾：Ajax at 20（2025-02-18）](https://jessejamesgarrett.com/2025/02/18/ajax-at-20/)

### 2006-01-14｜jQuery 发布

- **日期**：2006 年 1 月 14 日（John Resig 在 BarCamp NYC 发布）；1.0 稳定版 2006-08-26。
- **事实**：John Resig 发布 jQuery，「write less, do more」——以 CSS 选择器、链式调用与跨浏览器兼容层抹平 DOM 操作鸿沟。
- **历史意义**：此后近十年最流行的 JS 库（峰值渗透率逾八成网站），事实上承担了「浏览器标准统一前的兼容层」职能，也是 npm 之前最大的插件生态。
- **来源**：
	- [jQuery 官方历史页（2006-01-14 BarCamp NYC / 2006-08-26 1.0）](https://jquery.com/history/)
	- [John Resig 本人：10th Anniversary of jQuery](https://johnresig.com/blog/10th-anniversary-of-jquery/)

### 2009｜Node.js 诞生：JS 突破浏览器

- **日期**：2009 年（Ryan Dahl 创建；2009-11-08 在首届 JSConf EU 公开演示）。npm 于 2010 年初由 Isaac Schlueter 发布。
- **事实**：Dahl 以 V8 为内核、事件循环非阻塞 I/O 为架构实现服务端 JS 运行时 Node.js，并在 JSConf EU 2009 演示；配套包管理器 npm 次年上线。
- **历史意义**：JS 第一次挣脱浏览器沙箱成为全栈语言；npm 后来成长为世界最大软件注册表，「前后端同语言」重塑了整个 Web 工程体系（构建、脚手架、全栈框架皆源于此）。
- **来源**：
	- [Node.js 官方 About（确认 2009 年由 Ryan Dahl 创建）](https://nodejs.org/en/about)
	- [JSConf EU 2009 原始演讲录像](https://www.youtube.com/watch?v=EeYvFl7li9E)

### 2012-10-01｜TypeScript 公布

- **日期**：2012 年 10 月 1 日（0.8 版；1.0 于 2014-04）。
- **事实**：微软（Anders Hejlsberg 领衔，C#/Turbo Pascal 之父）开源发布 TypeScript——JS 的类型化超集，编译到纯 JS。
- **历史意义**：给 JS 补上大规模工程所需的静态类型；经历早期社区激烈争论后成为新基建，React/Vue/Angular 及绝大多数大型前端项目默认采用，也预示「转译到 JS」路线的全面胜利。
- **来源**：
	- [微软官方博客：Announcing TypeScript（devblogs）](https://devblogs.microsoft.com/typescript/announcing-typescript-0-8-1/)
	- [TypeScript GitHub Releases（含 2012-10-01 初始发布）](https://github.com/microsoft/typescript/releases)

### 2013-05-29｜React 开源

- **日期**：2013 年 5 月 29 日（JSConf US 上宣布开源；Jordan Walke 在 Facebook 内部创造，Tom Occhino 等宣讲）。
- **事实**：Facebook 开源 React：以组件 + 声明式渲染 + 虚拟 DOM 重构 UI 构建。发布之初因 JSX 遭普遍质疑。
- **历史意义**：「组件化 + 声明式」范式战胜「MVC + 命令式 DOM 操作」，React 成为前端 UI 库的事实基线；其生态（Redux、React Native、Next.js）主导了 2015 年以后的前端版图。
- **来源**：
	- [React 官方版本页（react.dev，开源沿革）](https://react.dev/versions)
	- [React 官方博客一周年回顾：One Year of Open-Source React（2014-05-29）](https://legacy.reactjs.org/blog/2014/05/29/one-year-of-open-source-react.html)
	- [JSConf US 2013 原始演讲录像](https://www.youtube.com/watch?v=GW0rj4sNH2w)

### 2014-02｜Vue.js 公开

- **日期**：2014 年 2 月（2014-02-03 上 Hacker News 首页进入公众视野；作者尤雨溪 2013 年中完成首版原型）。
- **事实**：前 Google 员工尤雨溪（Evan You）以个人项目发布 Vue.js——渐进式框架，取 Angular 的模板与 React 的组件思想而求简。1.0 于 2015-10 发布。
- **历史意义**：三大框架中最平缓的学习曲线使其（尤其借中文社区之力）成为全球最流行的前端框架之一，证明个人主导的开源项目亦可进入一线生态；三大框架（React/Vue/Angular）并立格局在 2014–2016 年间定型。
- **来源**：
	- [Evan You 本人博客：First Week of Launching（2014-02-11）](https://blog.evanyou.me/2014/02/11/first-week-of-launching-an-oss-project/)
	- [Hacker News 首发帖（2014-02）](https://news.ycombinator.com/item?id=7169288)

### 2012–2014｜webpack 与打包器生态（来源偏二手）

- **日期**：2012 年 3 月 10 日 Tobias Koppers 首次提交；1.0 于 2014 年初发布（二手记述，⚠ 月粒度存疑）。
- **事实**：Koppers 以个人项目起步的 webpack，以 loader/plugin 架构把 JS、CSS、图片统一为可打包模块；经 Facebook（Pete Hunt 在 OSCON 推荐）与 React 生态带动成为事实标准。
- **历史意义**：模块打包器成为「前端工程化」的中枢设施——开发服务器、热更新、代码分割、Tree Shaking 均围绕打包器生长；「源代码 ≠ 交付物」的编译型前端范式由此确立（Vite 等后继者是对它的再革命）。
- **来源**：
	- [Wikipedia: Webpack（创始与版本时间线）](https://en.wikipedia.org/wiki/Webpack)
	- [webpack 创始人访谈（Koppers 本人讲述）](http://www.cross-platform-blog.com/tools/interview-with-webpack-author-tobias-koppers/)（注：一手访谈，但非官方档案，日期细节请以 npm 版本页复核）

### 2017-02-28｜WebAssembly MVP 达成跨浏览器共识

- **日期**：2017 年 2 月 28 日（四大浏览器引擎共识公告、Browser Preview 结束）；Chrome 57/Firefox 52 于 2017 年 3 月默认开启。
- **事实**：Chrome、Edge、Firefox、WebKit 四方在 W3C WebAssembly 社区组达成共识：WebAssembly MVP（最小可用版）设计完成，浏览器可默认开启。这是自 Blink fork 造成引擎分裂后，四大引擎罕见的一次同步行动。
- **历史意义**：Web 获得接近原生的二进制执行层——C/C++/Rust 等语言可编译进浏览器（游戏、音视频、Figma/AutoCAD 级应用成为可能），并在此后向浏览器之外（WASI）扩张。
- **来源**：
	- [W3C 官方邮件列表公告：WebAssembly consensus and end of Browser Preview（2017-02-28）](https://lists.w3.org/Archives/Public/public-webassembly/2017Feb/0002.html)

## 附录二：建议不收录的候选事件及理由

| 候选事件 | 不收录理由 |
| --- | --- |
| Opera 1.0（1995）及 Presto 各版本 | 长期小众，无份额/格局转折；其历史意义（2013 转 Blink）已并入 Blink 条目叙述 |
| XHTML 1.0（2000-01-26 REC） | 标准支线，生态转折意义弱；其失败因果已并入 2004 WHATWG 条目 |
| Chrome 快速发布周期（2010） | 过程性机制变更，非格局事件 |
| jQuery 2.0/3.0、React Hooks（2019）、Vue 2/3 | 均为过程性版本更新，无生态格局转折 |
| Node.js/io.js 分裂与合并（2014–2015） | 社区治理事件，对前端技术主线属支线（若写 Node.js 治理史可另议） |
| Firefox Quantum（2017-11） | 性能重振但未改变格局 |
| EdgeHTML 初版（2015-07 随 Win10） | 生命周期短且被 2018 转向事件覆盖，并入 Edge 条目背景即可 |
| CSS Zen Garden（2003） | 影响力大但属设计文化事件，非技术/格局转折（可视用户口味破例） |
| JSON 提出（2001–2002） | 语言支线；其标准化节点已由 ES5 内建 JSON 覆盖 |
| Service Worker/PWA（2015） | 长期渐进落地，无单一转折点 |
| HTTP/2（2015 RFC 7540）、QUIC/HTTP3（2022） | 属网络协议主线而非前端主线，建议另立协议线（若《编程史》已有网络主线则并入） |
| Web Components（2011 提出、2020 标准齐备） | 十年渐进、始终未成独主导，缺单一历史时刻 |
| ES2016 起的年度版本 | 发布节奏机制已在 ES2015 条目内说明，逐年条目属过程性 |
| Babel（2014，原 6to5） | 重要但属工具链细节，其意义已在 TypeScript/webpack/ES2015 条目中体现 |

## 附录三：与《编程史》现有条目的衔接

- **1995 Windows 95（已有）**：IE 1.0 条目与之衔接——Win95 是捆绑战略的载体，本稿补充 IE 起点的精确事实，可在原条目加交叉引用而非另立。
- **1998「开源」登场（已有，Netscape 开放源码）**：Netscape 于 **1998-01-22 宣布开源**、3 月底代码发布，mozilla.org 成立——即 Mozilla/Firefox 血缘的起点，建议在原条目补充此日期线索；本稿 AOL 收购（1998-11-24）与之同属 Netscape 终章，可归并到「Netscape 崩塌」一条。
- **2001 Windows XP（已有）**：IE6 垄断条目与其共用时间锚点，写「IE6 随 Windows XP 绑定，份额登顶」即可，不必单列 IE6。
- **反垄断诉讼**（US v. Microsoft）：关键节点为 1998-05 立案、2000-04-03 Jackson 法官裁定微软违反谢尔曼法（捆绑 IE 为核心指控）、2001-11 和解。属操作系统/商业史主线，若笔记未收，建议放在浏览器战争条目内一句话带过，不独立成条。
